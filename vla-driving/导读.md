# VLA 驾驶领域导读（编号 51–60）

> 10 篇精读：EMMA / DriveMoE / SOLVE / AutoVLA / ReAL-AD / MindDrive / OmniDrive / CoVLA / DriveAction / ADriver-I。
> 每篇独立文件夹 `vla-driving/<slug>-xray/`，内含精读长文（6000–12000 字）与自绘图。
> 读者：自动驾驶科研新手；课题：世界模型引导 + 自适应衰减情景记忆的闭环多规划器 Agent（LLM 调度多规划器执行开放式自然语言驾驶指令，Bench2Drive 闭环验证）。

## 这个领域在解决什么问题

VLA（Vision-Language-Action）驾驶要回答一个直接的问题：能不能让一个模型同时看懂画面、听懂人话、输出驾驶动作？传统端到端把感知、预测、规划做成流水线，每个模块说自己的"方言"；VLA 的做法是把三者都翻译成同一种表示，让一个模型端到端地从"看到什么 + 听到什么"直接到"怎么开"。2023 年 ADriver-I 提出 vision-action 交错序列时，这还只是一个想法；2024 年 Waymo 的 EMMA 用 2400 万条数据证明了"把几何翻译成文本让语言模型硬吃"是走得通的；2025 年成了推理与效率年——大家不再问"VLA 行不行"，开始问"VLA 怎么又快又准还不翻车"。

## 三条路线

**路线一：纯 VLA 端到端**——一个模型从像素和语言直达动作。EMMA（51）是这条路线的奠基验证：不加任何专用模块，把轨迹、检测框、车道线全写成文本，让预训练好的多模态大模型自回归生成。AutoVLA（54）走了另一条技术路线：把连续轨迹离散成 2048 个物理可行的动作 token，让"想"（CoT）和"做"（轨迹）变成同一个自回归模型的两种输出，再用 GRPO 同时优化"开得准"和"该快时少想"。DriveMoE（52）治的是这条路线的特有病——mode averaging：一个策略头被迫同时拟合互相冲突的行为模式，输出被拉向平均值；它的办法是把"看哪儿"（选相机）和"怎么开"（选技能专家）都变成轻量 router 按上下文做的选择题。MindDrive（56）治的是另一个特有病——模仿学习的分布偏移：一个 LLM 配两套 LoRA，Decision Expert 从 13 个词里选词，Action Expert 把词翻成轨迹，在线 RL 只在离散词上试错。

**路线二：VLM 与 E2E 的混合**——承认 VLM 推理慢、E2E 反应快，让两者各干各擅长的。SOLVE（53）把两者从"前后串联"改成"共享同一视觉编码器的并联双轨"：VLM 只做慢而高质量的轨迹参考，E2E 每帧拿带时延的旧 VLM 轨迹当初始化先验做实时精修。ReAL-AD（55）则是认知分层：战略层、战术层、操作层三层结构，VLM 给每一层各配一个"老师"，把人类司机的层级推理显式建模进端到端系统。

**路线三：数据与评测地基**——VLA 吃什么、怎么考。CoVLA（58）证明了车载 CAN/GNSS/IMU 本身就是动作日志：83 小时真实驾驶视频的轨迹和语言描述可以不靠人工标注，从传感器里"长"出来。DriveAction（59）反过来想：从驾驶员真实做出的高层动作倒着出题，为每个动作反推它依赖的视觉/语言子任务，形成一棵能逐层定位病灶的问答树。OmniDrive（57）卡在中间：用规则仿真批量算出候选轨迹的后果，再让 GPT-4 把"轨迹→后果"写成问答，造出 VLM 缺的那种"如果当时那么开会怎样"的稠密监督。

**思想源头**：ADriver-I（60，2023 年技术报告）是 vision-action 交错序列的出处——把控制信号写成数字词，和图像 token 交替排进同一个语言模型序列，MLLM 预测控制、扩散模型预测未来帧，两者互为条件地循环，"在自己创造的世界里开车"。它是本领域世界模型那条线的起点。

## 四组张力（新手先建立这四个判断）

1. **离散 vs 连续**：语言模型输出离散 token，驾驶动作连续。三篇给出了三个答案——EMMA：把几何全写成文本；AutoVLA：把轨迹离散成 2048 个动作 token；ADriver-I：把控制信号写成数字词。读的时候问：每种方案丢掉了什么信息？
2. **快 vs 慢**：VLM 懂常识但慢，E2E 快但笨。SOLVE 用异步双轨，AutoVLA 用快慢自适应，ReAL-AD 用三层认知。共同点是"简单场景少想、复杂场景多想"正在成为默认设计。
3. **模仿 vs 试错**：纯模仿学习有分布偏移。MindDrive 用在线 RL 在离散决策上试错，DriveMoE 用专家分工让稀有行为有自己的参数。注意两者的代价：RL 要仿真环境烧样本，MoE 要 router 监督信号。
4. **开环 vs 闭环**：nuScenes 开环指标和 Bench2Drive/CARLA 闭环分数讲的不是一回事。EMMA 的精读里专门拆了 Ego-MLP（0.35）这个对照——开环 L2 低可能是历史外推的捷径。看任何 VLA 论文的数字，先问它是在哪种评测下拿的。

## 10 篇之间的关系

- EMMA ↔ AutoVLA：都是纯 VLA，但"让语言模型输出动作"用了两种相反的手段——EMMA 把世界翻译成语言，AutoVLA 把动作翻译成语言。两篇对照读，离散/连续的张力就清楚了。
- DriveMoE ↔ SOLVE：都是"分工"，但 DriveMoE 是参数分工（MoE 专家），SOLVE 是系统分工（VLM+E2E 双轨）。
- AutoVLA ↔ MindDrive：都用 RL，但 AutoVLA 的 GRPO 修的是"推理长度"，MindDrive 的在线 RL 修的是"决策质量"，一个省时间、一个提上限。
- ReAL-AD ↔ SOLVE：都是分层，但 ReAL-AD 分的是认知层级（战略/战术/操作），SOLVE 分的是时间尺度（慢参考/快执行）。
- CoVLA ↔ DriveAction：一个管"训"（数据从哪来），一个管"考"（怎么评测），读完这两篇再看任何 VLA 方法论文，心里都有杆秤。
- OmniDrive ↔ ADriver-I：都和"想象"有关。OmniDrive 在数据侧做反事实（如果当时那么开），ADriver-I 在模型侧做交错 rollout（开在自己想象的世界里）。两篇合起来就是"世界模型引导"的思想全貌。

## 新手阅读顺序

1. **EMMA（51）**：先看 VLA 长什么样，建立整体画面。重点看"文本 vs 专用 token"的赌注。
2. **CoVLA（58）**：数据怎么来。理解 VLA 的"粮食"，以及自动化标注管线的两道过滤网。
3. **DriveAction（59）**：怎么评测。建立判断力：以后看任何 VLA 数字，先问评测协议。
4. **OmniDrive（57）**：反事实数据思想。承上启下，从数据过渡到模型。
5. **SOLVE（53）**：第一个混合架构。重点看异步双轨的时间线图。
6. **ReAL-AD（55）**：三层认知推理。注意"30% 提升"的基线条件。
7. **AutoVLA（54）**：离散动作 + 自适应推理，技术密度最高的一篇，可以慢读。GRPO 奖励设计是重点。
8. **DriveMoE（52）**：MoE 路由，与你的课题同构度最高的一篇，精读"与本课题的关联"节。
9. **MindDrive（56）**：在线 RL，与你的验证基准（Bench2Drive）同源，数字可直接对标。
10. **ADriver-I（60）**：思想源头。读完回看世界模型，理解 vision-action 交错序列为什么是自然的表示。

## 与你的课题的关联（总览）

- **调度器**：DriveMoE 的 Action MoE router 就是"LLM 调度多规划器"的雏形——router 按上下文选专家 ≈ LLM 按场景选规划器。它的精读里有一张同构对照表，直接可用。
- **自适应**：AutoVLA 的"该快时少想"（质量奖励 − λ×计算代价）与你的"场景驱动动态模块旁路"在数学上同构，建议用奖励算术代替手写切换规则。
- **验证**：MindDrive（DS 78.04）与 DriveMoE（DS 74.22）都在 Bench2Drive 闭环验证，是你未来实验最直接的对标基线。
- **世界模型**：OmniDrive 的反事实问答、ADriver-I 的交错 rollout，正是你"世界模型引导"支柱的思想资源；EMMA 精读里还提到"世界模型接 R2 文本契约"的具体想法。
- **记忆**：EMMA 把情景记忆视为"第 5 种 prompt 任务"，CoVLA 的自然语言化轨迹是记忆条目的天然格式——你的自适应衰减情景记忆缺的就是这种"事实锚点"设计。
- **指令接口**：EMMA 的自然语言输入是开放式指令最直接的接口起点；DriveAction 的树状评测可以借来评测你的指令执行效果。
