# 导读 · 领域E：Agent 系统在驾驶中的迁移应用（编号 81–85）

> 给科研新手的阅读地图：通用 LLM-Agent 那套机制（规划-行动循环、工具调用、反思、角色分工、多智能体协作），搬到自动驾驶上时，哪些好用、哪些水土不服，以及这 5 篇论文互相是什么关系。

## 先说结论：迁移的 landscape

通用 agent 机制往驾驶里搬，撞上的第一堵墙永远是**实时性**：LLM 推理一次几百毫秒到几秒，驾驶决策要 10–20Hz。所有认真的迁移工作都在回答同一个问题——慢思考的智能，怎么塞进快执行的回路。这 5 篇给出了四种不同的答案：

- **解耦**（AsyncDriver）：慢和快干脆分开跑，LLM 低频出"指令特征"，实时规划器高频执行，中间用门控注入。这是工程上最诚实的答案，也是你课题"异步流水线"优化的直接样板。
- **分层**（KoMA）：多步规划把长目标和短动作分层，层与层之间保证一致；多智能体之间只交换意图，不交换原始感知。
- **换介质**（LangCoop）：多车之间不传图像/特征，传自然语言——带宽降 96%，代价是 VLM 幻觉可能污染消息，而论文对这一点几乎没有讨论。
- **借身体**（SurrealDriver）：LLM 缺的不是知识，是"开过车"的身体直觉；把人类司机的事后"内心独白"当 CoT 示范直接移植。

第二堵墙是**评测的可信度**。5 篇里 4 篇是开环或简化仿真（highway-env、CARLA 简单场景），只有 AsyncDriver（nuPlan 闭环挑战场景）和 LangCoop（CARLA 闭环）沾了闭环的边。读的时候记住：凡是没有闭环数字的"提升"，都要打折扣——开环 L2 误差降了，不等于撞得少。

第三堵墙是**基座依赖**。KoMA 的审读里最扎眼的一条：GPT-4 换成 7B 小模型，成功率掉 30 个点。很多"agent 架构"的增益，剥开看是基座模型的增益。以后你自己做消融，记得把"换小基座"这一项放进去，这是区分"架构贡献"和"基座贡献"最便宜的办法。

## 5 篇的关系：一张图

```
单车智能体
├── SurrealDriver（83）：人类思维 → CoT prompt（解决"LLM 没开过车"）
└── AsyncDriver（81）：慢 LLM + 快规划器异步解耦（解决"LLM 太慢"）

多车协同
├── KoMA（82）：多智能体"读心"（意图推断）+ 排序反思（不开口，只揣测）
├── LangCoop（84）：多智能体"开口"（自然语言当通信协议）
└── AgentsCoDriver（85）：五模块完整循环 + 终身学习（感知-记忆-推理-反思-通信全套）
```

KoMA 和 LangCoop 是一对镜像：KoMA 让车**互相揣测**（不通信，靠意图推断），LangCoop 让车**直接说话**（通信，靠语言协议）。两种路线各有各的坑：揣测会错，说话会慢/会幻觉。你的课题是单车多规划器调度——有趣的是，这两条路线都能平移：KoMA 的"意图揣测"变成"仲裁器读懂每个候选规划器的意图"，LangCoop 的"语言通信"变成"候选规划器用自然语言自述意图与风险，仲裁器做语言级仲裁"。

AgentsCoDriver 是五篇里"最像完整 agent"的：观察、记忆、推理、反思、通信五个模块全有。它和 KoMA 的关系是：KoMA 把四个机制做深（尤其反思的排序机制），AgentsCoDriver 把五个模块拼全（但每个都浅）。读的时候对比着看，能看出"做深一个机制"和"拼全一个循环"两种不同的论文策略。

## 新手阅读顺序

1. **AsyncDriver（81）先读**。它是五篇里工程最扎实、和你课题关系最直接的（异步流水线就是你的时延优化第四条）。先建立"慢快解耦"这个基准答案，后面读别的时候才有参照。
2. **SurrealDriver（83）第二**。最薄（6 页），故事最清楚：人类经验怎么变成 agent 的 prompt。读完你会对"情景记忆里该存什么"有具体感觉——存轨迹，还是存"情境-推理-动作"三元组。
3. **KoMA（82）第三**。多智能体机制最深的一篇，排序反思是全文承重墙。注意它的两个"坑"：效率公式排版与文字矛盾、两车是回合制轮流决策——论文没讨论的同时性假设。
4. **AgentsCoDriver（85）第四**。有了 KoMA 的深度，再看这篇的"全而不深"，对比出两种论文策略。它的"强化反思"其实是"错了写检讨"（不是梯度 RL），别被名字骗了。
5. **LangCoop（84）最后**。最新（2025），想法最飘（语言当通信协议），审读也最狠（96% 带宽下降的口径问题、幻觉零讨论）。放在最后读，你已经有足够的怀疑工具，不会被 headline 数字带着走。

## 哪些机制好迁、哪些水土不服（给你的课题）

**好迁的**（可直接装进"LLM 调度多规划器"架构）：
- 慢快解耦（81）：LLM 调度器低频，规划器高频，时间戳补偿——就是你时延优化的第四条，AsyncDriver 给了完整样板。
- 排序反思前移（82）：KoMA 的反思是事后的；你的闭环风险校验是事前的。把"rollout 打分→排序→反事实反思"搬到仲裁器里，是 KoMA 没做、你最可能挖出增量的单点。
- 语言级仲裁（84）：候选规划器用自然语言自述意图与风险，仲裁器做语言级仲裁——比传轨迹点更可解释。
- 记忆冷启动（83）：Driving-Thinking-Dataset 是公开的，可直接做你情景记忆库的种子数据。

**水土不服的**（要改了再用）：
- 多智能体通信协议（84/85）是为"车与车"设计的，单车多规划器之间没有通信延迟和带宽问题，照搬是杀鸡用牛刀；取其"意图表达"的思想，丢掉"压缩传输"的包袱。
- 终身学习（85）的"只加不减"和你"自适应衰减"正好互补：记忆不能无限长，KoMA/AgentsCoDriver 都没有遗忘机制——这正是你的创新空间，不要被它们的"lifelong"叙事带偏。
- 人类思维 CoT（83）的样本只有 24 名司机，泛化到长尾场景存疑；当种子可以，当真理不行。
