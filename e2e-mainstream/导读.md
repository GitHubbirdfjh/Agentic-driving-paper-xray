# 领域 F 导读：主流端到端自动驾驶——5 篇论文建立坐标系

> 本组 5 篇（全局编号 86–90），全部按 paper-xray 规范深度精读，每篇 6000–10000 中文字，公式逐项讲透、怀疑式审读、数字出自原文。阅读对象是刚进入自动驾驶领域的新手：读完这一组，你应该能回答"当前主流在做什么、赌什么、缺什么"。

## 一、这条线从哪里来：模块化 → 端到端

经典自动驾驶栈是串行管线：感知 → 预测 → 规划 → 控制，每个模块独立优化、接口是人工定义的中间表示（检测框、轨迹、占据栅格）。这条管线有两个结构性毛病：误差在模块间累积放大；每个模块的优化目标都不是"最终开好车"，而是各自的代理指标。

端到端要干的事，就是把"最终开好车"变成唯一的优化目标，让梯度从规划一路反传回感知。演进线大致是：

- **ST-P3（2022）**：栅格化（rasterized）表示 + 可微的规划代价，证明了端到端可微规划这条路走得通，但栅格又贵又笨。
- **86 UniAD（CVPR 2023）**：扔掉"多任务各训各的"，提出 planning-oriented——一切任务都为规划服务；一切皆 query，任务之间用统一 query 接口互相传信息。这是后面所有工作的坐标原点。
- **87 VAD（ICCV 2023）**：UniAD 太重了（1.8 FPS）。向量化表示：场景里的车、车道线本身就是向量，干嘛先画成栅格再认回来？安全约束写成训练时的可微损失，推理零开销。Tiny 版 16.8 FPS。
- **89 SparseDrive（ICRA 2025）**：更进一步，连稠密 BEV 都不要了——全稀疏实例表示；并看出预测和规划是同一个多模态解码问题，并行做；碰撞重打分选最终轨迹。
- **88 Hydra-MDP（CVPR 2024 workshop 冠军）**：换一条路——不跟表示较劲，跟"学什么"较劲。单目标模仿学习在多指标评测下顾此失彼，那就用人 + 规则双教师蒸馏，多头解码器每个头对准一个评测指标。
- **90 DiffusionDrive（CVPR 2025 Highlight）**：规划头生成式化。机器人领域的 diffusion policy 多模态表达力强，但 20 步去噪太慢；截断扩散 + 先验 anchor，2 步去噪、45 FPS。

## 二、三条主线矛盾

**1. 表示之争：稠密 BEV → 向量化 → 稀疏。** 这是 2023–2025 端到端领域最实在的一条技术线。UniAD 用稠密 BEV + query；VAD 证明向量化又快又保实例结构；SparseDrive 证明稠密 BEV 可以整个拿掉。赌注一步比一步大，消融也一步比一步难做——表示和架构耦合在一起，"快"到底来自表示还是来自更小的 backbone，论文里经常分不开（VAD 的 9.3× 就有这个问题，精读里已如实标注）。

**2. 规划范式：单模态回归 → 多模态 → 生成/蒸馏。** 驾驶本质是多模态的（路口左转还是直行都是合法答案），单轨迹回归必然学出"平均"出来的中庸轨迹。UniAD 的规划头还是单模态的；SparseDrive 并行多模态解码 + 重打分；Hydra-MDP 多头对准多指标；DiffusionDrive 用扩散模型直接建模多模态分布。四种答案，四种代价。

**3. 评测之争：开环 nuScenes → NavSim → 真闭环。** 这是读这组论文最关键的批判视角，5 篇精读里每篇都单独审了：
- nuScenes 开环 L2 / 碰撞率：有"照抄自车历史轨迹"的捷径，低速场景天然占便宜，数字好看不等于开得好。
- NavSim PDMS：non-reactive 回放式"闭环"，背景车辆不 reacting；NVIDIA 官方博客自己称之为 "learned open-loop proxy metrics"。Hydra-MDP 的 91.0 和 DiffusionDrive 的 88.1 都是在这个 proxy 上拿的。
- 真闭环（CARLA / Bench2Drive）：5 篇里只有 VAD 顺手给了 Town05 结果（半页纸、基准老旧）。**开环数字不能直接作为闭环能力的证据**——这是你读任何端到端论文都要先问的一句。

## 四、新手阅读顺序

按时间线读，就是按领域演进读：**86 → 87 → 88 → 89 → 90**。

- 86 UniAD 先读：它是坐标系本身。不读它，后面"向量化""稀疏化"到底在反什么都不知道。
- 87 VAD 接着读：同一范式下的效率路线，query 交互的公式（1–3）在 UniAD 基础上更好懂。
- 88 Hydra-MDP：换视角——从"表示"转到"学什么"，顺便把 NavSim/PDMS 的评测机制搞懂，后面读 90 时直接复用。
- 89 SparseDrive：回到表示之争的终点，看"全稀疏"这个最大胆的赌注。
- 90 DiffusionDrive：最后读生成式路线，此时你对多模态规划的几种答案（并行解码/多头/扩散）已经有了完整参照系。

## 五、读完这组带走什么

三句话的坐标系：**表示上**，领域正从稠密 BEV 走向向量化/稀疏；**规划头上**，单模态回归已被多模态取代，分歧在于多模态怎么做（并行解码 / 多头蒸馏 / 扩散生成）；**评测上**，所有漂亮数字都建立在开环或回放式 proxy 上，真闭环验证是整个领域的欠账。

**与你的课题的关联**：这 5 篇都是你"专家规划器"池的现成候选——UniAD/VAD/SparseDrive 是感知-规划一体的重型候选，DiffusionDrive 是多模态候选生成器，Hydra-MDP 的多头打分思想可以借给仲裁器。它们统一缺的三块：开放式自然语言指令理解、情景记忆、独立于规划网络的在线风险校验——正是你的课题要补的。反过来，你的课题立项依据里最硬的一条批判也来自这组：**不要拿它们的开环数字当作闭环能力的证据**，你的 Bench2Drive 闭环验证恰好打在这个欠账上。
