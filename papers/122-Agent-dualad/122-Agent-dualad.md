# 双层分工最接近 RAMP 的先例：DualAD 的非对称否决与文本编码器

> **信息块**
> - 论文：DualAD: Dual-Layer Planning for Reasoning in Autonomous Driving
> - 作者：Dingrui Wang, Marc Kaufeld, Johannes Betz（慕尼黑工业大学 TUM，自主车辆系统教席）
> - Venue：**IROS 2025**（已核实：arXiv:2409.18053 v3 2024-12-04；作者官方仓库 mkaufeld/dualad 与 casessar/dualad 均标注 [IROS'25]；IROS 2025 于 2025 年 10 月在杭州举办）
> - 链接：https://arxiv.org/abs/2409.18053
> - 代码：**已公开并核对** https://github.com/TUM-AVS/DualAD（本目录 `code/` 为 2026-10-11 clone 的 shallow 副本；核心文件 `nuplan/planning/simulation/planner/abstract_idm_planner.py`，649 行）
> - 一句话核心洞见：双层架构里**上层永远只做一件事——踩刹车**。下层规则规划器负责"怎么开"（参考路径+轨迹采样），上层 LLM 每秒看一次由规则编码器翻译成"人话"的场景描述，只输出一个期望速度；且干预是**非对称**的：$v_d = \min(IR[\text{speed}], v_{rule})$——LLM 只能降速，不能加速。它不是规划器，是**带否决权的安全员**。这是本批五篇里离 RAMP"调度-校验"分层最近的一个。
> - 研读所用版本：v3（8 页），PDF 已存本目录 `2409.18053.pdf`

## 两层如何分工：先看代码，再看论文

论文的图 1 把分工画得很漂亮：下层"参考路径规划+运动规划"，上层"LLM 推理+危险检查"。但漂亮的图常常藏起关键细节，所以先看代码里真正发生的事。

**下层：三个可插拔的规则规划器。** IDM（式 5，沿道路中心线跟驰）、Lattice-IDM（IDM 纵向 + 格子采样横向，式 6 的离散优化）、Frenetix（多项式轨迹采样 + 加权代价选优，式 7）。它们共同的输出是一条参考路径 $P_{ref}$ 和一条规划轨迹（含速度剖面 $v_{rule}$）。注意：**下层完全不知道上层的存在**，它按自己的逻辑全速规划。

**上层：文本编码器 + LLM + 非对称覆盖。** 每一步（实际是每 10 步，见下文代码核对），场景 $S$ 被规则编码器转成文本 $D = f_{text}(S)$，LLM 输出 $I_R = LLM(D)$，其中包含一个建议速度 $IR[\text{speed}] \in [0, 15]$ m/s。最终执行速度：

$$v_d = \begin{cases} IR[\text{speed}] & IR[\text{speed}] \le v_{rule} \\ v_{rule} & \text{otherwise} \end{cases} \tag{9}$$

代码里的实现（`abstract_idm_planner.py` 第 252 行）是：

```python
if solution.velocity > self.DESIRED_SPEED: solution.velocity = self.DESIRED_SPEED
```

`DESIRED_SPEED` 默认 30（基本不触发），LLM 调用后把它设为 LLM 建议值（0~15）。**论文和代码完全一致**：LLM 的输出是一个速度上限钳位。这就是"非对称"——上层没有任何机制让车开得更快，它只能让车更慢。这是一个深思熟虑的安全设计：LLM 的幻觉在这里的**最坏后果是"过度减速"（堵车），而不是"加速撞墙"**。把 AI 的失败模式设计成"fail-safe 而非 fail-deadly"，是全文最值得抄走的一课。

**代码核对出的四个论文没写的细节**（审稿人视角的高价值信息）：

1. **LLM 是 1Hz 调用的，不是每步。** `if use_llm and self.LOCAL_TIMER % 10 == 0`——仿真 10Hz，LLM 每 10 步查一次。论文正文只说"dynamically checks"，没给频率。1Hz 的监督频率意味着：两次 LLM 调用之间有 1 秒是纯规则规划器在裸奔——上层的"监督"是稀疏的。
2. **每次 LLM 调用后 `time.sleep(30)`（GPT-4o）或 `sleep(7)`（GLM-4-flash）。** 这是为了躲 API 限流。换句话说，论文里的闭环实验，GPT-4o 版本每 10 个仿真步就要在墙钟时间上**暂停 30 秒**。实验能跑通纯粹因为 nuPlan 仿真器是 lockstep 的（不等 planner 返回不推进）。这也解释了为什么默认用免费的 GLM-4-Flash 做主实验——不是不想用 GPT-4o，是**用不起时间**。
3. **LLM 的 prompt 极简，没有 CoT。** 系统提示是场景文本，用户提示全文就是："Assume you are the driver of the ego vehicle, and you can adjust the speed (between 0 and 15). What speed do you suggest… Only Output a simple number, don't answer anything else."——**只要一个数字，不要推理过程**。论文图 1 里画的"Slow Down"文字是示意，实际管线里 LLM 不输出任何 rationale。这是个有争议但务实的选择：要数字就别让它废话，废话越多格式越容易崩。
4. **格式崩溃是真实发生的，有专门的脏处理。** `llm_ans = float(output_string)`，前面还有一段处理 `"'t\n"` 前缀的 strip。表 II 脚注里 GLM-4-Flash 有 10%~30% 的仿真因"输出不符合格式"而失败——代码里的 `float()` 抛异常就是失败现场。**弱 LLM 的指令跟随能力是这套架构的真实瓶颈**，论文用脚注诚实地记了一笔。

## 文本编码器：把"坐标"翻译成"人话"是上层的全部本钱

既然 LLM 只看文本，文本的质量就是上层的智商上限。编码器的设计（3.1 节，图 3）分三步：

1. **笛卡尔 → Frenet。** 用下层规划出的参考路径 $P_{ref}$ 做基准，把每个 agent 的位姿 $(x, y, \theta_{cart})$ 转成 $(s, d, \theta_{fren})$。这一步很关键：Frenet 坐标是**道路对齐**的，"s=29.8 米"直接对应"沿路前方 29.8 米"，LLM 不需要心算道路曲率。
2. **阈值离散化。** 纵向：$s > 1$ 为"ahead"，$s < -1$ 为"behind"，$[-1,1]$ 为"parallel"；横向同理（阈值 1 米）；朝向分四档（$\alpha=0.06$ rad 算同向，$\beta=3.08$ rad 算反向，中间看是否朝向自车轨迹，$\gamma=1$）。**连续量被有意模糊成定性描述**——"5.1 meters behind and 3.2 meters right"，而不是 "(−5.13, 3.17)"。
3. **固定模板组装**（式 4 的 $f_m$）：ID / Position（含人话）/ Size / Speed / Orientation。图 4 的例子：
   ```
   ID: VEHICLE_70e4b0e66ab85734
   Position: (29.8, -0.0) meters (29.8 meters ahead and directly in line with the ego)
   Size: Width: 1.9 meters, Length: 4.9 meters
   Speed: 5.62 m/s
   Orientation: -0.01° (moving in the same direction as the ego vehicle)
   ```

为什么要多此一举？论文搬出了 Platonic Representation Hypothesis（Huh et al., ICML 2024）来论证"文本推理和图像推理应该等价"。坦率说，这是**哲学包装**——真实原因一句话就能说完：**LLM 是在文本上训练的，给它看文本它最聪明**。但编码器的工程价值是实在的：消融表 III（GPT-4o，10 个场景）显示，去掉文本编码器（直接喂原始数值），Lattice-IDM+LLM 的 R-CLS 从 44.88 掉到 39.78（-11.4%），NR-CLS 从 76.72 掉到 71.01（-7.4%）。**"怎么把场景序列化给 LLM"是一个 +11% 的变量**——这个数字值得所有做 LLM 调度的人抄在小本本上。

编码器的局限论文自己承认了：只描述 agent，不描述地图（车道线、人行道都没进文本）；LLM 一次只看一帧，没有历史。这两条都是 RAMP 可以直接"认领"为改进点的。

## 数字：在"精心挑选的难题"上考高分

评测设计先看明白：nuPlan mini（2000+ 场景）上先跑一遍，**按 IDM 的 R-CLS 分数挑出最差的 55 个**（Hard-55），再按 PDM-Closed 的分数挑出最差的 24 个（Super-Hard-24）。这是一种"**专挑你不会的考**"的评测法——优点是 headroom 大、能看出 LLM 的增量；缺点是**数字不能外推到一般场景**。读表时心里要装着这个前提。

**主表（表 I，默认 GLM-4-Flash，† 为 GPT-4o）**：

- **Lattice-IDM** 是最大赢家：Hard-55 上 R-CLS 39.76 → **57.31**（+44.1%，验算一致），NR-CLS 52.36 → 60.25；Super-Hard-24 上 33.83 → **46.03**（+36.1%）。注意 57.31 已经**追平人类专家 log-replay 的 58.32**——论文标题党了一把"comparable to human expert"，分母是 Hard-55 这个子集，不是全部场景。
- **IDM**：R-CLS 34.56 → 40.25（+16.5%），但 NR-CLS 50.12 → **49.37（掉了）**。
- **Frenetix**（本身就很强）：R-CLS 77.80 → 77.86†（GPT-4o，基本没动），NR-CLS 78.77 → **75.55（掉了 3.2 个点）**。
- PDM-Closed（规则 SOTA）在 Hard-55 上只有 58.33/35.15——顺便证明了"在难例上规则规划器也会翻车"，给 LLM 的存在提供了合法性。

**非对称干预的副作用解释了 NR 的下跌**：non-reactive 是 log-replay，背景车不理你；LLM 只能降速不能加速，降速在 log-replay 里除了损失进度分（progress）没有任何安全收益——因为背景车根本不会撞你。所以 NR 掉、R 涨，是**设计使然**，不是 bug。作者没有藏这个现象，但摘要里只讲 R 的提升，这是叙事上的选择性强调。

**表 II（10 个场景，LLM 档次对比）**：GPT-4o 的 Lattice-IDM+LLM 是 NR 76.72 / R 44.88，GLM-4-Flash 是 64.26 / 22.07，**R-CLS 差了一倍**。"用更强的 LLM，系统直接变强"——这是全文对"LLM 即推理引擎"这个范式最有力的辩护：**系统的智能是可以随基座模型升级而免费升级的**，规则部分不用动。但代价是 GLM-4-Flash 10%~30% 的格式失败率——以及这些失败仿真在表 I 的平均分里是怎么处理的，**论文没说**。如果失败的被剔除了，那就是 survivorship bias；如果记了零分，那就是低估。无论哪种，都应该披露。

**一个被验证的算术**：摘要/正文里的 "+44%"、"+36%"、"+16%"、"nearly 20%" 我全部用表 I 的数字验算过，一致。数字本身是诚实的。

## 怀疑式阅读

**第一，"双层"的叙事 vs "1Hz 限速器"的现实。** 引言花了一页讲人类大脑 15 瓦、注意力自适应分配，把 DualAD 包装成"模仿人类认知"。但代码揭示的现实是：上层每秒输出一个数字、钳住下层的速度。这当然是一种分工，但"认知"的含量没有叙事里那么多。更准确的描述是"**规则执行器 + LLM 安全钳**"。叙事无罪，但读者要分清哪部分是机制、哪部分是故事。

**第二，评测集是"为 LLM 定制的考卷"。** Hard-55 按 IDM 的失败挑，Super-Hard-24 按 PDM-Closed 的失败挑——考题专挑规则规划器不会的，而这恰好是 LLM 的舒适区。如果换一套"LLM 容易犯蠢"的场景（比如需要精确几何计算的窄道会车），数字可能会反过来。Frenetix 那一行（强规则规划器 + LLM 几乎无增益）已经暗示了：**LLM 的增益 ≈ 下层有多弱**。这个等式论文没有明说，但数据里写着。

**第三，单帧、无地图、无历史——上层的"视力"很差。** 上层看到的只是一帧的 agent 文本描述，没有车道线、没有上一秒发生了什么。一个 1Hz 的、近视的、只能说"慢点"的安全员，能在 Hard-55 上把 R-CLS 从 39.76 拉到 57.31，恰恰说明这些难例里**大部分失败就是"该减速没减速"**——IDM 类规划器的通病是跟驰模型太乐观。换句话说，DualAD 的成功有一半要归功于"对手太弱"，而不是"上层太强"。

**第四，成本账没算。** 即使按 1Hz、GLM-4-flash（免费 API），每次调用 7 秒 sleep，150 步的仿真里 15 次调用 = 105 秒纯等待；GPT-4o 版本是 30 秒 × 15 = 450 秒。论文不报墙钟时间，但任何想复现的人都要有心理准备：**这套评测是拿时间换出来的**。以及 GLM-4-flash 免费额度的稳定性——智谱的免费 API 随时可能变，这是可复现性的外部风险。

做得漂亮的地方也要记一笔：**非对称干预的设计**是真知灼见——把 AI 的输出空间约束成"只能让系统更保守"，这是安全关键系统里"包络保护"（envelope protection）思想在 LLM 时代的翻版，航空业用了几十年。以及**诚实报告负面结果**（Frenetix 无增益、NR 下跌、格式失败率）——在 LLM-for-driving 普遍只报喜的风气里，这很难得。

## 与 RAMP 的血缘 / 划界（本批重点）

**DualAD 是 RAMP"调度-校验"分层思想最接近的在先先例，血缘关系可以画出一张精确的对应表：**

| DualAD | RAMP | 关系 |
|---|---|---|
| 下层：单个规则运动规划器（IDM/Lattice/Frenetix） | 下层：多规划器池（异构规划器） | RAMP 把"一"推广成"多" |
| 上层：LLM 文本推理 | 上层：LLM 调度器 + 风险校验器 | RAMP 把"一"拆成"二"（调度 vs 校验） |
| 干预动作：标量速度上限（只能降速） | 干预动作：轨迹级的否决/重排序 | RAMP 的动作空间更丰富 |
| 上层输入：当前帧的文本描述 | 上层输入：世界模型未来 rollout + 情景记忆检索 | RAMP 的上层"看得见未来、记得住过去" |
| 触发：固定 1Hz 稀疏监督 | 触发：风险驱动的按需校验 | RAMP 的门控是语义的，不是定时的 |

**RAMP 从 DualAD 能直接拿走的三样东西：**

1. **"上层只做减法"的安全戒律。** DualAD 证明了非对称干预（只能更保守）在工程上是 work 的，且失败模式是 fail-safe。RAMP 的闭环风险校验可以直接继承这条戒律：校验器的输出永远是"否决/降级"，绝不"加速/加码"。在 ICAPS 的 planning 语境下，这可以包装成"shielding"（安全屏蔽）的实例——planning 文献里有成熟的 shielding 理论可引，审稿人会很受用。

2. **文本编码器的序列化经验。** Frenet 相对坐标 + 阈值离散化 + 固定模板，消融证明 +11% R-CLS。RAMP 的 LLM 调度器同样需要把场景喂给 LLM，DualAD 的编码器是现成的起点。更进一步：RAMP 可以把**世界模型 rollout 的未来**也用同样的模板序列化（"3 秒后，VEHICLE_X 将在自车前方 12 米"），让调度器做"未来条件下的调度"——这是 DualAD 没做、RAMP 可以做的增量。

3. **"基座升级免费"的论证。** 表 II 证明换更强的 LLM 系统直接变强。RAMP 在论文里可以引用这一点来回应审稿人"你们的方法是不是过拟合到某个 LLM 了"——DualAD 的实证表明，分层架构下 LLM 是可替换的推理引擎，方法不绑定某个具体模型。

**划界（RAMP 的 novelty 台阶，一句话版）：** DualAD 的上层是**单步、单帧、单动作**（输出一个速度标量）；RAMP 的上层是**多步（调度+校验两步）、多帧（世界模型时序 rollout）、多动作（在规划器池上调度+在轨迹级否决）**，外加 DualAD 完全没有的情景记忆。DualAD 回答的是"LLM 能不能当安全员"，RAMP 回答的是"安全员能不能再有个参谋部（世界模型+记忆）"。在 related work 里，DualAD 应该放在"分层 LLM 监督"小节的**第一段**——它是这个故事的起点，RAMP 是终点。

还有一个具体的技术迁移点：DualAD 的干预是开环的（LLM 说降速就降速，不验证降速后的效果）；RAMP 的校验是闭环的（对每条候选轨迹打风险分，选最低的执行）。"开环监督 vs 闭环校验"是两篇论文在方法论上最锋利的一条分界线，写 related work 时值得用一句话点出来。

## 可复现性备注（代码核对结论）

- 论文与代码**核心一致**：非对称速度钳位（式 9）、Frenet 文本编码器（含 0.01 m/s 动静阈值）、1Hz 调用节流，代码里都能对上。
- 论文**没写**但代码里有的：`time.sleep(30/7)` 的 API 限流等待、LLM 输出的 `float()` 脏处理、prompt 只要数字不要推理。复现时 LLM.yml 里 `use_llm`/`use_text_encoder` 两个开关控制实验配置。
- 复现门槛：nuPlan mini 数据集（需注册下载）+ 智谱/OpenAI API key + 大量墙钟时间。按代码的 sleep 设置，完整复现表 I 的时间成本以**天**计。
