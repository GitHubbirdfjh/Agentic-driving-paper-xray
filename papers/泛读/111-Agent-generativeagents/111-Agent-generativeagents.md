# 记忆、反思、计划：Generative Agents 给 agent 造了第一个"海马体"

> **信息块**：Generative Agents: Interactive Simulacra of Human Behavior · Joon Sung Park, Joseph C. O'Brien, Carrie J. Cai, Meredith Ringel Morris, Percy Liang, Michael S. Bernstein（斯坦福 + Google Research / Google DeepMind）· **UIST 2023（第 36 届，2023-10-29–11-01，旧金山），最佳论文奖**（Best Paper，UIST 官网历年获奖名单确认）· DOI 10.1145/3586183.3606763 · arXiv:2304.03442（v2，2023-08-06）· 代码公开 https://github.com/joonspk-research/generative_agents（Apache 2.0；2026-10-11 实测 22,215 stars）· 在线 demo（Smallville 小镇）· **核心洞见一句话**：LLM 本体一个字不动，外面套一个"记忆流-检索-反思-规划"的脚手架，智能体的长期一致性就从 prompt 技巧变成了架构问题——**记忆用自然语言写，检索按"新近+重要+相关"三因子加权，反思把经验蒸馏成高层结论再喂回记忆**。

## 它要回答的问题：LLM 为什么"当时可信、过后就忘"

2023 年初的 LLM agent 有个公认的毛病：单轮对话惟妙惟肖，但没有长期一致性。让它扮演一个角色，十分钟后它就忘了自己说过什么、答应过什么。论文第 1 节把这个问题说得很准：人类行为空间巨大，一致性要求 agent 能"在新交互、冲突、事件不断涌现又淡去的过程中，管理不断增长的记忆"。GPT-4 当时已经很强，但作者明确写道：**长程规划和一致性的挑战，即使对 GPT-4 也依然存在**——所以他们用的是 gpt-3.5-turbo（GPT-4 的 API 当时还是邀请制），等于宣告"这个问题靠换更大的模型解决不了，得靠架构"。

Smallville 是他们的试验场：25 个 agent 的模拟小镇，每人一段身份描述当种子记忆，跑两天游戏时间，看能不能涌现出信息传播、关系形成、群体协作。Valentine's Day 派对是那个著名的种子：只告诉 Isabella"想办个派对"，两天后 12 个 agent 听说、5 个到场，还有人趁机约会——**没有一行脚本写"派对流程"，全是从记忆+交互里长出来的**。

## 记忆流（memory stream）：全部用自然语言记账

架构的核心是一个叫 memory stream 的长期记忆模块。**大白话**：它就是一个按时间追加的清单，每一条记忆是一个自然语言句子，外加两个时间戳——创建时间，和"上次被想起来的时间"。种子记忆是身份描述按分号切开的一句句话（"John Lin 是药店店员"、"他和邻居 Sam Moore 认识好几年了"），之后每一步感知到的观察（"Isabella 正在摆羊角面包"、"冰箱空了"）都追加进去。

"全部用自然语言记"这个决定是深思熟虑的：只有自然语言能被 LLM 直接检索、直接推理、直接生成更高层的结论。如果记忆是向量，LLM 就读不懂；如果是结构化数据库，开放世界的事件又装不下。代价是 token 开销巨大——25 个 agent 跑两天花了"数千美元的 token 额度、好几天时间"（第 8.2 节原话）。**这是全文最诚实的一处成本披露**，也是后来所有记忆架构论文都要回答的问题：检索做得再漂亮，跑不起也是白搭。

## 检索：recency + importance + relevance，三因子加权

记忆流会无限增长，prompt 装不下，所以每一步都要检索一个子集。检索函数是全文最值得抄的公式：

$$\text{score} = \alpha_{\text{rec}} \cdot \text{recency} + \alpha_{\text{imp}} \cdot \text{importance} + \alpha_{\text{rel}} \cdot \text{relevance}$$

三项先各自 min-max 归一化到 [0,1]，$\alpha$ 全取 1（**没调参，直接 1:1:1**——2023 年的论文敢这么写，说明三项的量级设计本身就是对齐的），取分最高的若干条，塞满 context window 为止。

三项各自的含义：

- **Recency（新近性）**：按"自上次被检索起经过的游戏小时数"做指数衰减，衰减因子 0.995。注意不是"创建时间离现在多久"，而是"**上次被想起来**离现在多久"——被经常想起的记忆会保持新鲜，这是对人类记忆提取练习效应（retrieval practice）的拙劣但有效的模仿。$0.995^{24} \approx 0.887$，一天不被想起只衰减 11%，**衰减得非常慢**，基本靠 importance 和 relevance 在干活。
- **Importance（重要性）**：记忆创建时直接问 LLM："1 到 10 打分，1 是纯粹日常（刷牙、铺床），10 是刻骨铭心（分手、大学录取），下面这段记忆的'poignancy'是几分？"论文给了实例："cleaning up the room"得 2 分，"asking your crush out on a date"得 8 分。**重要性是一次性判定的，不随时间更新**——这是个简化，RAMP 的"自适应衰减"恰恰是要动这一块。
- **Relevance（相关性）**：把每条记忆和当前 query（当前情境）都 embed 成向量，算余弦相似度。query 是什么取决于"相关于什么"，比如决定行动时 query 就是当前观察。

论文 4.1 节有个对比实验说明检索为什么必要：直接问 Isabella"你最近热衷什么"，如果把全部记忆摘要塞进 prompt，回答是车轱辘话（"collaborations for events and projects and cleanliness"）；用检索挑出相关记忆，回答立刻具体（"让客人感到受欢迎、策划活动、比如 Valentine's Day 派对"）。**摘要（summarize-all）vs 检索（retrieve-relevant），检索赢**——这对后来所有 RAG-for-agent 的设计是一锤定音的。

## 反思（reflection）：记忆的"蒸馏塔"

只有原始观察的 agent 会犯一种蠢：被问"想和谁共度一小时"，它选交互次数最多的 Wolfgang——但两人只是点头之交。人类会怎么做？从"Klaus 花几小时做研究项目"泛化出"Klaus 热爱研究"，再从"Maria 也在做研究"泛化出"两人有共同语言"，于是选 Maria。**Reflection 就是把这种泛化做成定期的批处理**。

触发条件：最新一批事件的 importance 分数之和超过阈值 150。按论文的量级（普通事件 2–8 分），大约攒二三十个事件触发一次，**实际约一天 2–3 次**。流程三步：

1. 拿最近 100 条记忆问 LLM："只看这些，能问出 3 个最高层的问题是什么？"（例："Klaus 热衷什么话题？"、"Klaus 和 Maria 是什么关系？"）
2. 把这 3 个问题当 query 做检索（含已有的 reflections），拿到相关记忆。
3. 问 LLM："从这些陈述里提炼 5 条高层洞见，格式：洞见（because of 1, 5, 3）"——**要求它标注每条洞见的证据编号**，解析后存回记忆流，并保留指向证据的指针。

因为 reflections 自己也进记忆流、下次检索也会被检出来，系统会生成**反思树**：叶节点是原始观察，越往上越抽象（Figure 7 的 Klaus 树：从"在写论文""在读 gentrification 的书"长出"Klaus 对 gentrification 研究非常投入"）。这是全文最漂亮的机制：**记忆不再是平的清单，而是有抽象层次的**。

## 规划（planning）：从"一天 5–8 段"递归拆到"5 分钟"

没有规划的 agent 会在 12 点、12 点半、1 点各吃一次午饭（论文的原例子：每轮只优化"当下可信"，长期就荒诞）。规划的做法是自顶向下递归分解：先让 LLM 按"身份+昨日总结"写一天 5–8 个大块（"1 点到 5 点在图书馆写论文"），再拆成小时块（"4 点休息一下"），再拆成 5–15 分钟块（"4:00 吃根香蕉，4:05 出去走走"）。**计划也存进记忆流，检索时和观察、反思一起被考虑**——计划不是外挂的状态机，是记忆的一种。

Reaction（反应）是规划的对偶：每步把新观察喂给 LLM，问"继续按计划走，还是反应？"（例：John 看到 Eddy 在花园散步 → 检索"Eddy 是我儿子、在写音乐作业、喜欢散步时想事情"→ 决定上前问作业进展 → 从反应时刻起重排当天计划）。对话生成同理：每句话都 conditioned on"对对方的记忆摘要 + 对话历史"，直到一方决定结束对话。

环境 grounding 也值得一提：Smallville 的世界是一棵树（世界→区域→物体，边表示包含），转成自然语言喂给 agent（"厨房里有个炉子"）；agent 选地点时从树根递归问 LLM"去哪个区域"，走到叶节点再用传统寻路算法移动。**自然语言是 agent 和引擎之间的唯一接口**，和 HuggingGPT（107）的"语言当插头"是同一个哲学。

## 实验：两种评估，各自证明了什么

**受控评估（第 6 节）**：把 agent 当人"面试"，5 类问题 × 每类 5 个（自我认知、记忆、计划、反应、反思），100 个 Prolific 众包评估者对 5 种配置的回答按可信度排名，用 TrueSkill（Xbox 排名那套 Elo 推广）转成分数：

| 配置 | TrueSkill $\mu$ |
|---|---|
| 完整架构 | 29.89 |
| 去 reflection | 26.88 |
| 去 reflection+planning | 25.64 |
| 人类众包写手 | 22.95 |
| 去 observation+reflection+planning（= 2023 年之前的 LLM agent） | 21.21 |

完整 vs 无记忆：Cohen's d = 8.16（八个标准差，效应巨大）；Kruskal-Wallis $H(4)=150.29, p<0.001$，Dunn 事后检验除"众包写手 vs 全去"外全部显著。**注意实验设计的一个诚实声明**：消融配置用的是完整架构跑出来的同一批记忆（作者承认这是"保守估计"，因为消融版自己跑两天根本走不到同样的状态）。众包写手基线作者也明说"不代表人类最高水平"。

**端到端评估（第 7 节）**：25 个 agent 跑两天游戏时间。Sam 竞选市长的消息从 1 人（4%）传到 8 人（32%），派对消息从 1 人传到 13 人（52%），**作者逐条核对了记忆流，确认没有一条是幻觉**；关系网络密度 0.167 → 0.74；12 个被邀请的 5 个到场（没来的 7 个里 3 个有冲突、4 个"想来但当天没计划"——后者是 planning 的失败）；453 条关系问答里 1.3%（6 条）是幻觉。

**三种典型错误**（7.2 节，RAMP 做记忆时要避开的坑）：① 检索失败导致的 embellishment（Tom 记得"要在派对上和 Isabella 聊选举"，却不记得"派对是否存在"；Isabella 无中生有"Sam 明天要开发布会"；Yuriko 说邻居 Adam Smith 写了《国富论》——同名人类的知识污染）；② 物理常识进不了自然语言（宿舍浴室一次只能进一个人，但 agent 按"宿舍浴室"的常识理解为多人）；③ 指令微调的副作用：对话过于正式、过于配合（Isabella 从不拒绝别人的派对建议，久而久之兴趣都被带偏）。

## 怀疑式阅读

1. **$\alpha$ 全取 1，没有敏感性分析**。三因子等权是拍脑袋还是真不敏感？论文没做消融。如果 importance 的 LLM 打分本身噪声大，等权可能是在用另两项给它擦屁股。
2. **重要性一次性判定、永不更新**。分手 10 分，十年后还是 10 分（按公式只有 recency 在衰减，还衰减得很慢）。RAMP 的"风险加权自适应衰减"要解决的正是这个问题：重要性应当随风险和时间动态调整。
3. **反思的证据引用是"看起来严谨"**。要求 LLM 标注"because of 1, 5, 3"，但没有任何验证引用的编号真的支持结论——LLM 完全可以编一个漂亮的编号。这是 2023 年的普遍做法，今天看来需要外部校验。
4. **成本**：数千美元 + 好几天，25 个 agent 两天。**这个数字决定了这套架构在 2023 年只能做 demo**，也解释了为什么后来 MemGPT、A-MEM 等工作首先砍的就是"每步调多少次 LLM"。
5. **评估的主观性**：可信度（believability）排名是主观指标，评估者还被允许看完整记忆流回放（等于开卷考）。效应量巨大（d=8.16）部分来自"无记忆版实在太蠢"（连自己是谁都答不对），不是"完整版特别聪明"。

## 与 RAMP 的血缘/划界

**血缘是"记忆"这一整条线**。Generative Agents 是 agent 记忆架构的开山：memory stream（经验全记录）→ 三因子检索（recency/importance/relevance）→ reflection（经验蒸馏成高层结论）→ 计划与行动，这个四段式是后来所有 agent 记忆工作（MemGPT、Reflexion、A-MEM、Mem0）的共同祖先。RAMP 的"风险加权自适应衰减情景记忆"直接站在它的肩膀上，对应关系精确到公式：

- 它的 recency（指数衰减 0.995）→ RAMP 的自适应衰减（但 RAMP 的衰减率是风险加权的，高风险记忆衰减慢）；
- 它的 importance（LLM 一次性打分 1–10）→ RAMP 的风险权重（动态的、从闭环反馈里更新的）；
- 它的 relevance（余弦相似）→ RAMP 保留（分层检索的第一层）；
- 它的 reflection（定期蒸馏）→ RAMP 没有直接对应物，这是 RAMP 可以补的一块：情景记忆里的高风险片段是否值得定期蒸馏成"驾驶反思"，是 RAMP 后续工作的 natural extension。

**划界有三条**，每一条都是"驾驶"这个领域逼出来的。第一，**实时性**：Generative Agents 每步调多次 LLM、跑两天花数千美元；驾驶是 10–20Hz 的闭环，RAMP 的记忆检索必须在毫秒级完成，这就是 RAMP 做"分层粗细检索"的动机——开山论文的架构在驾驶里**原样跑不动**。第二，**记忆的目的不同**：它的记忆服务于"可信度"（believability），RAMP 的记忆服务于"风险"（risk）——检索的 query 不是"当前情境"，而是"当前风险"，这是 related work 里要讲清的范式差异。第三，**它没有执行层的校验**：记忆错了，agent 就照着错的记忆行动（Tom 的派对例子）；RAMP 的闭环风险校验独立于记忆，即使记忆检索错了，安全盾还能拦一道——这是 RAMP 对开山架构的实质性补强，也是 ICAPS 审稿人会问"你们和 Generative Agents 的区别是什么"的标准答案。
