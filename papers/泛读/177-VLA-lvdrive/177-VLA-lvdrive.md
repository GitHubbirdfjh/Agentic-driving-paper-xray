## 稀疏监督和像素重建：2026 年初 VLA 撞上的两堵墙

读这篇论文之前，先把时间坐标摆正。2026 年 5 月，VLA 驾驶已经走完第一波：ORION（ICCV 2025，小米汽车同一团队）证明了"多视角图像 + 语言指令 → LLM → 轨迹"这条路在 Bench2Drive 上能跑到 DS 77.74；ReCogDrive 把强化学习接进来，DS 71.36；DriveVLA-W0 开始谈世界模型放大数据 scaling law。领域在这个时点的默认信念是：VLA 的瓶颈在动作监督太稀疏——一条轨迹几个 waypoint，喂不饱几十亿参数的场景理解能力。

于是出现两种补救。第一种是给 VLM 讲故事：DriveVLM、Senna 让模型先输出场景描述再规划，指望语言把推理过程显式化。第二种是世界模型路线：UniDrive-WM 让模型自回归地生成未来图像的离散 token，把"预测未来"当辅助任务。前者的问题是语言描述和轨迹之间隔了一层转述；后者的问题更实在——LVDrive 引言里点名的三件事，每一件都打在 UniDrive-WM 这类方法的七寸上。

第一，像素重建带偏表征。为了把未来帧画得像，模型被迫把容量花在纹理、光照、路面颗粒这些对规划无用的细节上。作者引了 I-JEPA（Assran et al., 2023）和 V-JEPA 2（2025）为自己站台：预测应该发生在抽象表征层，而不是像素层。这不是新论点，但把它第一次系统地搬进"大 VLA 驾驶模型"这个载体，是 LVDrive 的切入点。

第二，自回归太贵。UniDrive-WM 生成未来图像要逐 token 解码几千个视觉 token，推理延迟直接爆炸。驾驶是实时任务，这个代价不是"优化一下"能解决的，是结构性的。

第三，未来特征没进规划。已有方法要么让未来视觉特征和运动特征"隐式交互"一下（UniDrive-WM、FutureSightDrive），要么拿未来帧当世界模型去算 reward（DriveWorld-VLA）。没有一种设计把未来语义**显式地、作为条件**喂进轨迹生成器。辅助任务学到的东西，最后和规划器是两张皮。

这三堵墙就是论文的起点。注意作者的措辞强度分布：对第一点用的是"we argue"（第 2 节 related work 里关于 latent world modeling 的段落），对第二、三点用的是事实陈述（"inherently time-consuming"、"Neither design is an explicit mechanism"）。底气最足的是第二点——一次前向 vs 自回归，这是算术，不是观点。

## 作者手里的三张牌

从论文的组织方式反推，作者开工前有三张牌，每张都降低了风险。

第一张是**现成的骨架和训练管线**。二作 Diankun Zhang 是 ORION 的一作，ORION 就是这篇的直接前身：同样的 EVA-02-L + QT-Former 视觉编码、同样的 Vicuna v1.5 + LoRA、同样的 VAE 式生成规划器（承自 VAD/GenAD/ORION 一脉）。LVDrive 用的初始化权重就是 ORION 第一阶段（Chat-B2D 的 VQA 对齐）训好的。所以作者不是从零搭一个 VLA，而是在一个已经 DS 77.74 的系统上，只动"监督信号"这一个变量。表 3 的 Mbase（65.25 DS on Dev10）就是 ORION 第二阶段训练范式的复刻——起点本身是经过验证的。

第二张是**免费的稠密监督**。未来帧本来就在训练数据里躺着，不用标注、不用采集。VQGAN-ImageNet 的权重是公开的，冻结它、取它的量化 code embedding 当目标，整个辅助任务的"老师"是零成本请来的。这和 FPD-Drive 请 PDM evaluator 当裁判是一个路数：找一个现成的、不需要训练的外部信号源。

第三张是**Bench2Drive 的官方评测协议**。220 条路线、44 个场景 × 5 种路线实例，DS/SR/Efficiency/Comfortness/Multi-Ability 五套指标全是现成的。作者不用自证"我的评测是公平的"，直接把表 1 摆出来和所有人对打。

三张牌里最硬的是第一张：站在 ORION 的肩膀上，实验的方差主要来自新加的模块，而不是整个系统的抖动。这也解释了为什么论文敢把主要篇幅花在消融上——骨架是稳定的，消融的信号才可信。

## 为什么预测的是 latent 而不是像素：一次具体的形状 walkthrough

先看图 2（论文第 3-4 页），再看公式。LVDrive 的核心手法分三步，每一步都有具体的形状，先把形状表立在这里，后面所有讨论都落在这张表上。

| 符号 | 形状 | 含义 |
|---|---|---|
| $x_s, x_h$ | 结构化多视角特征（QT-Former 压缩后） | 当前 + 历史场景的视觉输入 |
| $x_q$ | 文本 token | 语言指令 |
| `<img_i>`, $i \in \{0..N\}$, $N=256$ | 每帧 256 个占位 token | 第 $j$ 个未来帧的 latent 视觉槽位 |
| `<img_start>` / `<img_end>` | 边界标记 | 把 6 帧的槽位切分开 |
| $F$ | 6 | 未来帧数（只预测前视） |
| $D$ | 4096 | LLM（Vicuna v1.5）隐层维度 |
| $H_{t+j}$ | $\mathbb{R}^{N \times D} = \mathbb{R}^{256 \times 4096}$ | 第 $j$ 个未来帧槽位对应的 LLM 末层隐状态 |
| $V_{t+j}$ | $\mathbb{R}^{N \times C_v} = \mathbb{R}^{256 \times 256}$ | 视觉解码器输出的语义未来特征 |
| $C_v$ | 256 | VQGAN-ImageNet 后量化 embedding 维度 |
| `<waypoint_ego>` | 1 个 token，放在未来序列**最后** | 规划 token，其嵌入 $H_p \in \mathbb{R}^{1 \times 4096}$ |
| $z$ | $\mathbb{R}^{C_z}$, $C_z=32$ | VAE 采样的运动隐变量 |
| $s_{ego}$ | $\mathbb{R}^{F \times 2D} = \mathbb{R}^{6 \times 8192}$ | 第一阶段解码的未来运动状态 |
| $C_r$ | 1024 | 精化器 cross-attention 维度 |
| $\tau_c, \tau_f$ | $\mathbb{R}^{K \times F \times 2}$, $K=6$ | 粗轨迹 / 精化后轨迹（6 种模态 × 6 步 × xy） |

推理时，输入序列是这样铺的（见自绘图）：

```

```

*自绘图：LVDrive 单次前向的 token 布局与张量形状。特殊 token 共 6×(256+2)+1 = 1549 个，推理时全部预填充，一次前向同时读出未来场景表示和规划嵌入。*

`[多视角视觉 token] [文本指令] [<img_start> 256×<img_i> <img_end>] × 6 [<waypoint_ego>]`

特殊 token 总数：$6 \times (256 + 2) + 1 = 1549$。推理时这 1549 个 token 全部预填充（pre-filled），LLM 做**一次**前向，每个位置的隐状态一次算完——没有逐 token 自回归。这就是"单次前向"的全部含义：把原来需要 1549 步自回归生成的离散视觉 token，换成 1549 个槽位的一次并行读出。

然后是两次"读出"（readout），都发生在同一次前向的末层隐状态上：

**读出 1：未来场景。** 对第 $j$ 帧的槽位区间，取出 $H_{t+j} \in \mathbb{R}^{256 \times 4096}$，过一个**单层线性**视觉解码器 $VIS_\theta$（4096→256，无激活函数，见附录 A.1）：

$$V_{t+j} = VIS_\theta(H_{t+j}), \quad V_{t+j} \in \mathbb{R}^{N \times C_v} \tag{2}$$

监督目标是冻结的 VQGAN-ImageNet 把**未来真实前视图像**（256×256，未来 6 个时刻）编码成的特征：VQGAN 给出 $16 \times 16 \times 256$ 的 latent，展平成 $256 \times 256$，再过 LayerNorm。注意作者刻意用的是**量化后的 code embedding**，而不是离散 code index——目标本身就是连续向量，所以损失可以直接用余弦相似度 + L1：

$$L_{vis} = w_c L_{cosine} + w_r L_{reg} \tag{3.4}$$

$w_c$、$w_r$ 的具体数值论文**没有给出**（全文只出现这一个公式）。这是后面怀疑清单的第一条：两项的量级、谁主导梯度，无从判断。

**读出 2：规划。** `<waypoint_ego>` 被放在未来序列的**最后**。因为 LLM 用因果注意力，这个 token 能看到它之前的所有 token——包括 6 帧共 1536 个未来视觉槽位。它的嵌入 $H_p \in \mathbb{R}^{1 \times 4096}$ 就这样**隐式地**聚合了未来场景信息。这一步没有任何额外的损失项，是纯粹靠位置摆放实现的"信息聚合"。问题式地想：如果把 `<waypoint_ego>` 放到未来序列**前面**，因果注意力会把它和未来槽位隔开，$H_p$ 就看不到未来——整个"未来感知推理"的前提就垮了。这个位置摆放是设计里最便宜、也最承重的一笔。

公式 (1) 把整个任务写成联合分布：

$$V_{t+1:t+F},\, s \sim p(V_{t+1:t+F},\, s \mid x_s, x_h, x_q) \tag{1}$$

$s$ 是规划 token 的嵌入。注意这个公式是**声明式**的：它说"我们在联合建模未来视觉和动作"，但真正的机制是上面的两次 readout + 因果注意力的位置设计。公式本身没有给出联合分布的分解形式（比如 $p(V)p(s|V)$ 还是反过来），读的时候不要被它的一般性迷惑——承重的是实现细节，不是这个公式。

## 只预测前视：一个强假设及其代价

"人类司机主要看前方，所以前视预测足以提供未来感知"——这是第 3.1 节的原话，也是全篇最强的一个假设。它的工程收益很实在：只预测一个视角，1549 个 token 里未来部分是 $6 \times 258 = 1548$ 个；如果六个视角全预测，token 数要翻数倍，H20 上 2.03 秒的推理时间就保不住了。

代价在表 2 里兑现了：Give Way 技能 20.00%，是 VLA 行里最低的一档（和 ReCogDrive 的 20.00% 并列）。Give Way 的典型场景是后方有救护车接近需要让行——前视未来预测天然看不到车尾发生的事。作者在第 4.3 节和附录 A.4 里**诚实地承认了这一点**，还给了失败案例（图 8：救护车从后面接近，自车直行不让行），并把原因直接归于前视预测导致模型注意力偏向前方。

这里要给作者记一笔诚实分：很多论文会把最差的一项藏进 "mean" 里一笔带过，LVDrive 把失败案例画成整整一页图。但也要看到另一面：Give Way 在 Bench2Drive 里只有 2 个场景（附录表 7），权重很小，所以这个结构性盲区几乎不影响 DS/SR 总分。如果评测里 Give Way 场景占 1/5，DS 80.71 这个数字是要打折的。**指标的分布，决定了缺陷的可见度。**
## 两阶段解码：为什么未来特征不能一步到位揉进规划

这是论文里戏剧性最强的一段，表 3 的三行消融就是剧本。先把两阶段的机制讲完，再回头看那三行数字为什么这样跳。

**第一阶段：VAE 式粗规划。** 规划嵌入 $H_p$ 先被映射成一个高斯分布：

$$z \sim p(\mu, \sigma^2); \quad (\mu, \sigma^2) = DIS_\theta(H_p), \quad z \in \mathbb{R}^{C_z} \tag{3}$$

$$s_{ego} = STATE_\theta(z, H_p), \quad s_{ego} \in \mathbb{R}^{F \times 2D} \tag{4}$$

附录 A.2 给了完整实现，值得逐项过一遍，因为每一项都有讲究：

- $DIS_\theta$：三个 1×1 一维卷积 + ReLU，把 4096 维压到 2048；平均池化后再过一个 1×1 卷积，同时输出 $\mu$ 和 $\log\sigma$，各 32 维（$C_z = 32$）。1×1 卷积在这里等价于逐位置的 MLP，用卷积写只是为了沿用 VAD/GenAD/ORION 的代码习惯。
- **KL 散度项被删了。** 标准 VAE 目标里有 $KL(q(z|x) \| \mathcal{N}(0,I))$，把隐分布往标准正态上拉。作者说"凭经验删掉"，理由是 KL 正则会过度约束多模态隐空间、损害学习能力。删掉之后，这个"VAE"其实退化成了一个**没有先验约束的条件随机编码器**：$z$ 的分布可以自由长成任何形状，只要能帮着把轨迹解码准。这是一个诚实的工程选择——多模态轨迹（$K=6$ 对应 6 种导航指令）本来就不该被压成单峰高斯。但代价是：没有任何东西阻止 $z$ 塌缩成确定性编码（方差学到接近 0），多模态性这时全靠"采样"这个动作在形式上维持。论文没有报告学到的 $\sigma$ 的实际量级，这是个缺口。
- **训练和推理的输入不对称**，这是附录里最容易滑过去的一句："训练时，真值自车轨迹和规划嵌入拼接起来作为输入，去生成分布，以稳定分布学习。" 也就是说，训练时 $DIS_\theta$ 看到的是 $[H_p; \tau_{gt}]$（后验），推理时只能看到 $H_p$（先验）。标准的 CVAE 会用 KL 项把后验和先验绑在一起；这里 KL 被删了，绑后验和先验的绳子就没了。实践中它 work（表 1 的数字为证），但这意味着分布生成器在推理时做的是**分布外泛化**：它没见过的输入组合（只有 $H_p$、没有真值轨迹）要输出合理的 $(\mu, \sigma)$。作者没有讨论这一点，也没有消融"训练时不拼接真值轨迹"会怎样。
- $STATE_\theta$：采样的 $z$（32 维）先重复 6 次对齐 6 个预测时刻；4 层 GRU（隐层 1024）+ 3 层 MLP（ReLU）输出 4096 维；再把 $H_p$ 也重复 6 次拼在后面，得到 $s_{ego} \in \mathbb{R}^{6 \times 8192}$（$8192 = 2 \times 4096$，这就是公式 (4) 里 $F \times 2D$ 的来源）。最后 3 层 MLP（ReLU）解出 $K=6$ 条粗轨迹 $\tau_c \in \mathbb{R}^{6 \times 6 \times 2}$。

**第二阶段：精化器。** 把第一阶段的运动状态投影成 ego motion query，再用 cross-attention 去未来视觉嵌入里"取"语义：

$$Q_{ego} = PROJ_\theta(s_{ego}), \quad Q_{ego} \in \mathbb{R}^{F \times C_r} \tag{5}$$

$$K_{fut}, V_{fut} = PROJ_\theta(H_{t+1:t+F}), \quad K_{fut}, V_{fut} \in \mathbb{R}^{F \times C_r} \tag{6}$$

$$s^*_{ego} = TRAJREFINER_\theta(Q_{ego}, K_{fut}, V_{fut}), \quad s^*_{ego} \in \mathbb{R}^{F \times C_r} \tag{7}$$

精化器是 2 层 transformer block（$C_r = 1024$），$PROJ_\theta$ 是单层线性 + LayerNorm + GELU。精化后的 $s^*_{ego}$ 进两个结构相同的 MLP 头（2 层线性 + LN + GELU），分别输出 base trajectory 和 offset，相加得到最终轨迹 $\tau_f$。base + offset 的拆分是为了生成灵活性与多样性——offset 头可以学残差修正，base 头保大盘。

这里有一个**全文最有信息量的设计选择**：公式 (6) 里 cross-attention 的 K、V 用的是 $H_{t+1:t+F}$——LLM 的原始隐状态——而不是解码出来的 $V_{t+1:t+F}$。论文只用一句话解释："保留更多来自 LLM 的推理信息"。

把这句话展开：$V_{t+j}$ 是被训练去拟合 VQGAN 特征的，而 VQGAN 是在 ImageNet 上为**图像重建**训练的。$V$ 里装的是"能重建出未来图像"的语义，带着重建任务的偏置；$H$ 是 LLM 末层隐状态，除了拟合 VQGAN 之外，还同时服务于规划 token 的因果聚合，里面残留着 LLM 的推理痕迹。用 $H$ 做 K、V，等于让精化器直接读 LLM 的"思考过程"，而不是读已经被 VQGAN 目标"提纯"过的视觉特征。这是一个有品味的选择——它承认了辅助任务的目标（拟合 VQGAN）和主任务的需求（规划）之间存在张力，不把辅助任务的输出当成唯一的真理。

但这里也有一个**论文没说清楚的形状缺口**：$H_{t+j} \in \mathbb{R}^{256 \times 4096}$（每帧 256 个 token），而公式 (6) 的输出是 $\mathbb{R}^{F \times C_r} = \mathbb{R}^{6 \times 1024}$——每帧 256 个 token 是怎么压成 1 个的？平均池化？取特定 token？附录 A.2 只写了"投影到匹配的隐维度"，没写 token 维度的归约方式。复现的人到这里会卡住。

## 表 3 的三连跳：先变差，再变好，说明了什么

Dev10（10 条路线，每条来自不同代表性场景）上的消融，论文 4.4 节的解读值得逐行检验：

| 变体 | 未来预测 | 解码 | DS | SR |
|---|---|---|---|---|
| Mbase | – | – | 65.25 | 4/10 |
| Mvis | ✓ | – | 66.31 | 3/10 |
| Mone | ✓ | 一阶段 | 60.43 | 3/10 |
| LVDrive | ✓ | 两阶段 | 82.39 | 7/10 |

Mbase 是纯动作监督的基线（ORION 第二阶段范式的复刻）。Mvis 直接把未来预测当辅助任务加上去：DS 涨了 1.06，SR 掉了 1 条路线。作者的解释是"运动规划和未来场景预测活在视觉/动作两个不对齐的特征空间里，朴素多任务引入了冲突的优化信号"。

停一下。DS 涨 1.06、SR 掉 1/10——在 10 条路线的粒度下，这个"一升一降"有多少是信号、多少是噪声？SR 的粒度是 10%，掉一条路线完全可能是某条路线上的偶发碰撞。作者用"we speculate"（推测）来措辞，是诚实的。但紧接着的 Mone 又掉了 6 个点 DS，这就很难用噪声解释了，说明"冲突"这个故事至少方向是对的。

Mone 是作者试过的**第一种修复**：把 $H_p$ 直接当 ego motion query，用 cross-attention 去抓未来特征，再喂进 VAE 规划器——让两个任务"朝着同一个目标优化"。结果更差（60.43）。作者的结论是：这种直接融合损害了运动特征的学习。然后才有了两阶段：先用动作标签把粗轨迹的动作特征**稳定下来**（第一阶段只靠 $L_{plan}$），再让精化器去聚合未来语义（第二阶段 $L_{plan\_r}$）。DS 从 60.43 跳到 82.39。

这个"先稳定动作、再引入视觉"的顺序，恰好呼应了精化器用 $H$ 不用 $V$ 的逻辑：**动作特征有自己的主权，视觉是来帮忙的，不是来夺权的。** 一阶段融合失败的根本原因，可能是 cross-attention 的梯度直接打进了 $H_p$，干扰了 VAE 分布的成形；而两阶段里，第一阶段的 $H_p \to (\mu,\sigma)$ 路径不受视觉梯度干扰，视觉只在第二阶段以残差（offset）形式介入。这是一个可以从梯度流角度讲通的故事，论文没有明说，但表 3 的数字支持它。

不过要打一个折：所有消融都在 Dev10 上，10 条路线。82.39 vs 65.25 的差距足够大，不太可能是噪声；但 Mvis 到 Mone 的"进一步变差"（66.31→60.43），以及 M1（65.42）相对 Mbase（65.25）的"轻微提升"，都在噪声带里。读消融表时，只信大跳变。

## 表 4：DINOv3 输给 VQGAN，是冗余还是维度没对齐

未来监督的 backbone 对比是论文里第二精彩的消融：

| 变体 | 监督 backbone | 特征维度 | DS | SR |
|---|---|---|---|---|
| Mbase | – | – | 65.25 | 4/10 |
| M1 | 内部视觉编码器 | 1024 | 65.42 | 4/10 |
| M2 | MoVQGAN（Emu3） | 4 | 59.91 | 3/10 |
| M3 | DINOv3-Large | 1024 | 71.72 | 5/10 |
| LVDrive | VQGAN-ImageNet | 256 | 82.39 | 7/10 |

M1 说明：拿自己正在训练的视觉编码器当老师，等于自己教自己，几乎没增益（+0.17 DS）——外部冻结大模型的知识才是增量的来源。这个对照做得干净。

M2 掉到 59.91：MoVQGAN 的 code embedding 维度只有 4（为离散 token 化高度压缩的），作者归因于"维度太低，信息传不过去"。合理。

M3 是关键：DINOv3-Large（1024 维，自监督视觉表征的当前顶流）带来明确增益（71.72），但输给 VQGAN-ImageNet（82.39）。作者的解释是"DINOv3 的特征过于丰富，把冗余信息当噪声带进了视觉-动作共享空间"。

这个解释**站不太住**，至少不是唯一的解释。另一个同样合理的解释是**优化难度**：视觉解码器是单层线性，4096→1024（DINOv3）和 4096→256（VQGAN）的拟合难度不一样；1024 维目标的余弦+L1 损失 landscape 更崎岖，6 个 epoch 可能根本没拟合好。论文没有做"把 DINOv3 特征降到 256 维再试"的控制实验，所以"冗余噪声"和"维度/优化难度"两种解释分不开。一个更干净的消融应该是固定目标维度、只换 backbone 的语义来源。现在的表 4 同时变了两个变量（backbone 和维度），结论的归因是含糊的。

话说回来，VQGAN 赢本身是个**反直觉**的结果：一个在 ImageNet 上为重建训练的生成模型，当"语义老师"打败了 DINOv3。这说明在驾驶场景里，VQGAN 的 codebook（16384 个码）学到的可能是中层视觉模式（边缘、纹理基元、物体部件），恰好和"未来场景里有什么东西在动"这个规划需求对齐；而 DINOv3 的高层语义对轨迹解码来说可能太粗了。这是个值得深挖的点，论文点到为止。
## 表 1 逐项过堂：作者没强调的三件事

Bench2Drive base split（1000 clips，44 场景 × 23 天气 × 12 城镇；950 训练 / 50 开环验证；220 条路线交互评估）上的主结果，LVDrive：**DS 80.71，SR 58.26%**，纯视觉（C），模仿学习。往下逐项看：

**第一，赢的是交互评估，不是开环拟合。** 开环 Avg. L2 上 LVDrive 是 0.63——DriveMoE 0.38、DriveTransformer-Large 0.62、UniDrive-WM-AR 0.64，LVDrive 处在中游。它的 DS/SR 第一，来自 220 条路线上的实际驾驶表现，而不是轨迹拟合精度。这个反差恰好是论文立论的证据：未来预测改善的是模型对交互式场景的应对（该刹车时刹车、该绕行时绕行），而不是把开环 L2 再压低 0.1。开环 L2 和交互 DS 的脱钩，在端到端驾驶里是老现象（TCP-traj L2 1.70 但 DS 59.90 就是一例），LVDrive 是又一个注脚。

**第二，Comfortness 14.34 是全表最低。** 把 VLA 行扫一遍：Driveπ0 14.88，DriveMoE 15.31，ReCogDrive 17.45，ORION 17.38，UniDrive-WM-AR 28.01。LVDrive 的 14.34 垫底。Efficiency 155.77 倒是健康的（UniDrive-WM-AR 158.44，ORION 151.48）。组合起来看：车开得快、分高，但顿挫。**这是"用舒适性换进度"的老故事在 VLA 线上的重演**——ReCogDrive 的精读里我们见过一模一样的结构（PDMS 里 progress 权重翻倍、舒适性 17.45 全文零讨论）。LVDrive 的摘要写"significant improvements in closed-loop driving performance"，正文没有任何关于舒适性代价的讨论。DS 的计算里舒适性不占权重（DS 只计路线完成和违规折扣），所以这个代价在主指标里是隐形的。审稿人如果问"你们的车为什么这么抖"，论文里没有答案。

**第三，和 UniDrive-WM 的差距是 1.49 个 DS 点，不是代差。** UniDrive-WM-AR 79.22 / 56.36，+Diff 变体 79.31 / 56.42；LVDrive 80.71 / 58.26。作者在 4.3 节花了一整段讲这个对比，论点是"latent 学语义 vs 像素重建"的优越性，外加"我们不用复杂的多阶段训练管线"。1.49 个点的领先，在 220 条路线的评估下方差有多大？论文没给多次运行的标准差（训练用 32×H20 跑 6 epoch，成本决定了不太可能跑多次），所以"显著超过"（significantly）这个词的统计学底气是不足的。话又说回来：用**单阶段端到端训练**（6 epoch，无多阶段管线）达到这个数字，工程上是更干净的结果——即使把"显著"打个折，结论方向大概率成立。

另外两个值得记录的数字：表 5 里**粗轨迹本身**（Mcoarse，只用 $H_p$ 解码、不进精化器）在 Dev10 上已经 73.22 / 5/10，超过 Mbase 的 65.25 / 4/10。这说明"未来感知推理"（因果注意力把未来信息聚合进 $H_p$）这一步已经贡献了大部分增益，精化器是把 73.22 推到 82.39 的第二程。这个分解很重要：它证明论文的两个贡献不是互相依赖的，单拿"一次前向联合建模"出来也成立。

## 表 6 的 36.62 秒：一个假设基线的诚实度

推理速度对比（H20，batch size 1，Bench2Drive 官方验证集）：Mbase 0.93s，LVDrive 2.03s，MAR 36.62s。

MAR 是什么？论文原话："a hypothetical autoregressive baseline MAR, which is configured to generate vision and action tokens of equivalent length"——一个**假设的**自回归基线，按"生成等长视觉+动作 token"配置，36.62 秒不是某个真实模型的实测延迟。作者用"hypothetical"这个词，是诚实的：它论证的是量级（自回归 1549 个 token 在 7B LLM 上就是几十秒的量级），不是和某个具体竞品的公平对比。

LVDrive 2.03s vs Mbase 0.93s：未来预测任务让单次前向慢了约 2.2 倍。2 秒一帧，离车载实时（通常 10-20Hz）还差一个数量级，但比自回归路线近了 18 倍。论文说"in principle leads to higher inference efficiency"，这个"in principle"用得克制——它承认 2.03 秒还不是终点。

## 和 HyWorldVLA 的分岔：纯 latent 和像素+latent 混合的立场之争

（以下基于任务描述中"HyWorldVLA 是像素+latent 混合监督"的定位写成，HyWorldVLA 原文未精读，细节以原文为准。）

两者的分歧点恰好是 LVDrive 引言的第一堵墙：**像素重建对表征学习是有害还是有益？**

LVDrive 的立场是明确的否定：像素重建把模型容量引向纹理细节，偏离规划需要的语义，所以**彻底不要像素分支**，只做 latent 监督（引 I-JEPA/V-JEPA 2 为理论背书，表 4 的 M2/M3 为经验证据）。如果 HyWorldVLA 保留像素重建分支、同时做 latent 预测（混合监督），那它赌的是另一面：像素级未来帧能提供 latent 特征给不了的细粒度几何约束（比如精确的物体轮廓、遮挡边界），而 latent 分支负责语义，两者互补。

这是一个**可验证的经验分歧**，不是观点之争：LVDrive 这边的证据是表 4（纯 latent 82.39，MoVQGAN 这种偏重建的监督掉到 59.91）；HyWorldVLA 那边需要拿出"加上像素分支后规划指标反而提升"的数字。RAMP 的 related work 里如果同时引用两者，一句话就能把战场划出来："LVDrive 认为像素重建有害而只做 latent 监督，HyWorldVLA 保留像素分支赌互补，RAMP 走第三条路——latent 未来分布不只拿来做表征学习，还要在推理时被异构消费者复用。"

## 与 RAMP 的血缘/划界

RAMP 的四支柱：(a) LLM 调度异构规划器池；(b) 世界模型单次前向、中间分布同时服务 LLM 调度先验与独立风险验证（异构复用）；(c) 风险等级连续调制衰减速率的情景记忆（高风险忘得慢；非参数测试时适应）；(d) 候选轨迹独立 rollout 风险仲裁。

LVDrive 和 RAMP 的血缘只有一处：**"一次前向，多处使用"**。LVDrive 的 1549 个预填充 token 在一次前向里同时产出未来场景表示 $V_{t+1:t+F}$ 和规划嵌入 $H_p$，再被 VAE 规划器和精化器两处消费；RAMP 创新点 B 的"世界模型单次前向复用"也是让一次前向的中间分布服务多个下游。但机制目标完全不同：

- **LVDrive 的复用是表征学习式的**：未来预测是训练时的辅助任务，目的是把更好的场景理解"烤进" LLM 的权重和 $H_p$ 里；推理时没有独立的消费者在"使用"未来分布做决策，精化器的 cross-attention 是网络内部的前向计算，不是跨模块的复用。它的世界模型只在训练时存在（as 监督信号），推理时退化成隐状态。
- **RAMP 的复用是决策式的**：世界模型的中间分布在**在线推理**时同时喂给两个异构消费者——LLM 调度器拿它当先验、独立的风险验证器拿它做仲裁。两个消费者目标不同（调度 vs 验证），这才是"异构"二字的含义。

其余三处是**空白**，不是重叠：LVDrive 没有记忆（无 (c)），没有规划器池与调度（无 (a)），没有独立风险仲裁（无 (d)；它的"精化器"在网络内部，没有独立的验证视角，更谈不上对候选轨迹的 rollout 仲裁）。LVDrive 是一个**单体 VLA**——一个模型、一次前向、一条流水线；RAMP 是一个 **agent 系统**——多个异构部件、在线决策、显式仲裁。把 LVDrive 的世界模型部分抽出来，它可以当 RAMP 支柱 (b) 里"世界模型"的一个候选实现（latent 未来预测代替像素预测），但 LVDrive 本人不解决调度、记忆、仲裁中的任何一个。

**一句话 related work 定位**：LVDrive 证明了在 VLA 内部用纯 latent 未来预测代替像素重建能提升交互式驾驶表现（Bench2Drive DS 80.71），但它止步于单体模型的表征学习——无记忆、无多规划器调度、无独立风险验证；RAMP 把"一次前向的未来分布"从训练时的辅助监督提升为在线决策时被异构消费者（调度先验 + 风险仲裁）复用的运行时资产，并补上 LVDrive 完全没有的情景记忆与仲裁机制。

## 如果我是审稿人，我会追问的七件事

1. **损失权重去哪了。** $L = L_{vis} + L_{plan} + L_{plan\_r} + L_{qt} + L_{ce}$，五项直接相加，隐含权重全是 1；$L_{vis} = w_c L_{cosine} + w_r L_{reg}$ 里 $w_c, w_r$ 全文未给。$L_{cosine}$（0~2 范围）和 $L_{mse}$ 的量级差着数量级，实际主导梯度的是哪一项？表 3 里"Mvis 引入冲突优化信号"的故事，如果是因为权重没调好，整个叙事都要重写。没有敏感性分析，这是论文最大的可复现性缺口——而官方代码又不存在。
2. **基线数字是重跑的还是引用的。** 表 1 囊括 17 个方法，作者不可能全重跑（32×H20 跑 6 epoch 的成本摆着）。表注没写哪些是重跑、哪些是引用，设置是否对齐（base split、评估路线版本）无从验证。Bench2Drive 官方仓库的评估脚本版本迭代过，不同版本 DS 口径有细微差别。
3. **Dev10 的统计效力。** 所有消融在 10 条路线上，SR 以 1/10 为粒度。Mvis→Mone 的"进一步变差"、M1 的"轻微提升"都在噪声带里。只有 LVDrive 的 +17 DS 大跳变是可信的。
4. **"显著超过"的统计学底气。** 和 UniDrive-WM 差 1.49 DS 点，无多次运行标准差。"Significantly"这个词在摘要里出现了，证据只支持"领先"，不支持"显著"。
5. **Comfortness 垫底无人讨论。** 14.34 全表最低，摘要和结论零提及。DS 不计舒适性，所以指标看不见代价，但部署时这是硬伤。
6. **训练-推理不对称的分布生成器。** 训练时 $DIS_\theta$ 看 $[H_p; \tau_{gt}]$，推理时只看 $H_p$，KL 项又被删了——后验和先验之间没有约束。这是 CVAE 文献里已知危险的设计，论文没讨论、没消融。
7. **前视假设的边界。** "人类主要看前方"在高速公路跟车时成立，在环岛、Give Way、倒车时不成立。作者诚实地报告了 Give Way 的失败，但没有回答：这个假设的天花板在哪里？如果把后视未来也加进去，token 数和延迟怎么 trade off？

## 带走的两个想法

第一个是**可迁移的**："辅助任务的目标和主任务的需求之间存在张力"——LVDrive 用 $H$ 不用 $V$ 做精化器的 K/V，就是不把辅助任务的输出当真理。下次你设计多任务学习时，问一句：辅助头输出的东西，主任务真的应该直接吃吗？还是应该吃产生它的中间表示？

第二个是**留给 RAMP 的**：LVDrive 把"预测未来"做到了单次前向、latent 空间、纯语义监督，证明了这条路在交互评估上走得通。但它也暴露了单体 VLA 的天花板——未来信息只在前向计算里流淌了一遍，没有被任何独立的机制**检查**。精化器 refine 了一次轨迹，但没有东西问"这条精化后的轨迹会不会撞"。RAMP 的支柱 (d)（独立 rollout 风险仲裁）正好补在这个位置上：LVDrive 告诉我们未来表示可以学得很好，RAMP 要回答的是**学好的未来表示如何在运行时被不信任地使用**。
