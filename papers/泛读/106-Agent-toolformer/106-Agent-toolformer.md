## 它要解决的悖论

引言第一段摆出的悖论:大模型能写诗、能做常识推理,却算不对 400/1400,也记不住"新英格兰医学杂志的出版商是谁"。前者靠 scale(规模,堆参数)解决,后者 scale 越大越会一本正经地胡说。2023 年 2 月的现状是:想让模型用工具,要么花大钱让人标"这里该调计算器"(WebGPT、LaMDA 的路线),要么只在特定任务上写死工具(PALM 式)。

Toolformer 的 desiterata(设计愿望清单,§1)有两条,都很硬:(1)**自监督**,不要人标,连"人类觉得有用"都不要——因为人类觉得有用的,模型不一定觉得有用;(2)**通用性**,模型自己决定何时、何地、用哪个工具,而不是每个任务配一个 prompt。这两条决定了它不能走 prompt 路线,必须**把工具使用写进权重**——微调。

## 三步管线:采样→执行→过滤,过滤是灵魂

给定一个工具(比如计算器),管线三步(§2,图 2):

**第一步,采样候选。** 给每个 API 写一个 few-shot prompt(图 3:两三个"输入→带 API 调用的输出"例子),让 GPT-J(6.7B)在 CCNet 语料上"随手标注"。具体做法:对文本 x 的每个位置 i,算模型在 prompt 后输出起始 token `[` 的概率 p_i,超过阈值 τ_s 的位置保留 top-k;在每个保留位置采样 m 个 API 调用。注意:**这一步的模型还不会用工具**,它只是在模仿例子格式瞎写——写出来的调用可能是错的、没用的,没关系,后面过滤。

**第二步,执行。** 真的去调 API,拿到文本结果 r_i。计算器就是算,QA 工具是 Atlas(一个在 Natural Questions 上微调过的检索增强模型),WikiSearch 是 BM25,翻译是 NLLB-600M,日历直接返回今天日期。

**第三步,过滤——整篇论文最漂亮的一步。** 对位置 i 的调用 c_i 和结果 r_i,定义加权交叉熵:

$$L_i(z) = -\sum_{j=i}^{n} w_j \log p_M(x_j \mid z; x_{1:j-1})$$

其中 z 是前缀,w_j 是权重(论文用线性衰减 w̃_t = max(0, 1-0.2t),**只看调用之后不远的 token**——因为工具结果的作用是局部的,离太远的词不该算它的功劳)。比较两个量:

- $L_i^+ = L_i(e(c_i, r_i))$:给了**调用+结果**时的 loss;
- $L_i^- = \min(L_i(\epsilon), L_i(e(c_i, \epsilon)))$:没调用,或调用了但**没给结果**时,取较好的那个。

保留条件:$L_i^- - L_i^+ \geq \tau_f$,即"知道结果比不知道,至少让 loss 降 τ_f"。

这个设计的精妙在 $L_i^-$ 的第二项:**调用了但没给结果**。它排除了两种自欺欺人:(a)模型本来就会猜后面的词,调用只是凑热闹——此时 $L_i(\epsilon)$ 已经很低,降不动;(b)调用的**问题本身**泄露了信息(比如问题里复述了答案),而不是结果有用——此时 $L_i(e(c_i,\epsilon))$ 低,但 $L_i^+$ 不会更低。大白话:**只有"结果本身带来了新信息",才算这个电话没白打**。这是自监督信号的全部,没有一个人标过"这里该用计算器"。

最后把剩下的调用织回原文(`x_1..x_{i-1} [Tool(args) -> result] x_i..x_n`),在增广语料上标准语言模型目标微调。API 的起止标记直接复用普通 token `[`、`]`、`->`,**不改词表**(§2 脚注 1)——这是个工程上的聪明决定:词表一改,预训练权重就对不上了。

推理时(§2 末):正常解码,直到模型吐出 `->`(表示"我在等工具结果"),**打断解码**、调 API、把结果和 `]` 塞回去、继续解码。这个"生成-暂停-执行-恢复"的循环,就是后来所有 function calling API(OpenAI 的 tools 参数、Anthropic 的 tool use、MCP)的标准形状——**Toolformer 在 2023 年 2 月就把这个协议定下来了**。

## 数字:6.7B 打赢 175B,但只在部分赛道

基线:GPT-J(6.7B,不微调)、GPT-J+CC(在无 API 的 CCNet 子集上微调,控制"多看语料"的增益)、OPT-66B、GPT-3-175B。评估全是零-shot。

| 任务 | Toolformer | GPT-3 175B | 工具使用率 |
|---|---|---|---|
| LAMA SQuAD / Google-RE / T-REx | 33.8 / 11.5 / **53.5** | 26.8 / 7.0 / 39.8 | QA 工具 98.1% |
| 数学 ASDiv / SVAMP / MAWPS | **40.4** / **29.4** / **44.0** | 14.0 / 10.0 / 19.8 | 计算器 97.9% |
| 问答 WebQS / NQ / TriviaQA | 26.3 / 17.7 / 48.8 | **29.0** / **22.6** / **65.9** | WikiSearch 99.3% |
| 时间 DATESET / TEMPLAMA | **27.3** / 16.3 | 0.8 / 15.5 | 日历 54.8% / 0.2% |

(表 3~7。LAMA 上禁用 WikiSearch 防不公平;QA 上禁用 QA 工具,因为 Atlas 就是在 NQ 上训的,用了等于开卷。)

三个关键观察:

1. **LAMA 和数学是碾压局**:6.7B 的 Toolformer 把 175B 的 GPT-3 按在地上,数学上甚至翻倍。这是"工具替代参数"最干净的证据:算术不需要记在权重里,需要时调计算器就行。
2. **开放问答输了**:WebQS 26.3 vs 29.0,TriviaQA 48.8 vs 65.9。论文归因于 BM25 太弱 + **不能交互**(不能改写 query、不能翻多页结果)。这是一个诚实的边界:工具的质量决定天花板,自监督只能解决"用不用",不能解决"工具行不行"。
3. **Toolformer(disabled)也变强了**:禁用 API 时,LAMA 从 19.2 涨到 22.1、数学从 9.6 涨到 14.8。论文的解释是"微调语料里见过大量调用和结果,模型自己也变聪明了"——相当于把工具的知识蒸馏进了一点权重。这是个意外的 bonus,但也说明**部分增益来自"多看了带答案的语料",不全是"学会了用工具"**。

语言模型能力(表 8):WikiText 困惑度 10.3 vs 10.3,CCNet 10.5 vs 10.5——**加工具没掉通用能力**,desideratum 第二条达成。

Scaling(图 4,§4.4):在 GPT-2 系列(124M~1.6B)上复现管线,发现**工具使用能力在约 775M 参数处涌现**,更小的模型用了等于没用。这是 CoT 式"能力涌现"在工具使用上的对应物。

## 怀疑式审读:自监督的糖衣之下

**1. 推理时最多调一次 API,且训练数据里没有链式调用。** §7 limitations 第一句就是承认:不能把一个工具的输出当另一个的输入(比如先查日历再拿日期去问 QA),因为各工具的调用是独立采样的,训练数据里没有链式例子。**这意味着 Toolformer 学到的只是"单步求助",不是"多步规划"**。论文标题说"Use Tools",实际是"use one tool once"。k=10 解码时"每个输入最多一次 API 调用"的硬限制(§4.2)进一步坐实:这是一个被刻意简化的设置。

**2. k=10 的解码 hack 稀释了"自主决定"的故事。** 推理时不是等 `<API>` 成为最可能 token 才调,而是只要它进 top-10 就调。表 9:T-REx 上 k=1(真贪心)时调用率 40.3%,k=10 时 98.1%;WebQS 上 k=1 时 8.5%,k=10 时 100%。**论文 headline 的数字全是在 k=10 下测的**——等于把模型"推"去用工具。更有意思的是表 9 的 calibration 分析:k=1 时模型有校准性(它选择调用的那些例子,恰恰是不调用会做得很烂的);k=10 时校准性消失。论文诚实地报告了这一点,但读者要明白:"自主决定何时用工具"的漂亮故事,在 k=1 时成立,在 k=10(实际报告数字的设置)时是被人工助推的。

**3. 日历工具的成绩单是拼凑的。** TEMPLAMA 上日历只用了 0.2%,增益来自 QA/搜索工具;DATESET 上 54.8% 用日历,大涨。两个数据集拼出"时间工具"这一行,但**没有一个数据集同时需要"先查日期再推理"**——而这恰恰是时间感知的真实形态。§5 自己承认:先查日历再问 QA 的链式用法被"最多一次调用"禁掉了,也学不出来。

**4. MLQA 上没稳定超过 GPT-J 原版。** 因为 CCNet 微调带来了分布偏移,部分语言掉了。工具增益被微调损伤抵消。这是"无代价" claim 的裂缝:自监督管线要求在特定语料上微调,而微调本身就可能伤及原有能力(多语言首当其冲)。

**5. 过滤标准有已知的假阳性,论文把它合理化了。** 表 10:"Fast train success"这个 WikiSearch 调用,过滤分数 0.92(不低),但返回的乐队八卦跟上下文毫无关系——它降低困惑度只是因为"多了一段流畅英文"。论文说"少量噪声反而有用,逼模型不盲从工具结果"。这话有一定道理(正则化),但也暴露了**困惑度差不是"有用"的完美代理**:它奖励"让文本更可预测",不奖励"让答案更正确"。在 QA 任务上这可能问题不大,在需要精确推理的场景里就是隐患。

**6. "自监督"的边界:工具本身的知识是监督来的。** QA 工具 Atlas 是在 Natural Questions 上**监督微调**过的;LAMA 的增益里,有一部分是把 Atlas 的监督知识蒸馏给了 GPT-J。论文的"自监督"指的是"何时用工具"的决策信号,不是工具的知识来源。这个区分论文没有点破,但引用时要清楚:Toolformer 没有凭空变出知识,它只是学会了**向一个有知识的工具求助**。

**7. 阈值 τ_s、τ_f 是按工具单独调的,目标是"凑够数据量"**(附录 A:"chosen to ensure a sufficiently large number of examples")。这不是原则性选择,是工程凑数。结合第 6 点,整个管线的"自监督"光环要打折扣:采样靠 few-shot 例子(人写的)、阈值靠人调、工具靠监督模型——**人真正省掉的,只有"每个位置标该不该调用"这一件事**。但这恰恰是最贵的那件事,所以论文的贡献依然成立,只是不要把它理解成"零人工"。

## Lineage:从 prompt 技巧到权重行为的分水岭

Toolformer 之前,工具使用是 **prompt 层**的事(ReAct 用 prompt 交错思考和行动,但"调什么工具"是 prompt 写死的)。Toolformer 之后,工具使用是**权重层**的事:模型自己决定调不调用。它的直接后代是 OpenAI 的 function calling(2023-06,GPT-3.5/4 微调出结构化调用,协议形状与 Toolformer 的 `[API(...) -> result]` 同构)、Gorilla、ToolLLM/ToolBench(把工具从 5 个扩到 16k 个)。

它的历史地位:第一个证明"**工具使用可以不靠人工标注学会**"的工作,哪怕这个"学会"有上述诸多限定。它的方法论遗产是那套过滤准则——"有没有帮到你,就看后续 token 好不好猜"——这是一个**可迁移的自监督信号设计**,不只适用于工具调用,任何"要不要引入外部信息"的决策(检索增强、记忆读取)都能套用。

## 与 RAMP 的血缘/划界

Toolformer 与 RAMP 的关系:**"调用外部能力"的决策机制有血缘;但 RAMP 调的是规划器,不是计算器**。

- **对"LLM 在线多规划器调度"模块:决策逻辑可借鉴,对象完全不同。** Toolformer 的"何时调工具"是一个二元/多选决策,靠微调进权重;RAMP 的"选哪个规划器"是每帧的在线仲裁,靠 prompt/显式打分。两者共享一个抽象问题:**"我自己搞不定,要不要把控制权交给外部模块"**。Toolformer 的回答是"离线学会、在线凭直觉";RAMP 的回答必须是在线的,因为驾驶的"搞不定"是状态依赖的(上一秒能搞定,下一秒对向来车就搞不定了)。划界:Toolformer 是**开环、离线学**的工具选择;RAMP 是**闭环、在线**的规划器调度。但 Toolformer 的过滤思想可以迁移:调度器选规划器的训练信号,可以借鉴"选了这个规划器,后续风险有没有降"的自监督准则——这是 related work 里可以写的一句方法论呼应。
- **对"世界模型中间分布复用"模块:正交,且互为镜像。** Toolformer 是"向外求助"(调外部 API 拿事实);RAMP 的世界模型是"向内求助"(调内部预测拿未来)。有趣的是,Toolformer 的 API 调用格式 `[Tool(args) -> result]` 和 RAMP"一次前向同时出调度先验和风险分布"的设计,在抽象层面都是"一次调用、多种用途"。但 Toolformer 的工具是**事实性**的(计算器、搜索),RAMP 的世界模型是**预测性**的(未来轨迹分布)——前者解决"不知道",后者解决"不确定"。
- **对"情景记忆"与"安全盾"模块:无直接关系。** Toolformer 没有记忆(调用历史不沉淀)、没有安全(调错工具只是答案变差)。它的局限清单(§7:无链式、无交互、不考虑调用成本)恰恰是 RAMP 这类 agent 系统必须回答的问题:驾驶里每一次"调用"(选规划器、查记忆)都有时延成本,Toolformer 明确说自己"不考虑工具的计算成本"(§7 末),而 RAMP 的时延优化(中间分布复用、分层检索、动态旁路)正是对这一缺失的回答。

一句话:Toolformer 是"**让模型学会求助**"的开山工作;RAMP 的调度器面临的是同一个"求助决策",但求助对象从计算器变成了异构规划器,决策从离线直觉变成了在线风险感知的仲裁。引用时把它放在"tool use / function calling"的源头,划界词是"offline tool selection vs online planner arbitration"。
