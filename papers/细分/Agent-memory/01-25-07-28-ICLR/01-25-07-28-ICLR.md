## 2. 作者到底在解决哪个具体卡点

### 2.1 前人撞墙的两个场景

作者的起点是一个观察：此前所有 VLM 驾驶规划工作（DriveLM、DriveVLM、Reason2Drive 等）都跑在**被动感知**上——输入是固定的几张图，推理是纯文本 CoT。这在两类场景下会出问题：

1. **缺信息**：默认前视图分辨率不够时，远处的红绿灯、小目标在视觉编码器的下采样里直接丢失，文本 CoT 再怎么"仔细看"也看不见。附录 A.13 把这一点讲得很直白：instruction-guided attention（用文字提示"注意中间的红绿灯"）只能在已压缩的特征上重排注意力，丢掉的高频细节找不回来；实测只比 baseline 高 1.45 个点（46.72 vs 45.27），而 RoI 放大能高 3.54 个点（48.81）。
2. **信息冗余**：把六个视角全塞进去，模型要处理大量无关像素，算力浪费不说，注意力还会被带偏。表 7 的被动基线显示：Passive-SV（环视）只比 Passive-FV（仅前视）高 0.4 个点（43.10 vs 42.70），多花的算力几乎没换来信息。

人类司机的做法是：简单路况凭直觉开，复杂路况才"再看一眼"（查盲区、确认信号灯）。作者把这句话翻译成两个机制：**active perception**（需要时主动调工具取证据）+ **hybrid thinking**（按场景复杂度切换推理深度）。这是推断，但引言第 2 页的论述顺序（先讲人的主动感知，再讲人的认知效率）支持这个还原。

### 2.2 作者手里的底牌

三个底牌，证据都在正文里：

- **底牌一：自有长尾数据**。Drive-Internal 数据集，35K 个视频片段、40+ 种驾驶场景，专门收 road works、animal crossing 这类长尾。这让"工具在长尾场景有用"这个故事有地方落地，也解释了为什么 DriveAgent-R1 在 Drive-Internal 上的工具增益（+6.07）远大于在 nuScenes 上的（+0.38）：nuScenes 相对"干净"。
- **底牌二：LiAuto 的工程链路**。附录 A.2 的四个工具（Retrieve View 历史帧池、RoI 放大、Depth Anything V2、开放词表单目 3D 检测）都是可落地的现成模块，不是 paper-only 的玩具。
- **底牌三：RL 训练 VLM 的经验**。团队此前有 Drive-R1（Li et al., 2025c）的工作，知道 VLM 在驾驶规划里有"走文本捷径、忽视图像"的毛病（Li et al., 2025c; Chen et al., 2025），所以先做了一轮 530K VQA 的 domain alignment（DriveAlign-3B），再谈规划。

### 2.3 方法是怎么一步步长出来的（推断）

按论文结构倒推，作者的路线大概是这样走的（标注意图的部分为推断）：

1. **先试"无脑加工具"**：给 VLM 接上视觉工具箱，让它在推理中途调工具。结果发现两个麻烦——小模型（Qwen2.5-VL-3B/7B）给了工具反而掉点（表 1：3B 在 Drive-Internal 上 −0.42，7B 掉 −3.57），说明"会用工具"本身是需要学的能力；而且所有场景都调工具太贵。
2. **于是加"模式开关"**：简单场景走纯文本，复杂场景才调工具。这就是 hybrid thinking 的由来——不是一开始的顶层设计，更像是对"工具滥用"的修正（推断；附录 Fig.15 的 forced-tool 在简单场景下被无关工具调用带偏、输出危险 "Keep Speed" 的案例，就是这个教训的直接证据）。
3. **训练分三段**：SFT 冷启动教会格式 → FCM-RL 把两个模式各自练强（防止模型偏废一开始较弱的 tool 模式）→ AMS-RL 学"何时切换"。MP-GRPO 和 Rtool 都是为这个"先分开练、再学选择"的路线服务的。
4. **最后补证据链**：domain alignment 消融（表 5：去图后掉点 −15.8% vs −11.0%，证明决策真的依赖图像）、主动 vs 被动消融（表 7）、延迟对比（表 8），每一张表都在回答一个预设的质疑。

## 3. 关键设计：哪些是承重墙，哪些是装修

承重结构有三根：**问题形式化（meta-action 序列）→ 主动感知（工具箱 + 交错推理）→ 混合思考（三阶段训练）**。其余如 DriveBench 评测、MLP 运动头，都是外挂的验证件。

### 3.1 输出为什么是 4 个离散 meta-action，而不是轨迹

输入：I₀（前视图）+ T₀（车速、导航指令）。输出：未来 8 秒、每 2 秒一个的 meta-action 序列 A = (a₁, a₂, a₃, a₄)，每个 a_t = (s_t, j_t)，s_t ∈ {Accelerate, Keep Speed, Decelerate, Stop}（4 种速度），j_t ∈ {Straight, Right Turn, Left Turn}（3 种朝向）。

这个选择很务实：VLM 不擅长回归连续坐标（引言明确说了这点），离散意图序列把规划问题变成"分类 + 排序"问题，VLM 的 next-token 机制天然适配。代价是粒度粗——12 种组合、2 秒一跳，精细的避障机动表达不出来。作者用外挂 MLP 把 meta-action 转成 3 秒轨迹（§3.3），等于承认：VLM 只负责"意图"，执行另请高明。

### 3.2 主动感知：四个工具各自解决什么信息缺口

Tool-based M-CoT 的推理是一个多轮循环：历史 H₀ = T₀ ⊕ I₀；每一步 k，LM 解码器从 H_{k−1} 生成文本思考 T_k 和可能的工具调用 𝓣_k；工具执行后结果编码成图像 embedding I_k 并拼回历史：H_k = H_{k−1} ⊕ T_k ⊕ I_k；直到输出动作序列或达到上限 K（实现细节：最多 3 次工具调用）。

四个工具的分工（附录 A.2）：

1. **Retrieve View**：取任意视角的清晰图，附带**历史记忆池**——过去 5 秒、1Hz 采样的所有视角图像缓存。解决"刚才灯是什么颜色""那辆车在动吗"这类时序问题，又不用喂整段视频。这是全文唯一带"memory"字样的模块，但注意：它是一个 5 秒 FIFO 图像环形缓存，**不是**跨场景的经验记忆。
2. **RoI Inspection**：在**高分辨率原图**上按绝对像素 bbox 裁剪放大。附录 A.13 点出它的本质是"分辨率放大器"：绕过视觉编码器的下采样瓶颈，把丢失的高频细节重新编码进来。这是四个工具里信息增益最大的一个（表 11：RoI 单工具 +3.54 first-frame）。
3. **Depth Estimation**：调 Depth Anything V2 生成指定视角的深度图，给单目 VLM 补 3D 空间感。
4. **3D Object Detection**：开放词表单目 3D 检测（Zhang et al., 2025），可按需指定检测目标（如 "barrier"），输出位置/尺寸/朝向。

一个值得留意的实现细节：公式里 I_k = VisionEncoder(Execute(𝓣_k)) 把工具输出统一写成"图像编码"，但 3D 检测的输出本质是文字列表（目标名+3D 框参数）。附录没有说明这类结构化文本输出是如何进入 token 流的（是直接拼文本，还是转成某种 embedding）。这是论文语焉不详的一处，见第 6 节。

### 3.3 混合思考：一个 token 的分岔口

两种模式共享同一套 description→reasoning→prediction 的 CoT 骨架，区别只在入口 token：

- `<think_text>`（M_text）：纯文本推理，只用初始输入 (I₀, T₀)。
- `<think_tool>`（M_tool）：进入上面的多轮工具交错循环。

模式选择本身就是一次生成：解码器先吐出 mode token，再沿对应路径走到底。附录 A.12 的 Fig.17/18 展示了 streaming 推理中**跨帧切换**：t−4 时刻路况简单用文本模式，接近路口发现卡车风险后切到工具模式做 RoI 确认；风险过去后又切回文本模式省算力。模式不是一锤定音的全局开关，而是每帧独立决策。

### 3.4 三阶段训练：为什么不能一步到位

- **Stage 0（预处理）：Domain Alignment**。用 530K 驾驶 VQA（四类：场景描述、交通实体识别、关键目标定位、交通常识规则）全参数微调 Qwen2.5-VL-3B 得到 DriveAlign-3B。数据管线：100 万实拍帧 → CLIP 聚类去重 → Qwen2.5-VL-72B 生成 QA（70% 模板 + 30% 自由）→ Doubao-Seed-1.6 当裁判**满分才保留** → Doubao 重写问题增多样性。表 9：驾驶 VQA 从 72.9 涨到 84.6（+11.7），通用基准也涨了 2.0（64.4→66.4），没顾此失彼。
- **Stage 1：DM-SFT**。4K 高质量 CoT 冷启动，一半 D_text 一半 D_tool。关键在**必要性划分**：先用 3B 自己筛——M_text 下准确率 >0.9 的算简单，进 D_text；剩下的用 72B 裁判——只有开了工具才涨点的进 D_tool；模棱两可的留给后面的 RL 探索集 D_explore（15K，动作时步分布平衡）。CoT 标注是 72B"逆向"生成的：给定 ground-truth meta-action，反推一段合理的思考过程，再用 judge 模型打分（s∈[0,1]，低于阈值 τ 打回重写），最后规则清洗（格式、工具调用频次控制）。这里有个方法论上的诚实点：SFT 教的是"像会用工具的样子"，真正的"何时用"留给 RL。
- **Stage 2：FCM-RL（Mode-Partitioned GRPO）**。核心 trick：对每个输入 q，**强制**生成 G/2 个 text 响应和 G/2 个 tool 响应（实现中 G=4，即 2+2），然后把 G 个响应**混在一起做归一化**算 advantage。这样组内既有"同模式不同轨迹"的对比，又有"跨模式"的对比，弱的那个模式不会被直接放弃。奖励 R = R_acc + R_fmt：准确度奖励 + 格式奖励（后者罚"在 text 模式里调工具"这类犯规）。
- **Stage 3：AMS-RL**。放开模式限制，模型自己选 mode token，用原生 GRPO 训练。奖励多了 R_tool 一项，只对选了 M_tool 的轨迹生效：R_tool = (R_acc,i − R̄_acc^text) − N_i·C_tool。其中 R̄_acc^text 是**同组内**所有纯文本轨迹的平均准确度（组里没有文本轨迹则该项为 0），N_i 是工具调用次数，C_tool = 0.125。直觉：工具带来的准确度增益，必须超过"本来用纯文本也能拿到的分数"再减去"每次调用的固定成本"，否则就是负奖励。C_tool 的 0.125 不是调出来的：作者设定"主动感知至少要纠正 4 步序列中的 1 个 meta-action 才算值"，即 0.25 的增益，摊到中位数 2 次调用上，0.25/2 = 0.125。最后 clip 到 [−0.2, 0.2] 保稳定。

表 6 证明"分开练再学选"不是白折腾：FCM→AMS 的最终版（Madaptive 45.42，MSA 68.52）超过了"只堆 FCM 两轮"（44.91，MSA 57.32）和"只堆 AMS 两轮"（44.13，MSA 61.61）——FCM 负责把两种模式各自的执行力练高（forced 模式准确度更高），AMS 负责把选择练准（MSA 更高），功能互补。

## 4. 公式推演：符号、目的、实例

### 4.1 推理循环 H_k = H_{k−1} ⊕ T_k ⊕ I_k

- H_k：到第 k 步为止的全部上下文（token embedding 序列），形状是 [总 token 数, hidden_dim]。
- T_k：本步的文本思考（token 序列）。
- 𝓣_k：本步的工具调用请求（结构化文本，如 `{"view_index": "front", "bbox": [...]}`）。
- I_k：工具返回结果编码后的 embedding。
- ⊕：embedding 序列拼接。

物理动作翻译：这就是 ReAct 循环的多模态版——"想一步 → 发现缺证据 → 调工具 → 把新图拼进上下文 → 继续想"。上限 K=3 次调用封顶，防止无限查图。

### 4.2 GRPO 与 MP-GRPO

标准 GRPO 目标：

J_GRPO(θ) = E[ (1/G) Σᵢ ( min(wᵢAᵢ, clip(wᵢ, 1±ε)Aᵢ) − β·D_KL(π_θ‖π_ref) ) ]

- wᵢ = π_θ(oᵢ|q)/π_θ_old(oᵢ|q)：重要性采样比，新旧策略的概率比，形状是标量。
- Aᵢ：组内归一化 advantage，Aᵢ = (rᵢ − mean(r))/std(r)，G 个响应的奖励先算均值方差再标准化。**这就是 GRPO 不用 critic 的原因**：基线直接从同组采样里估计。
- clip 防止单步更新过大；β·KL 把策略拴在参考模型附近。

MP-GRPO 的改动不在公式，在**采样**：O(q) = {oᵢ^text}_{i=1}^{G/2} ∪ {oⱼ^tool}_{j=1}^{G/2}。G=4 时，每组 2 个强制文本响应 + 2 个强制工具响应，4 个一起算 mean/std。几何直觉：advantage 的零点是"这组混合样本的平均水平"，tool 轨迹要超过的不仅是别的 tool 轨迹，还有 text 轨迹——跨模式对比被硬编码进了归一化分母。

### 4.3 准确度奖励：加权 Levenshtein

R_acc = 0.7·R_speed + 0.3·R_traj，速度权重更高（安全优先）。

R_seq(Â, A) = 1 − D(Â,A)/max(m,n)，D 是加权编辑距离：删除/插入代价固定 0.6，替换代价 C_sub = 1 − S，S(â, a, t) = I(â=a)·w_{a,t}。

小实例：ground truth A = [Decelerate, Decelerate, Stop, Stop]，预测 Â = [Decelerate, Keep Speed, Stop, Stop]。只看速度分量（m=n=4）：第 2 个位置替换，S = 0（不匹配）→ C_sub = 1·w。假设 w≈1，则 D = 1，R_speed = 1 − 1/4 = 0.75。若预测全对，D=0，R=1；全错（4 次替换），D=4，R=0。删除/插入代价 0.6 < 1 的含义：长度对不上时，宁可做对齐（0.6）也不硬替换（1）——鼓励"意思对但错位"的预测拿部分分。

w_{a,t} 的三步：① 逆频率 (f̄_t/f_{c,t})^0.5，罕见动作（如 Stop、Left Turn）权重高；② clip 到 [0.7, 1.3] 防极端；③ 每时步归一化到均值 1，不改变该时步奖励总尺度。针对的是驾驶数据的长尾：绝大多数帧是 Keep Speed+Straight。

### 4.4 工具使用奖励：R_tool = (R_acc,i − R̄_acc^text) − N_i·C_tool

实例：某组 G=4，2 个 text 轨迹准确度 0.6、0.7（R̄^text = 0.65），某 tool 轨迹准确度 0.9、调了 2 次工具：R_tool = (0.9 − 0.65) − 2×0.125 = 0.25 − 0.25 = 0。刚好打平——呼应"纠正 1 个 meta-action（0.25）摊 2 次调用"的设计原点。若只调 1 次工具就拿到 0.9：R_tool = 0.25 − 0.125 = +0.125，正奖励；若调 3 次：0.25 − 0.375 = −0.125，被罚。注意正文公式里写的是 R_tool ∝ (R_acc − Acc̄_text − margin)，附录实现里 margin 一词消失、被吸收进了按次计费里——正文与附录在此处表述不完全一致（见第 6 节）。

## 5. 实验：数字、条件、解读

### 5.1 主结果（表 1）：3B 对 GPT-5 和人类

评测条件：one-shot prompting；所有模型测"无工具"和"有工具"两档；闭源模型走官方 API 的 "no-thinking" 模式；指标是 First-Frame Joint Acc（第一帧速度+轨迹同时命中）和 Seq Avg Joint Acc（4 帧平均），另有 Relaxed Speed Matching（比真值保守一档给 0.5 分、两档给 0.2 分，鼓励保守）。

Drive-Internal 测试集（1.5K，自有长尾数据）：

| 模型 | First-Frame（无→有工具） | Seq Avg（无→有工具） |
|---|---|---|
| Human | 49.59 | 49.29 |
| GPT-5 | 56.30 → 56.48 (+0.18) | 47.19 → 47.97 (+0.78) |
| DriveAgent-R1 | 45.27 → **51.34 (+6.07)** | 43.29 → **45.42 (+2.13)** |
| Qwen2.5-VL-3B | 24.06 → 23.64 (−0.42) | 24.98 → 22.63 (−2.35) |

nuScenes 测试集（2K，跨数据集）：DriveAgent-R1 52.58→52.96 (+0.38) / 44.43→47.10 (+2.67)；GPT-5 为 48.75→49.11 / 44.85→45.14——**序列准确度上 3B 模型超过了 GPT-5（47.10 vs 45.14），接近人类（48.24）**。

两个解读：① 工具增益 +6.07 是全场最大，说明"会用工具"确实是练出来的稀缺能力——3B/7B 基座裸上工具反而掉点，工具是双刃剑；② GPT-5 的工具增益只有 +0.18/+0.78，一个可能是 GPT-5 本来就强（天花板），另一个可能是 prompt 和工具箱是按自家模型调的，存在"主场优势"（见第 6 节）。

### 5.2 消融：每个 claim 都有一张表

- **Domain alignment 真的管用吗（表 4/5）**：DriveAlign-VQA 84.6（+11.7 over 3B 基座），通用基准 66.4（+2.0）——没牺牲通用能力。关键证据是"去图测试"：拿掉图像输入，DriveAgent-R1 掉 15.8%，而基于未对齐基座的变体只掉 11.0%——掉得越多，说明决策越依赖图像而非文本捷径。这是对"visual neglect"指控的直接回应。
- **主动 vs 被动（表 7）**：只允许用 Retrieve View 的受限版（44.39）同时超过 Passive-FV（42.70，+1.69）和 Passive-SV（43.10，+1.29）。后者信息上限完全相同（同一个 6 视角池子），+1.29 说明"按需取"胜过"全量灌"——冗余输入确实干扰注意力。
- **效率（表 8）**：单 H20、batch=1、vLLM、100 样本×5 次平均。Passive-SV 8.50s → M_tool 7.91s → M_adaptive 6.74s；token 数 210.77 → 314.45 → 265.57。自适应模式比纯工具模式省约 15% 延迟。注意绝对值：**6.74 秒一帧离车载实时还差两个数量级**，"deployment-friendly"是相对被动多视角和 72B 而言的。
- **DriveBench（表 2）**：Perception 34.07（DriveLM 16.85 的两倍）、Behavior 43.69 第一——主动感知拿到的细节确实转化成了决策分。但 Prediction 32.85 低于 DriveLM 的 44.33，作者没解释这一项。
- **运动规划外挂（表 3）**：冻结 DriveAgent-R1 + 轻量 MLP（输入：meta-action one-hot、视觉 token、ego 状态），nuScenes 开环 ADE 平均 0.28m（0.13/0.24/0.47），优于 DriveVLM-Dual 的 0.31m；碰撞率平均 0.14%。证明高层意图能落地到轨迹，但这是开环评测，不是闭环仿真。

### 5.3 定性案例： hybrid thinking 的高光与翻车

- Fig.14（复杂路口）：text 模式漏掉远处白车（0/100），forced-tool 漫无目的调了个 front-left 视角也没看对地方（25/100），自适应模式主动 RoI 放大路口区域发现来车、减速右转避让（100/100）。**"有工具"不如"知道为什么调工具"**——这是全文最有说服力的一张图。
- Fig.15（简单场景）：forced-tool 被一个无关的交通标志检测带偏，输出危险的 "Keep Speed"（25/100）；自适应切回 text 模式正确减速（100/100）。"工具滥用"的反例。
- Fig.16（失败案例，附录 A.11）：夜间路口，模型一开始正确识别绿灯，调了 front-right 视角后误把**行人红灯**当成自己的灯，改成不必要的 Stop。作者承认这是"对新视觉证据的过度依赖"——工具拿回来的信息，模型缺乏质疑和仲裁机制。这是第 6 节要展开的真问题。

## 6. 怀疑式审读

**1. 核心评测集是私有的。** Drive-Internal（35K clips，测试 1.5K）的构建管线只在附录 A.3.2 用三段话交代（CLIP 长尾检索 + 人工检查 + 按机动方差抽难例），无公开访问。全文最亮眼的数字（+6.07 工具增益、超 GPT-5 序列准确度的一半功劳）都落在它上面。nuScenes 上的增益小得多（+0.38/+2.67），让人怀疑主结果有多少是"自家数据自家标"的红利。标签管线本身（3 秒滑动窗 + 0.5m/s、0.3m/s²、15° 阈值 + GPT-4.1 精修）是作者定的，模型学的分布和标签的偏置同源——Human 基线 49.59 first-frame 说明这任务本身噪声就不小。

**2. 基线对比有"主场"嫌疑。** 闭源模型用 one-shot + "no-thinking" 模式调 API，工具箱的 prompt 和调用格式显然是按自家训练流程打磨的。GPT-5 的工具增益只有 +0.18，很难区分是"GPT-5 不需要工具"还是"GPT-5 没被教会用这套工具"。公平的对比应该给每个基线同等的工具使用示例或微调，但这在闭源 API 上做不到——作者在附录 A.8 交代了评测细节，但这个结构性不对称依然存在。

**3. "部署友好"的绝对值站不住。** 6.74 秒/帧（batch=1，H20，vLLM）即使相对 Passive-SV 省了 20%，离 10Hz 级车载实时还差 60 倍以上。论文摘要说 "deployment-friendly"，正文 §3.7 只谈相对延迟。诚实的表述应该是"比被动多视角便宜"，而不是"可部署"。

**4. 工具输出的编码方式没交代。** 公式 I_k = VisionEncoder(Execute(𝓣_k)) 暗示所有工具返回都被当图像编码，但 3D 检测返回的是文字列表（目标名 + 3D 框）。附录 A.2 给了四个工具的调用格式，唯独没说返回结果如何序列化进 token 流。是拼英文描述？还是转 embedding？这个缺口让 tool-based 推理的数据流无法完整复现。

**5. 正文与附录的 R_tool 表述不一致。** 正文 §2.3.3 写 R_tool ∝ (R_acc − Acc̄_text − margin)，附录 A.5 的实现公式是 R_tool = (R_acc,i − R̄_acc^text) − N_i·C_tool，margin 一词在实现中消失（被按次计费吸收）。差别不大，但做复现的人会困惑 margin 到底取多少。

**6. 数据闭环：Doubao-Seed-1.6 身兼三职。** 它既是 DriveAlign-VQA 的裁判（满分才保留）、又是问题重写器、最后还作为表 1 的对比基线。裁判选出的数据天然偏向裁判自己的判断标准，而基线对比里 Doubao 的工具增益（+4.06 first-frame）是全场第二——这里面有多少是"数据按它的口味筛过"的成分，无法排除。

**7. 必要性划分的循环定义。** D_tool 的定义是"72B 只有开工具才涨点的样本"。工具的"必要性"于是依赖于 72B 用工具的能力——如果 72B 本来就不会用好某类工具，这类样本会被划进"不需要工具"，SFT 阶段就永远学不到。这是个自举（bootstrap）偏差，作者把模糊样本丢给 D_explore 做 RL 探索，部分对冲了这个问题，但没有量化对冲效果。

**8. MSA 指标是自参照的。** Mode Selection Accuracy 的"最优模式" m*_i 定义为"事后看哪个模式准确率高"。模型在训练中见过 D_explore 上的模式对比信号，评测时 m* 又是用同一套模式算出来的——选择器和被选择对象来自同一分布，MSA 68.52 的绝对值意义有限，横向对比（FCM→AMS vs 单堆）的相对意义更大。

**9. 超参数多为启发式。** C_tool=0.125 的"最小有效增益"推导、Levenshtein 删除/插入代价 0.6、逆频率指数 γ=0.5、clip [0.7,1.3]、温度 1.0/0.7——全是设定值，无敏感性分析。C_tool 的推导尤其脆弱："纠正 1 个 meta-action = 0.25 增益"假设了 4 步等权，但 R_acc 里明明有位置-动作权重 w_{a,t}，两者没对齐。

**10. 失败案例指向真短板，且没有机制解。** Fig.16 的行人灯误判暴露：工具返回的新证据**没有可信度加权和冲突仲裁**——后来者居上，直接覆盖了正确的初始判断。作者在结论里把修复推给"未来工作"（加强路口拓扑理解 + 对抗训练）。一个每帧独立决策、证据只增不减的架构，天然缺少"质疑新证据"的回路。

## 7. 与 RAMP 的血缘 / 划界

RAMP 的三块：(A) 风险加权自适应衰减情景记忆——高风险经历衰减慢、低风险衰减快，非参数检索；(B) Single-Pass World-Model Reuse——每周期一次前向编码共享初始潜状态，多规划器候选轨迹做 action-conditioned rollout；(C) LLM/SLM 调度多个独立规划器、每个输出多条候选轨迹、风险仲裁选优。按记忆 / 调度 / 世界模型 / 闭环校验四轴对照如下。

### 7.1 记忆机制：划界为主，正交可叠加

DriveAgent-R1 唯一的"记忆"是 Retrieve View 的**历史记忆池**：过去 5 秒、1Hz 的环形图像缓存。这是**感知层的短期 FIFO**，不是经验层的东西：没有跨场景、没有检索打分、没有衰减、更没有风险加权。它和 RAMP 的情景记忆（长期、非参数、按风险调衰减速度）在**时间尺度**（5 秒 vs 全历史）、**内容**（像素帧 vs 风险标注的经历片段）、**机制**（先进先出 vs 风险加权保留）三层上都不重叠——**划界**。

血缘只有一层薄的：两者共享"按需取回而非全量灌入"的信息经济学。DriveAgent-R1 用它论证了"主动取"胜过"被动全量"（表 7 的 +1.29），这个证据可以借来支撑 RAMP 记忆检索的设计动机。

正交叠加的具体接口：RAMP 的情景记忆库可以直接做成 DriveAgent-R1 工具箱的**第五个工具**（Retrieve Experience）——输入当前场景 embedding，返回历史高风险相似片段的描述，拼进 H_k 参与推理。DriveAgent-R1 的三阶段训练管线（特别是 R_tool 的"增益−成本"计费思想）可以直接用来训练"何时查记忆"：把 C_tool 换成记忆检索的延迟代价，把 R̄_acc^text 换成"无记忆基线"，AMS-RL 的框架几乎不用改。

### 7.2 规划器调度：表面相似，实则划界；但选择器的训练方法可借

这是最容易混淆的一轴。DriveAgent-R1 的"混合思考"听起来像调度，但它调度的**不是规划器，而是单个 VLM 的推理深度**（纯文本 vs 工具增强）。输出永远是一个 4 元 meta-action 序列，不存在"多个独立规划器各出多条候选"的结构。RAMP 的调度发生在**规划器之间**（异构规划器 + 风险仲裁），DriveAgent-R1 的选择发生在**推理模式之间**——粒度差了一整层。**划界**。

可借用的血缘在训练方法：AMS-RL + R_tool 解决的是"何时调用昂贵模块"的通用问题，RAMP 的调度器面临一模一样的问题（何时切保守规划器、何时触发重规划）。R_tool 的设计模式——**同组内相对基线的增益 − 调用次数×单次成本**——可以直接移植为调度器的奖励：把"工具调用"换成"规划器切换/重算"，把组内文本基线换成"默认规划器基线"。MP-GRPO 的强制分组思想对 RAMP 也有用：如果某个规划器初期弱，调度器会直接弃用它；强制每个规划器在训练组里占固定份额、统一归一化，能防止这种"赢者通吃"的早熟收敛。

### 7.3 世界模型使用：完全缺席，划界

DriveAgent-R1 **没有任何未来预测**：四个工具全是当前帧/历史帧的感知增强（Depth Estimation 给的是单帧几何，不是时序 rollout）。它的"预测"只是 CoT 里的文字小节名，输出的是意图序列而非状态序列。RAMP 的 Single-Pass World-Model Reuse（共享潜状态 + action-conditioned 多轨迹 rollout）在 DriveAgent-R1 里没有对应物——**干净划界**。

反过来想：DriveAgent-R1 恰好证明了"无世界模型也能把高层决策做好"，它的价值在于把**感知证据**这一环做扎实。RAMP 如果要引用它，位置是 related work 的"agentic 感知"段落，而不是世界模型段落。一个自然的叠加方向：把 RAMP 的世界模型 rollout 做成 DriveAgent-R1 的工具（"预测未来 3 秒 BEV"），让 VLM 在 tool 模式里能"看"未来——这正是 DriveAgent-R1 架构原生支持、只是没人放进去的东西。

### 7.4 闭环校验：两边都没有，但缺的不是同一种东西

DriveAgent-R1 的评测是开环的：meta-action 准确度、DriveBench 打分、nuScenes ADE 全是离线比对，没有闭环仿真介入。唯一的"校验"是 R_fmt 格式惩罚和事后人类打分。RAMP 的闭环风险校验（多候选轨迹的风险仲裁、执行后反馈回记忆衰减）在这里不存在——**划界**。

但两边的"校验观"有个值得玩味的差异：DriveAgent-R1 的全部努力方向是**感知证据的可信度**（"决策有没有看对东西"），RAMP 的校验方向是**决策后果的风险**（"选了这条轨迹会发生什么"）。Fig.16 的失败案例恰好卡在两者之间：模型看错了灯（感知错），但没有任何后果推演去拦截这个错误（"如果真是红灯，直行会怎样"本可以触发二次确认）。这提示 RAMP 的 related work 可以这样写：DriveAgent-R1 把"证据 grounding"做到了工具级主动，但缺少后果级校验——这正是风险仲裁要补的洞。两者是**互补的正交关系**，不是竞争关系。

### 四轴小结

| 轴 | 关系 | 一句话 |
|---|---|---|
| 记忆机制 | 划界为主、正交可叠加 | 5 秒 FIFO 像素缓存 vs 风险加权长期情景记忆；可加为第五个工具 |
| 规划器调度 | 表面相似实则划界、方法可借 | 调的是推理深度不是规划器；但 R_tool 的"增益−成本"奖励和 MP-GRPO 强制分组可直接移植给调度器训练 |
| 世界模型 | 干净划界 | 无未来预测；RAMP 的 world model 可做成它的新工具 |
| 闭环校验 | 都没有、互补正交 | 它校验"看没看对"，RAMP 校验"选得对不对"；Fig.16 的翻车正是缺后者的代价 |

## 8. 一句话总结 + 关联阅读

**一句话**：DriveAgent-R1 把"开车时该想多深、该看多细"变成了一个可学习的开关——3B 小模型靠这个开关在序列决策上摸到了 GPT-5 的水平；但它所有的聪明都发生在"看清当下"这一层，对"未来会怎样"和"选错了会怎样"只字未提，而这恰恰是任何想上路的系统绕不开的两道题。

**关联阅读**：
- Drive-R1（Li et al., 2025c）：同一团队的前作，RL + VLM 驾驶规划的起点；DriveAgent-R1 的 domain alignment 动因（visual neglect）出自这里。
- AgentThink（Qian et al., 2025, arXiv:2505.15298）：同期另一条"工具增强 CoT 驾驶"路线，对比着看能分清两家在工具设计上的取舍。
- DeepEyes（Zheng et al., 2025, arXiv:2505.14362）：用 RL 激励"带着图像思考"的通用 VLM 工作，MP-GRPO 的思想近亲。
- AutoVLA（Zhou et al., 2025, NeurIPS 2025）：自适应推理 + RL 微调的 VLA 驾驶，hybrid thinking 在端到端动作空间的对应物。
- ReCogDrive（ICLR 2026）：同样 3B 量级、RL 调优的驾驶 VLM，扩散规划器路线的代表，可与 DriveAgent-R1 的离散 meta-action 路线对照。
