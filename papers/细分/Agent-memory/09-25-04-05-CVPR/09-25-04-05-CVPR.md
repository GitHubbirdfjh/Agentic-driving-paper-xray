## 2. 作者思路还原：他们到底在跟谁较劲

### 前人真正撞墙的三个具体场景

论文 Figure 1 把前人的墙画得很直白，分三格：

1. **单任务专家模型**：去雾的只会去雾、去雨的只会去雨。真实夜雨场景里，低光照 + 雾 + 噪声 + 雨滴是同时存在的，你事先不知道是哪几种退化耦合，单任务模型无从下手（Figure 1a 上半，Lightdiff/IDT/DiffLL/Img2img-turbo 全打叉）。
2. **All-in-one 方法**（AirNet、PromptIR、DA-CLIP、InstructIR 等）：一个模型处理多种退化，但全是在合成数据上有监督训出来的。真实数据与合成数据的分布差一拍，到了野外就失灵（Figure 1a 下半，InstructIR/MiOIR 打叉）。
3. **多专家协作**：把各路专家模型拼起来确实能处理耦合退化，但**对任务顺序极度敏感**——先提亮再去雾和先去雾再提亮，结果天差地别，顺序稍变性能就崩（Figure 1b：右边 "Right task order" 全打勾，左边 "Inappropriate task order" 打叉）。

第三格是全文真正的靶子：既然"顺序"决定成败，那最优顺序是谁来定的？人定不了（场景千变万化），穷举定不了（推理时没真值可打分），于是作者把目光投向 VLM。

### 作者的底牌（证据在论文何处）

作者手里有四张牌，每张在论文里都有明确出处：

- **牌一：VLM 当控制器**（§3.2，Figure 4）。基座是 Llava-Llama3-8b（§4.1），冻结的 CLIP ViT-L/14 做图像编码（1024 维视觉 token），可训练的 projector 映射到 LLM 的 4096 维隐空间（附录 §8.2）。工作流四步：Task Planning → Model Selection → Task Execution → Response Generation。
- **牌二：CleanBench 数据集**（§3.1，附录 §9）。150K 合成指令-回复对 + 80K 真实无标注退化图像（CleanBench-Real，分雨/夜/雪/雾四类场景）。合成退化用四个物理/生成式模拟器造（附录公式 8–11）：夜景走 sRGB→RAW→加散粒噪声→ISP 管线→叠加 Flare7K++ 光斑模板；雾景用 Depth Anything V2 估深度做透射图，雾密度 β∈[0.3,1.5]；雨景用物理渲染模型 WMod；雪景用 SD-turbo + LoRA + 文本提示 "driving in the snow"。SFT 的"标准答案"（最优任务序列）怎么来？对任务排列 × 模型组合做**穷举搜索**，用 IQA 打分选最优（§3.1 "exhaustive search strategy"）。
- **牌三：两阶段训练 SFT → MRRHF**（§3.2.1–3.2.2，Figure 5）。SFT 让 VLM 学会"看懂退化 + 输出任务序列"；MRRHF（对 RRHF 的扩展）在 80K 真实无标注数据上做人类反馈对齐，解决合成→真实的 domain gap。
- **牌四：IQA 模型当奖励**（公式 2）。没有配对真值，就用现成的无参考图像质量评估模型（Q-instruct、MUSIQ、MANIQA）打分，z-score 标准化后求和，构成统一奖励模型 S。

### 从最朴素尝试到最终形态：一个合理的生成过程

以下是对作者思考路径的**推断**（论文没有明写，标明为推断）：

**朴素尝试 1：人工定顺序**。直觉上"先去雾再提亮"这种经验规则能覆盖常见场景。但 Figure 1b 已经证明顺序敏感——真实耦合退化的组合空间太大，固定规则覆盖不了。Table 1 的策略 (IV)（人类专家预定义顺序）只排到 22.5%，佐证了固定规则的天花板。

**朴素尝试 2：VLM 直接在合成数据上 SFT**（这就是 JarvisIR-SFT）。这条路同期的 RestoreAgent、AgenticIR 也在走。问题是合成数据的退化是"干净"的、可枚举的，真实退化是耦合的、脏的——SFT 模型一到真实场景就"幻觉"，选错任务序列（§3.2.2 原文："JarvisIR-SFT exhibits increased hallucination, i.e., degraded perception restoration performance and decision-making capability"）。注意这里的 hallucination 指的是决策错误，不是 VLM 胡说八道。

**关键转折：真实数据有 80K，但没有配对真值，怎么做监督？** 作者的解法是把"恢复得好不好"这个问题外包给第三方裁判：IQA 模型。VLM 提出 N 个候选任务序列，真实调用专家模型执行，IQA 给恢复结果打分，分数回流训练 VLM。这就是 MRRHF 的由来——它本质上是一个"用 IQA 分数当偏好信号"的排序学习算法，不需要人类逐条标注，只需要"人类反馈"这个名义（实际是 IQA 模型反馈；论文标题里的 "human feedback" 有名不副实之嫌，见第 6 节）。

**最后的打磨**：vanilla RRHF 是纯 offline 的（候选回复全由 SFT 模型经 diverse beam search 一次生成，训练时不再探索），作者发现这会过拟合到分布内数据；纯 online 又会塌缩（Table 3：online 策略 reward 掉到 −0.87，diversity 1.27，验证集指标直接报 "–"，模型崩了）。于是 hybrid 采样（offline 保下限 + online 扩探索）+ 熵正则（防塌缩）+ 差分对比权重（别对"只差一点"的负样本下死手）。这三件套就是 MRRHF 相对 RRHF 的全部增量。

## 3. 关键设计讲透：什么是承重的，什么是装饰

### 承重结构一：退化感知 = 先"看病"再"开方"

JarvisIR 的 VLM 输出由两部分组成（§3.1 Response Generation）：

1. **CoT 退化推理**：蒸馏 DepictQA-Wild 的知识，对退化图像在清晰度（clarity）、色彩丰富度（colorfulness）、锐度（sharpness）三个维度做质量评估，生成文字版的"病情描述"。Figure 4 左侧示例："The image depicts a foggy nighttime scene with minimal visible details due to significant darkening and atmospheric conditions…"
2. **任务序列 + 模型选择**：形如 "Task 1: Denoising, Model: SCUNet → Task 2: Dehazing, Model: RIDCP → Task 3: Low light Enhance, Model: LightenDiff" 的施工单。

关键设计细节：**任务-模型指派被处理成单选题**（§3.1 Task-model Assignment）。用户指令里列出可用任务和模型的文字描述（从 GitHub/Hugging Face 扒来的），VLM 在 context 里做选择。这一步把"调度"变成了 VLM 最擅长的多选阅读理解，而不是让它凭空生成模型名——这是整个系统能work 的工程关键。

### 承重结构二：专家模型库是"雇佣兵"，VLM 是"包工头"

Table 4 列出全部工具：去噪 SCUnet；超分/去模糊/去压缩 StableSR-turbo、Real-ESRGAN；去雨 IDT、UDR-S2Former、Img2img-turbo；去雾 RIDCP、KANet；去雪 Img2img-turbo-snow、Snowformer；暗光增强 Img2img-turbo-night、HVI-CIDNet、LightenDiff。注意作者明说**故意不用最新 SOTA 模型**（§4.1："we select lightweight and efficient models instead of the latest state-of-the-art models"），因为他们要验证的是"调度范式"本身，不是刷榜。推理时 VLM 输出序列后，系统真实调用这些模型串行执行，前一个的输出是后一个的输入——顺序错了，噪声会被后面的模型放大，这正是 Figure 1b 的含义。

### 承重结构三：两阶段训练，SFT 管"会说话"，MRRHF 管"不说错话"

- **SFT 阶段**（公式 1，标准自回归交叉熵）：在 150K 合成数据上，让 VLM 学会指令跟随 + 退化描述 + 输出合法的任务序列。GT 的任务序列来自穷举搜索的最优解，CoT 部分来自 DepictQA-Wild 蒸馏 + GPT-4V 生成的指令对（每张退化图 GPT-4V 生成 20 候选，人工筛到 5 个）。
- **MRRHF 阶段**（公式 3–7）：在 80K 真实无标注图上，对每个（指令，退化图）生成 m 个候选回复（hybrid：m1 个来自 SFT 模型的 offline diverse beam search + m2 个来自训练中策略模型的 online 采样），真实执行每个候选的任务序列，IQA 统一奖励模型打分，然后用排序损失把策略模型的概率质量推向高分回复。

### 装饰：有它没它不伤筋骨的部分

- DepictQA-Wild 蒸馏、GPT-4V 自指令生成：都是数据飞轮的手段，换成别的 VLM 也能转。
- 论文里反复强调的 "reduce hallucinations"：实指决策错误率下降，借用了 VLM 幻觉的术语外衣。
- Figure 4 明确标注 "The design of the figure is inspired by [61]"（HuggingGPT）——调度范式的灵感来源作者自己交代了。

### 与下游感知任务的耦合方式：说实话，耦合得很浅

标题说 "Elevating Autonomous Driving Perception"，但全文**没有任何下游感知任务的指标**（没有检测 mAP、分割 mIoU、深度误差）。"感知"的提升完全由四个无参考 IQA 指标（MUSIQ、MANIQA、CLIP-IQA+、LIQE）代理。摘要里 "50% improvement in the average of all perception metrics" 的 "perception metrics" 指的就是这四个 IQA 分数。耦合链条是：退化图像 → JarvisIR 恢复 →（假设）更清晰的图像 →（假设）下游感知更好。第二个箭头在论文里没有实证。这是第 6 节要重点讨论的 gap。

## 4. 公式推演：每个符号落到实处

### 公式 1：SFT 的标准自回归损失

$$L_{sft} = -\sum_{i=1}^{N} \log P_{\pi}(R_i \mid \{I_i, M_i\}, R_{<i}; \theta)$$

- $I_i$：用户指令（文本，含可用任务/模型列表）；$M_i$：退化图像（视觉输入）；$R_i$：真值回复的第 $i$ 个 token；$N$：回复总长度（token 数）；$\pi$：SFT 阶段的模型；$\theta$：全部可训练参数（全参数微调 Llava-Llama3-8b）；$R_{<i}$：第 $i$ 个 token 之前的所有 token（自回归条件）。
- 目的：让模型学会"给定指令和退化图，逐 token 生成退化描述 + 任务序列"。这是 LLM 预训练同款目标，没有新东西，承重的是数据（CleanBench）而不是这个公式。

### 公式 2：多 IQA 模型的 z-score 统一奖励

$$S = \sum_{i=1}^{k} \frac{s_i - \mu_i}{\sigma_i}$$

- $s_i$：第 $i$ 个 IQA 模型给某张恢复图像打的原始分；$\mu_i, \sigma_i$：该分数的均值和标准差（论文未明确统计总体，推断为当前 batch/候选集上的经验均值方差——**未确认**，这是个小坑）；$k$：IQA 模型总数，训练时 $k=3$（Q-instruct、MUSIQ、MANIQA），评估时用 4 个（再加 CLIP-IQA+、LIQE）。
- 目的：不同 IQA 模型的量纲和动态范围不同（MUSIQ 是 0–100 量级，MANIQA 是 0–1），直接相加会被大量纲的绑架。z-score 把每个模型拉到同一尺度再求和。
- 几何动作：把 $k$ 个裁判的打分先"去量纲"再投票。等价于假设每个裁判的分数服从正态分布，取标准分相加。

### 公式 3：策略模型给候选回复的打分

$$p_i = \frac{\sum_t \log P_{\rho}(r_{i,t} \mid \{I_i, M_i\}, r_{i,<t}; \theta)}{\|r_i\|}$$

- $r_i$：第 $i$ 个候选回复（含退化描述 + 任务序列全文）；$r_{i,t}$：其第 $t$ 个 token；$\rho$：训练中的策略模型（从 SFT 模型 $\pi$ 初始化）；$\|r_i\|$：回复的 token 长度。
- 目的：把"模型有多想生成这个回复"量化成一个标量 $p_i$。除以长度是为了不让短回复占便宜（短回复的 token 连乘概率天然更高）。
- 物理动作：$p_i$ 是策略模型在"回复空间"中给 $r_i$ 分配的概率质量的对数密度。后续的排序损失就是在这个密度上做功。

### 公式 4：带差分对比权重的排序损失（MRRHF 的核心增量）

$$L_{rank} = \sum_{s_i < s_j} (s_j - s_i)\,\max(0, p_i - p_j)$$

- $s_i = S(r_i)$：公式 2 的奖励模型给候选 $r_i$ 的分数（执行其任务序列、IQA 评估恢复图之后得到）。
- 求和遍历所有" $r_j$ 比 $r_i$ 好"（$s_i < s_j$）的二元组。
- $\max(0, p_i - p_j)$：铰链项。只有当**差的回复 $r_i$ 得到的模型概率反而高于好的回复 $r_j$**时（$p_i > p_j$，排序错了），这一项才非零、才产生梯度；排序已经正确时梯度为零——这是一种"只纠错、不内卷"的保守更新。
- $(s_j - s_i)$：差分对比权重，奖励差距越大，罚得越狠。

**小实例算一遍**：设两个候选，$r_1$ = "先去噪(SCUnet)→去雾(RIDCP)→提亮(LightenDiff)"，执行后奖励 $s_1 = 0.8$；$r_2$ = "先提亮→去雾→去雨滴"，奖励 $s_2 = 0.2$。当前策略模型打分（长度归一化对数概率）$p_1 = -2.0$，$p_2 = -1.0$（模型目前更偏爱差的 $r_2$）。二元组 $(i=2, j=1)$：$s_2 < s_1$，权重 $= 0.8 - 0.2 = 0.6$，铰链 $= \max(0, -1.0 - (-2.0)) = 1.0$，该项贡献 $0.6 \times 1.0 = 0.6$。梯度下降会把 $p_2$ 往下压、$p_1$ 往上抬，即降低生成 $r_2$ 的概率、提高生成 $r_1$ 的概率。对比 vanilla RRHF（权重恒为 1）：若另有一对 $s_3=0.75, s_4=0.70$（差距仅 0.05），vanilla 会同等力度惩罚 $r_4$，而 MRRHF 只给 0.05 的权重——**奖励相近的候选不下死手**，这是附录 §10.3 论证的核心（去掉该权重，reward 0.67→0.53、diversity 6.55→2.62）。

### 公式 5：在最优回复上的交叉熵锚

$$L_{ft} = -\sum_t \log P_{\rho}(r_{i',t} \mid \{I_i, M_i\}, r_{i',<t}; \theta), \quad i' = \arg\max_i s_i$$

- 目的：除了"把差的往下压"，还要"把最好的往上拉"——直接对奖励最高的回复做 SFT 式极大似然，防止排序损失只学会"不犯错"却忘了"什么是对的"。这是一个下限保证。

### 公式 6：熵正则（注意符号，别读反）

$$L_{er} = -\sum_a \rho(a \mid y)\,\log \rho(a \mid y)$$

- $y$：agent 当前状态；$a$：动作（下一个 token）；$\rho(a|y)$：策略分布。
- 注意：$-\sum \rho\log\rho$ 就是**熵 $H$ 本身**（不是负熵）。总损失 $L = 0.5\,L_{rank} + 0.5\,L_{ft} + 0.1\,L_{er}$，最小化 $L$ 等价于**最大化熵**（系数 0.1），即鼓励策略分布保持分散、对抗塌缩。Table 3 证实：去掉它，diversity 从 6.55 跌到 4.56，reward 从 0.67 跌到 0.50。
- 几何动作：$L_{rank}$ 把概率质量从差回复搬到好回复（收缩），$L_{er}$ 则往所有方向均匀地"吹气"（扩张），两者拔河，hybrid 采样提供新样本让这场拔河持续有料可拔。

## 5. 实验解读：数字必须带条件

### 决策能力（Table 1，CleanBench-Real 验证集，2K 张）

六种策略对比，"Score" = 四个 IQA 指标归一化后求和，"Ranking" = 该决策在**所有可能决策**中的百分比排名（数值越小越好；枚举空间大小原文未说明——**未确认**）：

| 策略 | Score | Ranking |
|---|---|---|
| (I) 随机顺序+随机模型 | 1.12 | 43.2% |
| (II) 随机顺序+VLM 选模型 | 2.66 | 34.7% |
| (III) 随机模型+VLM 定顺序 | 3.08 | 23.4% |
| (IV) 人类专家预定义顺序和模型 | 3.94 | 22.5% |
| (V) 人类专家逐张手工定制 | 4.85 | 18.6% |
| JarvisIR-SFT | 5.17 | 14.3% |
| **JarvisIR-MRRHF** | **6.21** | **4.8%** |

解读三点：(1) VLM 定顺序（III）比 VLM 选模型（II）更重要——顺序确实是主要矛盾，呼应 Figure 1b；(2) MRRHF 相对 SFT 从 14.3% 提升到 4.8%，说明第二阶段真实数据的对齐是有效的；(3) JarvisIR 超过逐张定制的人类专家（4.85→6.21）——但"人类专家"只有一位、水平未知，这个基线的天花板本身存疑（见第 6 节）。

- Fog：74.22 / 0.7502 / 0.7805 / 4.714

### 消融：MRRHF 的三个零件各值多少钱（Table 3 / 附录 Table 5）

## 6. 怀疑式审读：公平地挑

1. **"50% 提升"的口径说不清**。摘要称 "50% improvement in the average of all perception metrics on CleanBench-Real"，但正文没有任何一处给出这个 50% 的计算过程。Table 2 里各指标提升幅度从 42%（Night MUSIQ）到近 200%（Night MANIQA）不等，"平均"怎么平均、相对哪个基线，**未确认**。引用时只能说"各指标均大幅领先"，不能复述 50%。
2. **奖励模型与评估指标是同一批人**。训练奖励用 Q-instruct+MUSIQ+MANIQA，评估也用这三个（外加 CLIP-IQA+、LIQE）。MRRHF 直接优化的就是考题本身——Goodhart 风险真实存在。唯一的安慰是 CLIP-IQA+ 和 LIQE 未参与训练仍同步提升，说明不全是过拟合到裁判。
3. **"human feedback"名不副实**。第二阶段叫 "human feedback alignment"，实际反馈信号来自 IQA 模型，没有人类标注员参与（与 RLHF 的人类偏好标注是两回事）。人类只出现在 GPT-4V 指令对的人工筛选环节。
4. **正文-附录 batch size 打架**。§4.1 写 MRRHF batch size 为 1，附录 §8.2 写为 2。复现时以哪个为准，**未确认**。
5. **人类专家基线 (V) 的强度未知**。Table 1 里 JarvisIR-MRRHF 超过"逐张手工定制的人类专家"，听起来很强，但专家人数、专业背景、耗时均未报告。一个仓促的专家和一个认真的专家，差距可能比 4.85→6.21 更大。
6. **穷举搜索的"最优"是小空间里的最优**。SFT 的 GT 任务序列来自"任务排列 × 模型组合"的穷举——任务约 7 种、模型约 13 个（Table 4），穷举的是这个固定小空间。真实最优（比如换更新的专家模型）不在空间里。
7. **CoT 推理的实际贡献微乎其微**（71.17→71.43），但论文把它包装成决策可靠性的关键。Figure 10 展示 MRRHF 纠正 SFT 决策错误的案例是定性个例。
8. **标题承诺大于实证**。"Elevating Autonomous Driving Perception"——但全文零个下游感知任务指标（无检测/分割/跟踪），"感知提升"完全由 IQA 分数代理。严格来说这是一篇"恶劣天气图像恢复"论文，不是"自动驾驶感知"论文。
9. **实时性只字未提**。自动驾驶感知前端有毫秒级延迟预算，而 JarvisIR 推理要跑 VLM（8B）+ 串行调用多个专家模型（含 StableSR-turbo、LightenDiff 等扩散模型）。延迟、显存、帧率全未报告，车端部署的可行性是空白。
10. **分辨率瓶颈作者自己承认了**（附录 §12）：CLIP ViT-L/14 把输入 resize 到 336×336 左右，自动驾驶需要的高分辨率细节在这个过程中已经丢了。退化感知（比如远处小雨滴）恰恰最需要分辨率。
11. **工具故意选弱**。作者明说用轻量非 SOTA 专家模型"简化验证"。这对"验证调度范式"是诚实的，但也意味着 Table 2 里 all-in-one 基线输给的不是"最强恢复系统"，而是"调度范式 + 弱工具"。换 SOTA 工具后差距会缩小还是拉大，**未确认**。
12. **适用范围窄**。附录 §12 承认：水下、老照片、人脸修复等场景不在覆盖范围；四个天气模拟器之外的退化（运动模糊的成因、传感器故障）也未覆盖。

## 7. 与 RAMP 的血缘/划界

先定调：**这是一篇上游感知增强论文，不是驾驶决策论文**。它回答"图像太脏看不清怎么办"，RAMP 回答"看清之后怎么开"。两者处在自动驾驶栈的不同层级，不存在直接竞争。下面按四个轴逐一过。

### 轴一：记忆机制 —— 划界，无记忆

JarvisIR 是**无状态**的：每张图像独立走一遍"感知退化 → 排任务序列 → 执行"，帧与帧之间不传递任何信息，没有情景记忆、没有经验库、没有衰减。RAMP 的 Risk-Weighted Adaptive Memory（高风险经历衰减慢、低风险衰减快，非参数检索）在这里**没有任何对应物**。

可借鉴点（弱）：JarvisIR 的"退化推理"（CoT 描述 clarity/colorfulness/sharpness）是一种对**当前观测质量的结构化自评估**。RAMP 的风险估计模块需要判断"当前观测有多不可信"，JarvisIR 提供了一个现成思路——让 VLM 先输出一段关于输入退化/不确定性的结构化描述，再把这段描述作为风险估计的输入特征。这比直接拿一个标量不确定性更可解释。但注意：JarvisIR 的退化描述是为"选恢复工具"服务的，RAMP 需要的是为"驾驶风险"服务的，两者语义不同，搬运时要重新定义描述维度。

### 轴二：规划器调度 —— 血缘，这是全篇最像 RAMP 的地方

JarvisIR 的 "VLM as controller 调度多个专家恢复模型" 与 RAMP 的 "LLM/SLM 调度多个独立规划器" 是**同一个 agentic 设计范式**：中央控制器不直接干活（不碰像素 / 不直接输出轨迹），只做任务分解 + 专家选择 + 顺序编排，专家模块是可替换的外部工具。

具体可借用的机制有两处：
- **任务-模型指派做成单选题**（§3.1）：把候选规划器及其文字描述摆进 context，让调度器做选择而非开放生成。RAMP 的调度器面临同样的"选哪个规划器"问题，这个"选项呈现"技巧可直接搬运——它把调度问题转化成了 VLM 最擅长的阅读理解。
- **顺序敏感性的实证**（Figure 1b、Table 1 策略 II vs III）：VLM 定顺序（3.08）比 VLM 选模型（2.66）更重要。RAMP 的多规划器如果存在执行/组合顺序（比如先用保守规划器打底、再用激进规划器精修），JarvisIR 的数据点提示"顺序"本身值得作为一个显式的决策变量，而不是固定写死。

划界：调度对象完全不同（图像恢复专家 vs 驾驶规划器），决策产物不同（任务序列 vs 候选轨迹），且 JarvisIR 的调度是**单次开环**的（plan→execute→respond，无重规划），RAMP 是闭环多轮仲裁。JarvisIR 的 MRRHF 只在**训练时**有反馈，推理时没有在线校验——这正是 RAMP 的闭环风险校验要补的那块。

### 轴三：世界模型使用 —— 划界，无世界模型

JarvisIR 没有世界模型，没有未来预测，没有潜状态。它的"模型"全是判别式/生成式的图像恢复器。RAMP 的 Single-Pass World-Model Reuse（一次前向编码共同潜状态、多规划器 action-conditioned rollout）在 JarvisIR 中无对应。**完全正交**，无借鉴。

### 轴四：闭环校验 —— 划界，训练时有反馈、推理时开环

JarvisIR 最接近"闭环"的是 MRRHF 训练回路：执行候选序列 → IQA 打分 → 更新 VLM。但这发生在训练阶段；推理部署后，给定一张图，VLM 输出一个序列并执行到底，**没有运行时校验、没有失败重排**。RAMP 的 Closed-Loop Multi-Planner arbitration 是推理时的在线风险仲裁（每个规划器输出多条候选轨迹，风险仲裁选最优），两者差了一个"运行时"维度。

可借鉴点（中等强度）：**多评估器 z-score 融合**（公式 2）。RAMP 的风险仲裁需要综合多个异构的风险信号（世界模型预测不确定性、记忆检索到的历史风险、各规划器自报置信度），这些信号量纲不同、动态范围不同。JarvisIR 用 z-score 标准化后求和的"统一奖励模型"思路，可以直接搬运为 RAMP 的"统一风险评分"融合层——简单、无参数、对量纲鲁棒。当然，z-score 的均值方差统计总体问题（公式 2 的 μ、σ 口径不明）搬运时要先想清楚是在线滑动窗口还是离线标定。

### 总判断

| 轴 | 关系 | 一句话 |
|---|---|---|
| 记忆机制 | 划界 | JarvisIR 无状态、无记忆；RAMP 的风险加权衰减记忆无对应物 |
| 规划器调度 | **血缘** | 同一范式：VLM/LLM 当控制器调度专家模块；"单选题式指派"与"顺序是决策变量"可直接借用 |
| 世界模型 | 划界 | JarvisIR 无世界模型，完全正交 |
| 闭环校验 | 划界为主、正交为辅 | JarvisIR 只有训练时反馈、推理时开环；多评估器 z-score 融合对 RAMP 风险评分层有借鉴价值 |

定位总结：JarvisIR 是 RAMP 上游的一个**正交模块**——它让摄像头在恶劣天气下"看得清"，RAMP 让系统在看清之后"开得稳"。如果 RAMP 的实验要覆盖恶劣天气场景，JarvisIR 这类恢复前置处理是天然的 pipeline 搭档；但在方法论层面，RAMP 能从它拿走的只有调度范式的两个工程技巧和 z-score 融合这一个数学技巧。它的退化感知思路对 RAMP 风险估计模块的借鉴价值是真实的，但需要把"为选恢复工具服务的退化描述"重定义为"为驾驶风险服务的不确定性描述"，不能直接照搬。

## 8. 一句话总结 + 关联阅读

**带走的一句话**：当退化是耦合的，最优解不在任何单个模型里，而在"调用顺序"里——JarvisIR 证明了让 VLM 当调度员、把排序问题交给排序损失（MRRHF）去学，是一条在真实数据上走得通的路；但它的"感知提升"止于 IQA 分数，"人类反馈"止于 IQA 模型，标题里的自动驾驶感知和人类，都还没真正到场。

**关联阅读**（按与本文的血缘远近排序）：
- **RestoreAgent [9]**（arXiv:2407.18035）：同期独立工作，同样用 MLLM 当任务规划器调度恢复工具，但只在合成数据上微调、无真实数据对齐——JarvisIR 的 MRRHF 正是对它的超越点。
- **AgenticIR [101]**（arXiv:2410.17809）：同期独立工作，用两个 off-the-shelf LLM/VLM 做工具调度，合成实验平台——三者同属"VLM-as-controller for restoration"这一波。
- **HuggingGPT [61]**：VLM 调度 Hugging Face 模型的开山思路，JarvisIR Figure 4 明确致谢其设计灵感。
- **RRHF [93]**（arXiv:2304.05302）：MRRHF 的母体，排序对齐范式；**PRO [63]**：差分对比权重的灵感来源。
- **DepictQA-Wild [91]**：JarvisIR 退化推理（CoT）能力的蒸馏来源，低层视觉质量推理评估。
- **InstructIR [18] / DA-CLIP [49]**：Table 2 里最强的两个 all-in-one 基线，代表"一个模型包打天下"路线的当前水平。
