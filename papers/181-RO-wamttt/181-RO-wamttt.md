## 先纠正一个误解：它不是在学"人怎么动手"

读标题最容易产生的第一印象是：又一篇"看人类视频学机器人操作"的论文，做法大概是把人的手部动作重定向（retarget）到机械臂上。这篇论文恰恰反其道而行：它**拒绝**把人类视频转成任何形式的动作。人类视频在整个管线里从头到尾都是 action-free 的——训练时没有，测试时也没有。论文附录 E.6 专门做了一个消融来证明这个选择：给人类视频配上 MediaPipe+MANO 估计出的伪动作、再加一个前向动力学损失，结果 4 个任务平均分从 72.3 掉到 28.9，掉了 43.4 个点。单目手部估计的噪声经由重定向放大后，反而污染了学习信号。

那么人类视频在这里到底是什么？答案是：**它是一份只在部署时才"打开"的记忆**。训练阶段，模型学会的不是"看到人类视频→输出机器人动作"这个映射，而是一个更间接的东西——"给定一段人类视频，如何用几步梯度把它压缩进一组快权重里，并且压缩完之后，这组快权重恰好能回答机器人观测流的查询"。人类视频不提供动作，它提供的是任务相关的视觉-动力学证据；真正把证据翻译成动作的，是预训练世界动作模型（WAM）里视频专家和动作专家之间本就存在的联合注意力。

这个"记忆"的载体也值得先说清楚，因为它和通常说的记忆（KV cache、检索库、RNN 隐状态）都不一样。它是**参数**：每个 DiT block 视频专家分支上挂的一个小 MLP 的权重 $W^{(\ell)}$。部署时，这组参数会被测试时训练（test-time training, TTT）更新；训练时，它每次用完就丢弃、从学到的初始化 $W_{init}$ 重新开始。这就是标题里 "by Watching Human Play at Test Time" 的字面意思——"看"这个动作发生在测试时，而"看"的结果是写进参数里的。

## 作者真正的起点：基础模型在部署时"不好使唤"

要理解这篇论文为什么长成这样，得先看机器人基础模型（RFM）在 2026 年中这个时间点的真实处境。预训练做大了之后，模型的部署接口其实很窄：语言指令、目标图像、一段短的观测历史。用户想让机器人换个新花样——"这次杯子换个拿法""按我刚才示范的那样摆盘"——通常只有三条路：

第一条路，采集机器人演示数据做微调。贵，而且全参数微调会灾难性遗忘，调完一个任务，之前泛化能力掉一块。

第二条路，把人类视频当 in-context 演示喂进模型（这篇论文里的 WAM-ICL 基线，思路接近 MimicDroid [18]）。不用训练，但 context 长度随演示增加而膨胀，而且——这是论文表 C.1 里最刺眼的一个数字——在训练环境（Orig.）里 WAM-ICL 能拿到 48.4%，一换到没见过的家庭环境（New）直接崩到 7.1%，保留率只有 15%。长 context 条件在分布内是帮助，在分布外是累赘。

第三条路，在预训练时就把人类视频混进去一起训（co-training，这篇论文里的 WAM-COTRAIN 基线）。结果更糟：在 Orig. 环境下它只有 29.8%，比完全不用人类数据的 LDA 主干（50.2%）还低。把人类数据直接稀释进多任务损失，不仅没有帮助，反而把 in-distribution 的策略质量都拖垮了。

三条路堵死之后，剩下的设计空间就很清楚了：**人类视频要在部署时用，但不能进 context、不能进主干参数**。那它能去哪？只能去一个新增的、隔离的、可写的"记忆槽"里。这就是 TTT 层的由来——它不是从这篇论文开始的（TTT layers 出自 Sun 等人 2025 年的 "Learning to (learn at test time)" [50]，Titans [51] 把它叫作"在测试时记忆"），这篇论文的贡献是把它做成了一个**人类视频专用的、可插拔的记忆分支**，并且解决了一个关键问题：快权重里记住的东西，凭什么是对机器人动作有用的？

## 作者的底牌是哪几张

从论文的组织方式看，作者手里有三张牌。

第一张是**基座**：LDA-1B [23]，同一个团队（Galbot）2026 年 2 月放出的世界动作模型。它不是普通的 VLA——每个 DiT block 里有两个耦合的专家，视频专家处理视觉 latent tokens，动作专家处理机器人动作 tokens，两者通过联合注意力通信。这意味着"视觉动力学"和"动作"在同一个表征空间里是连通的：你改了视频流的隐状态，动作流会通过注意力跟着变。这张牌决定了整个方法的上限：如果视频和动作是两个各玩各的头，记忆写进视频侧也引导不了动作。论文 3.1 节开篇就点名站在 LDA 上，不是偶然。

第二张是**机制**：TTT 快权重。它的数学形式在附录 A 里被作者自己证明了——在最简的线性情形下，最小化 key-value 记忆重建损失得到的权重，恰好等价于一个无 softmax 的线性注意力读出（后面会完整算一遍）。也就是说，"把人类视频写进参数"这件事，在数学上就约等于"给机器人查询装了一个人类视频的注意力头"，只不过这个注意力头不用存 KV cache，而是把 cache 蒸馏进了 MLP 的权重。这张牌的妙处在于：它让"记忆"和"注意力"成了同一个东西的两种说法，审稿人里做序列建模的一眼就能验证。

第三张是**证据**：真机实验。3 种构型（Unitree G1 人形、Galbot gripper 双臂两指夹爪、Galbot sharpa 双臂灵巧手）、9 个操作任务、25 次 trial 每格、Orig./New 双环境对照，外加 2,286 对配对的人-机器人数据。这不是仿真刷分，是真机。机器人论文里，能拿出这个量级的真机对照实验，底气就有了——数字后面再逐个审。

三张牌里最硬的是第一张和第二张的组合：基座的视频-动作耦合让"只动视频侧"成为可能，TTT 的数学让"参数即记忆"站得住。实验是把这个组合落地的证明。

## TTT 层到底是个什么东西

先补一点背景，因为理解整篇论文就靠这一个概念。标准的 Transformer 里，"记忆"只有两种形态：写在参数里的（训练时学好，部署时冻结），和写在激活里的（KV cache、RNN 隐状态，跟着序列走）。TTT layers [50] 引入了第三种：**快权重（fast weights）**——一组参数，但在测试时会被自监督损失更新。

具体到这篇论文，每个 DiT block 的视频专家分支上挂了一个 TTT 层。它包含两类参数，论文用"快/慢"的时间尺度来区分（附录 A 开头专门定义了记号，值得照抄这个区分法）：

- **慢参数**：四个投影 $\theta_K^{(\ell)}, \theta_V^{(\ell)}, \theta_Q^{(\ell)}, \theta_O^{(\ell)}$，加上快权重的初始化 $W_{init}^{(\ell)}$，再加上 WAM 本体 $\Theta_{WAM}$。它们由外循环优化器更新，部署时冻结。
- **快参数**：MLP $f_{W^{(\ell)}}$ 的权重 $W^{(\ell)}$。它在**一次前向**之内被内循环 SGD 更新 $N$ 次（论文里 $N=1$，后面会讨论这个"1"意味着什么），用完即弃，下一个样本从 $W_{init}$ 重新开始。

数据流是这样的（对应式 1–2）：

$$z^{(\ell+1)} = \hat{z}^{(\ell+1)} + \Delta z^{(\ell)}_{TTT}, \qquad x^{(\ell+1)} = \hat{x}^{(\ell+1)} \tag{1}$$

$$ \Delta z^{(\ell)}_{TTT} = \theta_O^{(\ell)} f_{W^{(\ell)}}(\theta_Q^{(\ell)}(z^{(\ell)})) \tag{2}$$

$z^{(\ell)}$ 是第 $\ell$ 个 block 输入的视频 latent tokens，$x^{(\ell)}$ 是动作 tokens，带帽的是 LDA 原生 block 的输出。TTT 只给视频流加了一个残差，动作流原样通过。注意这个设计的分寸感：**人类视频是纯视觉的，所以适应只发生在视频侧**；动作侧不直接碰人类数据，避免把视觉域的噪声灌进动作先验。转向（steering）是间接发生的——改写后的视频隐状态在后续 block 里通过视频-动作联合注意力影响动作生成。

张量形状（论文表 B.1 给出的主干配置 $L=16$ 个 MMDiT block，隐维 $D=1536$，32 头；TTT 头维度 $d=48$，快权重 MLP 隐藏宽 $f_h=128$）：

| 符号 | 形状 | 含义 |
|---|---|---|
| $z^{(\ell)}$ | $B \times L_z \times 1536$ | block $\ell$ 输入的视频 latent tokens |
| $x^{(\ell)}$ | $B \times L_x \times 1536$ | block $\ell$ 输入的机器人动作 tokens |
| $h_\phi$ | $B \times L_h \times 1536$ | 同步后的人类视频 tokens |
| $K_h^{(\ell)}, V_h^{(\ell)}$ | $B \times L_h \times 48$ | 人类侧经 $\theta_K,\theta_V$ 投影的 key/value |
| $Q_r^{(\ell)}$ | $B \times L_z \times 48$ | 机器人侧经 $\theta_Q$ 投影的 query |
| $f_{W^{(\ell)}}$ | $48 \to 128 \to 48$ | 快权重 MLP（每层约 1.2 万参数） |
| $\theta_O^{(\ell)}$ | $48 \to 1536$ | 把读出结果投影回主干隐维 |

快权重 MLP 每层只有约 $48 \times 128 + 128 \times 48 \approx 1.2$ 万参数，16 层加起来不到 20 万——相对 LDA-1B 的 10 亿参数完全可以忽略。"轻量自适应记忆"的"轻量"是字面意义上的。

## 记忆重建损失：这篇论文真正的承重结构

如果只看式 4 的内循环损失 $L_{adapt} = L^{human}_{vg} + \lambda \sum_\ell L^{(\ell)}_{KVM}$，容易以为视频预测损失 $L_{vg}$ 是主角。但消融表 2 显示，去掉记忆重建项（w/o Memory Recon.）在 Table Bussing 上从 100.0 掉到 66.7，在 Swap Place 上从 88.9 掉到 72.0——它是除 meta-training 之外掉得最多的一项。真正承重的是 $L_{KVM}$：

$$L^{(\ell)}_{KVM}(W_i) = \frac{1}{B L_h d}\left\lVert f^{(\ell)}_{W_i}(K^{(\ell)}_h) - V^{(\ell)}_h \right\rVert_2^2 \tag{3}$$

用人话说：**拿人类视频的 key 去查快权重 MLP，查出来的东西要等于人类视频的 value**。分母 $B L_h d$ 让它成为逐元素的均方误差，对 batch 大小、人类序列长度、嵌入维度都不敏感。

为什么这个损失能让 $f_W$ 变成"注意力"？附录 A 给了一个干净的论证，值得完整走一遍，因为它是整篇论文数学上最漂亮的一段。先看线性特例 $f_W(x) = Wx$，$W \in \mathbb{R}^{d \times d}$。把同步帧的人类 key/value 按行堆成 $K_h, V_h \in \mathbb{R}^{L_h \times d}$，最小化式 3 有闭式解：

$$W^* = V_h^\top K_h (K_h^\top K_h)^{-1} \tag{A.2}$$

这是标准的最小二乘。现在加一个各向同性假设 $K_h^\top K_h \approx (L_h/d) I_d$（白化或随机投影特征下近似成立），解退化成 Hebb 外积记忆：

$$W^* \propto V_h^\top K_h = \sum_{i=1}^{L_h} v_i k_i^\top \tag{A.3}$$

用机器人侧的 query $Q_r = \theta_Q(z_r)$ 去查：

$$f_{W^*}(Q_r) = W^* Q_r \propto \sum_{i=1}^{L_h} (k_i^\top Q_r) v_i \tag{A.4}$$

这正是**去掉 softmax、去掉核函数的线性注意力**：每个 value 按"key 和 query 的点积相似度"加权求和。$L_{KVM}$ 不是"注意力行为旁边的一个辅助正则"，在线性情形下，它就是注意力行为的变分定义。

![线性见证示意](~/workspace/your_files/paper-xray-100/papers/181-RO-wamttt/fig-witness.png)
*图 2（自绘）：线性特例下的见证。两个正交 key $k_1,k_2$ 各绑一个 value $v_1,v_2$；$W^*$ 记住外积和之后，任意 robot query $q$ 的读出都是 value 按 $(k_i^\top q)$ 加权的组合——没有 softmax 的注意力。*

在一个最小实例上验算一下，取 $L_h=2$，$d=2$，$k_1=(1,0)$，$k_2=(0,1)$（正交，满足各向同性假设的极端情形），$v_1=(2,1)$，$v_2=(-1,3)$。$K_h^\top K_h = I$，所以 $W^* = V_h^\top K_h = \begin{pmatrix} 2 & -1 \ 1 & 3 \end{pmatrix}$。来一个 robot query $q=(0.7,0.7)$：$W^* q = (0.7, 2.8)^\top$。直接按式 A.4 算：$(k_1^\top q)v_1 + (k_2^\top q)v_2 = 0.7(2,1) + 0.7(-1,3) = (0.7, 2.8)$。两边一致。query 离哪个 key 近，读出的 value 就偏向哪一边——这就是"记忆"的全部行为。

论文自己也坦白了这个论证的边界：实际部署的是带非线性和归一化的 MLP，不是线性 $W$，所以式 A.2–A.4 的等式只在 witness 意义下成立；MLP 的非线性和归一化扮演了 softmax 核的角色。这是一个诚实的写法——它没有声称证明了非线性情形，只说训练目标 $f_W(K_h) \approx V_h$ 不变，读出是"平滑的、学到的类注意力"。

## 为什么内循环只需要人类侧的信号

这是整个设计最关键的一步，也是读者最容易卡住的地方：meta-training 的内循环（式 4–5）和测试时的内循环（式 7–8）**长得一模一样**，而且两边都只用人类视频。

$$\begin{aligned}
L_{adapt}(W_i) &= L^{human}_{vg}(u_h; \Theta_{WAM}, \theta_{TTT}, W_i) + \lambda \sum_\ell L^{(\ell)}_{KVM}(W_i) \tag{4}\
W^{(\ell)}_{i+1} &= W^{(\ell)}_i - \eta \nabla_{W^{(\ell)}} L_{adapt}(W_i) \tag{5}
\end{aligned}$$

$$L_{TTT}(W_i) = \frac{1}{|B_h|}\sum_{u \in B_h} L_{vg}(u; \Theta_{WAM}, \theta_{TTT}, W_i) + \lambda \sum_\ell L^{(\ell)}_{KVM}(u; W_i) \tag{7}$$

$$W^{(\ell)}_{i+1} = W^{(\ell)}_i - \eta \nabla_{W^{(\ell)}} L_{TTT}(W_i) \tag{8}$$

为什么测试时没有机器人数据也能跑？因为 $L_{KVM}$ 的三样东西——$K_h^{(\ell)} = \theta_K^{(\ell)}(h_\phi)$、$V_h^{(\ell)} = \theta_V^{(\ell)}(h_\phi)$，以及视频预测损失 $L_{vg}$ 的输入——**全部从人类视频算出来**。$h_\phi$ 是按相位同步后的人类 tokens，不需要任何机器人侧的观测或动作。于是 meta-training 时"用人类视频写记忆"这个内循环，和测试时"用人类视频写记忆"用的是同一个信号形式：训练时学会的"怎么写"，测试时直接照搬。

那机器人侧的监督去哪了？在外循环：

$$L_{meta} = L^{robot}_{WAM} \tag{6}$$

$L^{robot}_{WAM}$ 是 LDA 原生的多任务损失——机器人视频 latent 上的视频扩散目标 + 机器人动作 chunk 上的动作扩散目标，论文声明"沿用 LDA 的损失形式、权重、噪声计划，不做任何修改"。梯度反传穿过 TTT 残差和内循环的快权重更新（解析可微，引自 Spatial-TTT [52] 的做法），优化慢参数 $\Theta_{WAM}, \theta_{\{K,V,Q,O\}}, W_{init}$。**快权重每次用完丢弃，从 $W_{init}$ 重置**——这是 MAML 式的经典设定：外循环不学"记住什么"，学的是"从什么样的起点出发，一步梯度就能记住有用的东西"。

这里埋着一个这篇论文没有大声说、但决定成败的点：内循环步数 $N=1$（表 B.1，meta-training 和测试时都是 1）。一次梯度步能写进多少东西？答案是：快权重本身不负责学通用知识，它只负责把**当前这段人类视频的 key-value 映射**塞进 $W$。通用知识（什么样的 $K_h$ 对应什么样的 $V_h$、什么样的 $Q_r$ 该查什么样的 $K_h$）全在慢投影 $\theta_{K,V,Q}$ 里，外循环用 10 万步、8×H800、batch 128 慢慢磨出来。一次内循环步只是"实例化"，不是"学习"。理解了这一点，就不会误以为测试时的一步 SGD 在创造什么新能力——它只是在调用 meta-training 焊好的接口。

## 人类和机器人是怎么"对上"的：相位同步

Meta-training 需要配对的人类-机器人数据：2,286 对 episodes（Unitree G1 上 600 对、Galbot gripper 上 544 对、Galbot sharpa 上 1,142 对），覆盖 9 个任务。人类视频用 GoPro 以第一人称视角直接在"New"家庭环境里录，没有任何手部姿态标注。

配对的方式粗糙得令人意外：对机器人 episode 里第 $t$ 步（总长 $T_r$），算归一化相位 $\phi = t/T_r$，然后在人类视频（总长 $T_h$）里取最接近这个相位的那一帧。没有动态时间规整，没有语义对齐，就是按进度百分比硬对。论文在 limitations 里自己承认这是第一条 caveat：如果配对的人类片段和机器人片段技能相位分布对不上，内循环的适应信号会变差，而且**损失函数不会报警**——静默失败。这是一个诚实但让人不安的承认：整个对齐机制建立在一个"进度百分比≈语义阶段"的假设上，对长时程、多阶段任务（比如 Multi-step Steak 有 18 个里程碑），这个假设有多牢靠，论文没有量化。

## 部署时到底发生了什么：走一遍完整流程

拿一个具体任务 Transfer Bottle（Galbot gripper 把瓶子从左手递到右手再放进盒子）走完全程。

**Meta-training 阶段（离线，一次）**。慢参数从 LDA-1B 预训练权重出发。每个训练步：取一批配对数据；人类视频 $u_h$ 按相位同步成 $h_\phi$；快权重从 $W_{init}$ 出发，做 $N=1$ 步内循环 SGD（$\eta=0.1$，$\lambda=4\times10^{-2}$），损失是人类视频预测 + key-value 重建；然后用适应后的 $W_N$ 跑机器人侧前向，残差加进视频流；外循环在机器人侧算 $L^{robot}_{WAM}$，反传更新所有慢参数。10 万步，AdamW，DiT 动作头学习率 $1\times10^{-4}$、VLM 接口 $1\times10^{-5}$，cosine 退火，5k 步 warmup。

**部署阶段（每次新任务/新场景）**。WAM、慢投影、$W_{init}$ 全部冻结。在目标场景里录一小批人类视频 $B_h$（论文说"re-recorded in the deployment scene"——注意，**每个部署场景都要现录人类视频**，这是一个真实的使用成本）。跑视频生成模式，只对视频侧快权重做 $N=1$ 步内循环 SGD（这次 $\eta=0.01$，是 meta-training 时的十分之一——论文没有解释为什么测试时学习率要小一个数量级，一个合理的推测是：meta-training 时内循环要给外循环提供足够强的梯度信号，测试时则只求稳定地写进记忆）。适应完的 $W_N$ 在整个 robot rollout 期间固定：

$$a_{t:t+k} \sim p_{\Theta_{WAM}, \theta_{TTT}, W_N}(a_{t:t+k} \mid o_t, g) \tag{9}$$

**同一个场景，WAM-ICL 基线怎么走**：它把同样的人类视频当 in-context tokens 喂进冻结的 WAM，没有快权重适应。在 Orig. 环境里它能到 48.4%（接近 LDA 的 50.2%），说明 in-context 条件在分布内确实能传递任务信息；但在 New 环境里它崩到 7.1%。为什么？人类视频的视觉统计（光照、桌面、杯子实例）变了之后，这些 tokens 不再是"任务提示"，而变成了"分布外的噪声条件"，直接污染了每一层的注意力。WAM-TTT 的隔离设计恰好绕开了这一点：人类侧的域偏移只能改写快权重里的人类-机器人记忆，**写不到** WAM 主干参数里，预训练的视觉推理和动作先验原样保留。

## 怀疑式审读：这些数字里哪些要打折

**第一，消融的样本量。** 表 2 每格只有 10 trials，而主表是 25 trials。直接后果：Swap Place 上 WAM-TTT 在表 2 是 88.9，在表 1 是 66.7——**同一方法、同一 New 环境，换了个 trial 数，差了 22 个点**。progress 是子目标加权的连续分数，10 个 trial 的均值方差不会小。这意味着表 2 里所有"掉多少个点"的读数都要配一个宽误差棒来理解：w/o TTT 在 Swap Place 是 74.1，只比 WAM-TTT 的 88.9 低 14.8——按主表的尺度，这个差距可能一半是噪声。WAM-LoRA 在 Swap Place 的 0.0（10 trials 全败）同样可疑：一个通用参数高效微调基线在 10 次 trial 里一次子目标都没蹭到，更可能的原因是超参数没调好而不是方法不行。论文没有报告任何种子数、误差棒、显著性——真机实验贵可以理解，但读者得自己把折扣打上。

**第二，"ties on Flip Steak (10.0)" 对不上表。** 正文 4.2 节写"WAM-TTT wins 7 outright and ties on Flip Steak (10.0)"，但表 1 里 Flip Steak 一列 WAM-TTT 是 34.3，LDA 是 10.0——34.3 对 10.0 不是打平。如果作者想说的是"在某处打平"，那也该是别的值；如果 10.0 指的是 LDA 的分数，那句子主语就错了。这是一个文本和表格对不上的笔误，虽小，但说明正文的结果描述没有逐字核对过表格。

**第三，EGOSCALE 是自实现。** 原文明确说原模型不开源，评估的是自己的 re-implementation，成绩 15.0。作为"人类数据 scaling"的代表基线，它输得这么难看，有多少是方法本身的问题、有多少是复现不到位，无法区分。拿自实现去打别人的方法，分数只能当下界看。

**第四，WAM-COTRAIN 的"主动损坏"可能另有原因。** Orig. 下 29.8 对 LDA 的 50.2，co-training 确实把 in-distribution 性能拖垮了。作者的解读是"没有显式对齐机制，稀释机器人监督是有害的"。但另一个同样合理的解释是：多任务损失里人类视频预测项和机器人动作项的权重配比没调好——附录只给了 WAM-TTT 自己的超参数（表 B.1），没有给 COTRAIN 的混合权重和搜索过程。一个没调好的基线输给精心调好的主方法，不能完全归因于"缺对齐机制"。

**第五，Stamp Paper 的反例被轻轻放过了。** 这是 9 个任务里唯一一个人类视频**帮倒忙**的：New 下 8.3 对 LDA 的 33.3。作者给了一个几何直觉（in-cubicle 盖章位形紧、扰动破坏对齐），但没有做任何验证这个解释的实验——比如检查人类视频里盖章动作是否本身就和机器人该做的位形不一致。如果人类演示和机器人最优行为在"位形紧"的任务上系统性地不一致，那 WAM-TTT 的适用边界就比论文暗示的窄，而这正是部署前最需要知道的事。

**第六，$N=1$ 和 $\eta$ 的不对称。** 内循环步数在 meta-training 和测试时都是 1，测试时学习率 0.01 是训练时的十分之一。为什么测试时步子要更小？论文没有一句话解释。结合 MAML 的视角可以推测：meta-training 的内循环需要给外循环提供足够大的"适应前后差异"信号，所以步子大；测试时只求稳定写入。但这只是推测。更深的问题是：**只做一步梯度更新的"测试时训练"，和"带一个可学习偏置的注意力"在表达能力上到底差多少？** 论文没有比较 $N=1$ vs $N=5/10$ 的曲线，我们不知道适应能力是否随步数单调变好，也不知道一步是不是已经饱和。

**第七，相位同步的脆弱性。** $\phi = t/T_r$ 取最近相位帧，这个对齐假设在 limitations 里被列为第一条，而且是"静默失败"——损失不报警。Multi-step Steak 这种 18 个里程碑的长任务，人类演示和机器人遥操作的节奏很难按百分比对齐。对齐噪声会直接进 $L_{KVM}$（key 和 value 来自同一帧 $h_\phi$，query $Q_r$ 来自机器人 token $z_r$——注意式 3 里 $K_h, V_h$ 是同一帧的，真正跨域对齐的压力在 $Q_r$ 查 $K_h$ 这一步）。附录没有量化相位错位对性能的影响。

**第八，超参数表里一个不起眼但反常的数字。** 表 B.1：AdamW 的 weight decay 是 $10^{-8}$——基本等于没有 decay。DiT 训练通常用 0.01 量级。为什么关掉？论文没提。可能的原因是外循环要保护 $W_{init}$ 和慢投影不被过度正则，也可能只是试出来这样好。无论如何，这是一个"论文没说但明显在起作用"的选择。

**第九，部署成本被低估了。** "只需无标注人类视频"是卖点，但附录 B 明确写了人类侧"re-recorded in the deployment scene for test-time TTT"——**每个新场景都要现录人类演示**。对 9 个任务的 benchmark 这不算什么，但对"open-ended deployment"的叙事，这是一个按场景线性增长的人力成本。论文没有讨论录制质量（视角、手部遮挡、演示熟练度）对适应的影响。

**第十，公平地说，做得漂亮的地方。** 附录 A 的线性见证推导是真漂亮：没有把 $L_{KVM}$ 包装成玄学，而是给了闭式解、给了适用条件、给了"只是 sanity check"的坦白。E.6 的伪动作消融是反直觉的诚实——大多数团队做了这种"加了东西反而变差"的实验会选择不放，作者放出来了，而且归因具体（单目 MANO 噪声→重定向放大→FD 信号被污染）。Limitations 三条没有一条是套话，每一条都指向了真实的风险。以及，WAM-ICL 保留率 15% vs WAM-TTT 76% 这组对照，不管样本量问题，是一个设计即结论的干净证据：**记忆的位置决定了它对域偏移的鲁棒性**——放在 context 里就是会被污染，放在隔离的快权重里就不会。

## 与 RAMP 的血缘/划界

先划清领域，再谈范式。WAM-TTT 是**机器人操作**（具身智能/桌面操作）的工作，实验在 Unitree G1、Galbot 双臂平台上做真机评估；RAMP 是**自动驾驶**，验证基准是 Bench2Drive 闭环仿真。两个领域的观测、动作、评价协议完全不同，WAM-TTT 的任何领域结论（比如"人类视频 1:1 替代机器人数据""伪动作有害"）都不能直接搬到驾驶上。引用时只取范式，不碰领域结论。

范式上的血缘在"记忆"这个概念上，而且是 RAMP 四支柱里第 (c) 支柱的直接参照。RAMP 的情景记忆是非参数的：检索历史情景、按风险等级连续调制衰减速率（高风险忘得慢）、测试时适应不涉及参数更新。WAM-TTT 的记忆是**参数化的**：快权重 MLP，可通过 TTT 内循环梯度更新。两者回答的是同一个问题——"部署时新来的信息往哪放"——但给出了光谱两端的答案：

- RAMP：记忆是**数据**，更新 = 写入/检索/衰减，不动参数。优点是稳定、可解释、和策略解耦；代价是记忆容量受检索机制限制，跨域的"翻译"（比如人类视频→机器人查询）需要显式的对齐设计。
- WAM-TTT：记忆是**参数**，更新 = 内循环梯度步。优点是记忆容量和表达力随 MLP 走，且 meta-training 把跨域对齐"焊"进了慢投影，部署时人类视频可以直接写；代价是需要配对数据做 meta-training，且快权重的更新是黑盒的。

对 RAMP 的具体启发有两层。第一，**"记忆可以是参数化的、可通过 TTT 更新的"是一个已被验证可行的方向**：WAM-TTT 证明了"冻结主干 + 只更新轻量记忆参数"在真机上能 work，而且人类侧域偏移写不进主干——这正是 RAMP 想要的"适应但不破坏"性质。第二，更落地的可能是**双速记忆**：RAMP 现在的非参数情景记忆负责"记得什么、忘多快"（风险加权衰减），未来可以在它上面再加一层 WAM-TTT 式的参数化快权重，负责"跨域翻译"（比如把路测的人类接管片段、仿真里没见过的 corner case 描述，写进快权重去调制检索的 query 投影）。非参数记忆管"存什么"，参数化记忆管"怎么查"——两层各做自己擅长的事。

一句话 related work 定位：**WAM-TTT 把"记忆"做成快权重、用测试时训练去更新，RAMP 的情景记忆走非参数检索加风险加权衰减——两者都是"让记忆在部署时自己长出来"的答案，一个是参数化更新、一个是非参数检索，范式相通、机制正交，可在 related work 里并列引用为记忆设计的两种路线。**

## 带走的东西

这篇论文留下的可迁移想法有两个。第一个是**"适应座位"（adaptation seats）**——论文 outlook 里自己提的概念：在基础模型的注意力结构里预留显式的、可被下游信息驱动的适应位置。WAM-TTT 的 TTT 层就是这样一个座位：主干训练时就知道"将来会有人往这里写东西"，于是把读写接口（慢投影）提前对齐好。这比"训完再想办法 adapter"高明，因为对齐发生在表征还可塑的时候。对 RAMP 的直接映射：世界模型的中间分布如果从一开始就设计成"可被记忆写、被调度器读"的接口，单次前向复用的收益会更大——接口是设计出来的，不是事后发现的。

第二个是**记忆位置的鲁棒性论证**：WAM-ICL vs WAM-TTT 的 15% vs 76% 保留率说明，同样是"用人类视频"，把它放在 context 里和放在隔离参数里，对域偏移是两种命运。RAMP 的情景记忆天然就是隔离的（非参数库 + 衰减），这个实验等于从侧面给 RAMP 的架构选择投了一票：**凡是来自部署侧、分布不可控的信息，先隔离再使用**。

真正值得做的具体问题，论文自己也在 limitations 里点了：快权重的表达能力边界没有被刻画——"部署任务离 meta-training 的配对分布越远，适应越弱"，但这个边界在哪、衰减有多快，没有一张图。沿着这条线，一个自然的实验是：固定 meta-training 分布，系统性地把部署任务推远（从换杯子实例，到换任务类别，到换构型），画出"距离-性能"曲线。这条曲线一旦画出来，"参数化记忆 vs 非参数记忆"的争论就有了定量的坐标系——而这正是 RAMP 在考虑"要不要加一层参数化记忆"时最需要的那张图。
