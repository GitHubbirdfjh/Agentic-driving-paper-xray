## 一次走进死胡同的导航：只看局部的 agent 在哪里卡住

先看一个具体的失败。R2R 数据集里一条指令："走出卧室，左转穿过走廊，在客厅沙发旁停下。"NavGPT（2023 年 5 月的零样本 VLN agent，MapGPT 的直接前任）是这样走的：它每一步只看到当前位置的几个可走邻居，配上一段由另一个 GPT 专家总结好的历史摘要。第 0 步它从卧室（记作位置 0）走向门口（位置 1），第 1 步左转进入走廊（位置 3），第 2 步发现位置 3 是死胡同。

死胡同本身不是灾难，灾难的是之后。NavGPT 的历史只是一段文字摘要："……曾到过走廊尽头，那里没有沙发"。它退回位置 1，面前摆着两个选项：位置 0（来时的卧室）和位置 4（还没去过的走廊另一头）。摘要里没有整张地图的样子，它不知道位置 4 通向哪里，也不知道更远处还有没有没看过的地方。论文图 1 左半部分画的就是这一刻：agent 的思考停在"继续探索周围"，实际上是在位置 1 和位置 3 之间来回打转，或者退回卧室重走一遍老路。REVERIE 上的统计把这件事量化了：NavGPT 只有 18% 的轨迹出现过至少一次回溯（backtrack），而回溯的那些里面，只有 53% 成功纠正过错误。

这个失败是结构性的，不是调参能救的。NavGPT 的决策函数形如"看当前邻居 + 读历史摘要 → 选一个邻居"，它的世界里不存在"远处还有个没去过的地方 5"这种对象。历史摘要是线性的、可走过的路；地图是分支的、包含没走过的路。把线性历史换成更长的线性历史，解决不了分支缺失的问题。这就是 MapGPT 要推翻的那个默认假设：**给 LLM 做导航决策，不需要把环境压缩成一段摘要，而是需要把环境展开成一张它能读懂的地图。**

## 这篇论文真正押的赌注

MapGPT 的底牌可以归纳成三张，按硬度排序。

最硬的一张是一个几乎零成本的表示选择：**别给 GPT 坐标，给它句子**。作者试过把每个节点的精确 GPS 坐标直接写进 prompt（消融表第 4 节），结果在 GPT-4V 上成功率从 42.6% 掉到 41.2%，比不加地图还差。而把同样的拓扑关系写成"Place 1 is connected with Places 0, 3, 4"这样的句子，成功率涨到 44.9%。一个表示把性能打下去、另一个表示把性能拉上来，中间没有任何训练、没有改一个参数——这种干净的对照是审稿人最难反驳的证据，也是整篇论文的承重墙。后面的自适应规划、多步计划，全是站在这面墙上才成立的。

第二张是时机。2024 年 1 月投稿时，GPT-4V 才发布两个月，VLN 领域还没有任何一个直接用 GPT-4V 做单阶段决策的 agent。MapGPT 的单专家 prompt 系统同时兼容纯文本 GPT-4（两阶段：先用 BLIP-2/Faster R-CNN 把图像转成文字）和 GPT-4V（单阶段：直接看图），"第一个吃螃蟹"本身就是 ACL 这种会议愿意给的分数。

第三张是"统一性"的叙事。R2R 的指令是逐步式的（"先直走再左转"），REVERIE 的指令是高层描述式的（"去找浴室"），前人的零样本 agent 基本只在 R2R 上验证。MapGPT 用同一套 prompt 系统、只改任务描述里的几处措辞，就同时在两个数据集上刷到零样本最优。这是对 ACL 审稿人口味的精准回应：关心的是语言和指令的泛化，不是导航本身。

推测一下真实的研究过程（以下为推断，依据是消融表的结构）：作者很可能先做了最朴素的尝试——把 DUET 那套在线拓扑图原样搬过来，节点坐标直接塞进 prompt，发现性能不涨反跌；然后才意识到问题不在地图，而在"GPT 看不懂坐标"；于是把坐标扔掉、只保留连接关系，性能一下拉起来；有了地图之后，自然想到让 GPT 在地图上写多步计划，而不是每步只选一个邻居。论文的叙述顺序（先地图、再规划）很可能就是真实的试错顺序，因为消融表里"坐标地图"那个负结果的位置，恰好是只有真实踩过坑的人才会去测的东西。

## 地图是怎么在线长出来的：G_t = {V_t, E_t}

MapGPT 的地图不是预先建好的。VLN 任务里 agent 一开始对环境一无所知，只能边走边画。论文沿用 DUET 的做法，把地图存成一个动态增长的图 $G_t = \{V_t, E_t\}$，下标 $t$ 是步数：

- $V_t = \{v_{t,i}\}_{i=1}^{K}$ 是到第 $t$ 步为止所有**观测到**的节点，共 $K$ 个。节点编号 $i$ 就是它被观测到的顺序——第 1 个看到的叫 Place 1，第 7 个看到的叫 Place 7。这个编号后面会直接成为 prompt 里的名字，所以"编号=发现顺序"这个看似随意的选择，实际上决定了 prompt 里地名的命名规则。
- $E_t$ 是这些节点之间的边。仿真器在每一步会告诉 agent 当前位置有哪些邻居可走，新看到的节点和边就从 $G_{t-1}$ 并进 $G_t$。

关键性质：**这张图只增不减**。走过的路不会消失，没走过的节点一旦被看到就永久留在图上。论文里有一句很容易滑过去的话——"map connectivity does not need to be updated if the agent decides to backtrack"，回溯时不需要更新地图——它的含义是：每条"谁连着谁"的信息是在节点第一次被探索时记录的，之后无论怎么走，这部分文本都不用重写。地图 prompt 的长度随探索单调增长，这既是它的力量来源，也是后面要讨论的扩展性隐患。

在第 $t$ 步，图里的节点被分成三类，这个分类直接决定了它们在 prompt 里出现的位置：

1. **走过的节点** $\{en_j\}_{j=0}^{t}$：从起点 $en_0$ 到当前位置 $en_t$ 的整条轨迹；
2. **可达节点** $\{an_t^0, an_t^1, \dots\}$：当前一步能直接走到的邻居；
3. **看到但暂时去不了的节点** $\{un_0, un_1, \dots\}$：比如隔着玻璃门看到的房间，或者从邻居方向瞥见、但当前这一步走不过去的地方。

第三类最有意思：它们是"全局视野"里超出局部动作空间的那部分，是 NavGPT 的世界里根本不存在的对象。

## 从图到句子：Trajectory、Map Connectivity、Supplementary Info 到底长什么样

图 $G_t$ 在内存里是邻接表，但 GPT 读的是文本。MapGPT 用三组模板把图"翻译"成英文句子，拼进 prompt。下面用一个具体的小房子把翻译过程完整走一遍，指令还是那条："走出卧室，左转穿过走廊，在客厅沙发旁停下。"

**第 0 步**，agent 在卧室 Place 0，仿真器说邻居是 Place 1（门口方向）和 Place 2（窗户方向）。此时：

- Trajectory（轨迹）模板是 `"Trajectory: Place {en_0} … {en_t}"`，填出来就是：
  `Trajectory: Place 0`
- Map Connectivity（地图连接）模板对**每一个走过的节点**写一句 `"Place {en_j} is connected with Places …"`：
  `Place 0 is connected with Places 1, 2`
- 动作空间里每个选项被改写成 `"{label} {direction} Place {an_t^i}: {o_{t,i}}"`，其中 $an_t^i$ 是可达节点的编号，$o_{t,i}$ 是朝那个方向看到的景象。方向词只有六个固定的：go forward to、turn left to、turn right to、turn around to、go up to、go down to。于是第 0 步的动作空间长这样：
  `A. stop`
  `B. go forward to Place 1: <a doorway leading to a hallway>`
  `C. turn left to Place 2: <a bedroom corner with a window>`
- 历史 $H_0$ 是固定的第一句话：`The navigation has just begun, with no history`。
- 还没有"看到但去不了"的节点，Supplementary Info 为空。

**第 1 步**，agent 选了 B，走到门口 Place 1。这里的邻居是 Place 0、Place 3（左转进走廊）、Place 4（右转进走廊）。透过走廊尽头的玻璃门，它还瞥见了 Place 5（像客厅），但这一步走不过去——Place 5 进入第三类节点。prompt 变成：

- `Trajectory: Place 0 Place 1`（论文模板里节点之间用空格分隔，实际代码中的分隔符未逐字核对）
- Map 部分长出第二行：
  `Place 0 is connected with Places 1, 2`
  `Place 1 is connected with Places 0, 3, 4`
- Supplementary Info 里第一次出现内容：`Place 5: <image of a living-room-like space seen through the glass door>`（单阶段 GPT-4V 系统里直接放原图；两阶段系统里放 BLIP-2 生成的文字描述）
- 历史 $H_1$ 按模板 `"step 0: {a_0^*}, …"` 记录，$a^*$ 是去掉选项字母的动作原文：`step 0: go forward to Place 1: <a doorway leading to a hallway>`

注意 Map 部分的写法：它**不从当前节点开始列邻接表**，而是把走过的每个节点各写一行"我连着谁"。GPT 读到的是一个扁平的、按探索顺序排列的邻接表。这种写法有一个微妙的好处：当 agent 回溯到走过的节点时，这部分文本一个字都不用改——图只增不减，文本只追加不修改。代价是长度：探索了 50 个节点，Map 部分就是 50 行，而且每一行在后续每一步都会被原样重复输入。

**第 2 步**，agent 按计划走进 Place 3，发现是死胡同（邻居只有 Place 1）。这时地图 prompt 里已经有三行连接关系，外加 Supplementary Info 里的 Place 5。GPT 的思考 $T_2$ 大致是："Place 3 没有通往客厅的路；根据地图，从 Place 1 可以回到 Place 4 那条分支；Place 5 在玻璃门后，可能是客厅，先退回 Place 1 再去 Place 4。"它选择退回 Place 1——这就是一次**有地图支撑的回溯**：目标不是"随便退一步"，而是"退到 Place 1，因为地图说 Place 1 连着还没探索的 Place 4"。

**第 4 步**，agent 从 Place 4 发现 Place 5 可达，走进去看到沙发，选择 `A. stop`。整条轨迹 0→1→3→1→4→5，中间包含一次死胡同和一次定向回溯。

把同一场景放在 NavGPT 上走：它在第 2 步也走进死胡同 Place 3，第 3 步退回 Place 1——到这里两者行为一致。分叉发生在第 3 步之后：NavGPT 的历史摘要里没有"Place 1 连着 Place 4"这条结构化事实，也没有 Place 5 这个"看到但去不了"的对象。它的选项只有文字描述的邻居，摘要说"走廊尽头没有沙发"，于是它可能选"turn around to"退回卧室 Place 0，或者在 Place 1 和 Place 3 之间摇摆。论文的回溯统计（MapGPT 49% 的轨迹至少回溯一次、其中 80% 成功纠正错误；NavGPT 18%、53%）正是这个微观差异在宏观上的投影。

## 为什么坐标被扔掉了：一次"越帮越忙"的消融

在决定用句子写地图之前，作者试过最直接的做法：把 DUET 原来用的精确 GPS 坐标直接塞进 prompt，让 GPT 自己理解空间结构。结果在消融表（表 4，R2R 的 72 场景子集）里，GPT-4V 基线（无地图）成功率 42.6%，加了坐标地图反而掉到 41.2%，SPL 也从 34.7 掉到 32.8。坐标不仅没帮忙，还帮了倒忙。

为什么？论文只写了一句观察："GPT-4V struggles slightly in its attempts to understand navigation environments based on multiple precise coordinates." 往深想一层：LLM 的预训练语料里，空间关系几乎总是以语言形式出现的——"厨房在卧室隔壁"、"穿过走廊左转"。模型见过无数遍的是**拓扑关系的语言表达**，而不是"节点 A 在 (3.2, -1.5)，节点 B 在 (4.1, -1.2)，所以 A 在 B 西边"这种数值推理。后者要求模型在每一步做减法、比较大小、再映射回方向词，这正是自回归语言模型最不擅长的精确计算。给它坐标，等于逼它用弱项做题；给它"Place 1 is connected with Places 0, 3, 4"，等于把它放回它最熟悉的语言推理舒适区。

这个消融是全文最有信息量的实验之一，因为它是一个**负结果**：它说明 MapGPT 的性能提升不是"加了更多信息"带来的——坐标也是信息，而且是更精确的信息。提升来自"信息以模型能用的形式出现"。做 prompt 设计的人应该记住这个教训：往 prompt 里加东西之前，先问这种形式是不是模型在预训练里见过上百万次的形式。

## 自适应路径规划 P_t：从"走一步看一步"到"先写计划再走路"

有了地图，MapGPT 做的第二件事是改变 GPT 的输出形状。NavGPT 每步输出的是思考 + 一个动作（公式 1）：

$$T_{t},a_{t,i}=LLM(PM(D,I,H_{t},O_{t},A_{t}))$$

其中 $D$ 是任务描述、$I$ 是指令、$H_t$ 是历史、$O_t$ 是观测、$A_t$ 是动作空间，$PM$ 是把它们拼成 prompt 的管理器。MapGPT 的公式 2 在输入里加了地图 $M_t$ 和**上一步的规划** $P_{t-1}$，在输出里加了**这一步的新规划** $P_t$：

$$T_{t},P_{t},a_{t}=LLM(PM(D,I,H_{t},O_{t},A_{t},M_{t},P_{t-1}))$$

$P_0$ 初始化为一句话：`Navigation has just started, with no planning yet`。之后每一步，GPT 都要读着上一步的计划，结合新的地图和观测，写出一份更新后的多步计划，再选当前动作。计划是迭代的：$P_t$ 是第 $t+1$ 步的输入。

回到上面的小房子例子。第 1 步 GPT 输出的 $P_1$ 可能长这样（意译自论文图 3 案例的风格）："计划：先去 Place 3 检查走廊左侧；如果 Place 3 是死胡同，退回 Place 1 走 Place 4 分支；Place 5 在玻璃门后、疑似客厅，留作候选；如果两条分支都没有沙发，回溯到 Place 2 重新探索。" 第 2 步撞上死胡同后，$P_2$ 更新为："Place 3 已排除。下一步退回 Place 1，然后去 Place 4。Place 5 仍是客厅候选。" 注意计划里**显式出现了多个候选节点和回溯条件**——这就是"自适应"三字的含义：计划不是写一次就不管了，而是每步根据新观测重写。

这和 DUET 式的"全局动作规划"有本质区别。DUET 让模型从"可达节点 + 看到但去不了的节点"这个全局集合里**直接选一个最优节点**（概率输出，不可解释）。作者也试过一个对应的变体：把 Supplementary Info 里的远处节点直接塞进动作空间，让 GPT-4V 选（表 4 里 "Topological Action" 那一行）。结果成功率 45.4%，只比不加规划的 44.9% 高一点，远不如自适应规划的 47.7%。论文的解释一针见血：让 GPT 从全局集合里**挑一个点**，是在逼它做它不擅长的精确选择；让它**写一段多步计划**，是在用它最擅长的语言推理。这个对比实验的价值在于，它替所有 LLM agent 设计者回答了一个通用问题：当你想让模型利用全局信息时，"输出一个计划"通常比"输出一个远距离动作"更对模型的胃口。

## 找浴室的那一轮：REVERIE 案例的逐轮推演

论文图 3 是一个 REVERIE 上的成功案例，值得逐轮拆开看，因为 REVERIE 的指令是高层描述式的（"去找浴室"），没有"左转直走"这种路标，agent 必须自己决定探索顺序。

场景：在 Place 4 时，agent 已经看到 6 个还没探索过的地方：Place 5、Place 9，以及之前路过时瞥见的 Place 1、6、7、8。其中 Place 5 和 Place 9 就在当前位置的邻居里，1、6、7、8 是远处"看到但去不了"的节点。6 个候选，GPT 的计划 $P_t$ 里**只圈了 4 个**："优先探索位于卧室区域、更可能连着浴室的 4 个地方"。这个选择本身就是在用地图做推理：计划文本里明确写了"如果必要，回溯到 Place 2 重新探索"——在还没失败之前，就把回溯点写进了计划。

接下来的几步，agent 按计划逐个检查这 4 个候选。关键的一步发生在发现"Place 5 和 Place 4 直连"之后：地图多了一条边，计划随之更新，探索顺序被重新排列。最终走到 Place 8 时，发现浴室藏在门后，停下，成功。

这个案例里三个能力是串起来的：**全局探索**（6 个候选里排序，而不是只看眼前 2 个邻居）、**地图理解**（"卧室区域的节点更可能连着浴室"——把语义先验和拓扑结构结合）、**自适应规划**（发现新边就重写计划，提前写好回溯预案）。缺了地图，第一步的"6 选 4"就无从谈起；缺了规划，"回溯到 Place 2"这种预案就不会存在。

附录里还有两个失败案例（图 6），作者诚实地放了出来：(a) agent 在 11 点钟方向的卧室和另一间很像的卧室之间选错，停在了错误但相似的地点——这是视觉 grounding 的问题，地图帮不上忙；(b) 场景复杂、指令线索不足时，agent 按计划探索 Place 2，而正确方向是 0→3，它没能及时回溯。这两个失败圈出了地图方法的边界：**地图解决的是"不知道该去哪"的问题，解决不了"看错了"和"线索本来就不够"的问题。**

## 那两个"~10% / ~12%"是在什么条件下拿到的

摘要里 "~10% and ~12% improvements in SR" 是绝对百分点，不是相对百分比，而且每个数字都有具体的对照上下文，拆开看：

**R2R 的 ~10 个点**：来自表 1，在和 NavGPT 完全相同的 72 场景子集（216 条轨迹）上，GPT-4V 版 MapGPT 成功率 47.7%，对比 DiscussNav（GPT-4，5 个专家融合 5 次预测）的 37.5%，差 10.2 个点。但要注意两个细节：一是 DiscussNav 的 37.5% 是在它"融合 5 次重复预测"的设置下得到的，作者为了公平，把三方都拉到**单次预测**设置下重测；二是同表里 GPT-4 版 MapGPT 是 41.2%，比 GPT-4V 版低 6.5 个点——视觉信息不经过文字转写，直接带来 6.5 个点的提升，这本身就是一个值得记住的数字。

**R2R 全量验证集**（表 2，783 条轨迹）：GPT-4 版 MapGPT 成功率 38.8%，对比 NavGPT（GPT-4）的 34%，提升 4.8 个点；GPT-4V 版 43.7%。注意 72 场景子集上的数字（47.7%）比全量集高出一截，论文归因于分布差异——子集是采样出来的，方差不会小。

**REVERIE 的 ~12 个点**：来自表 3，在从验证集随机采样的 500 条指令上，GPT-4V 版 MapGPT 成功率 31.6%，对比 NavGPT 的 19.2%，差 12.4 个点。这里 MapGPT 甚至追平了训练过的 HAMT（31.6%），虽然离 DUET 的 45.8% 还有距离。作者把公开发布的 HAMT 和 DUET 在这 500 条上重测了一遍，保证对照是同一子集——这个做法值得肯定，很多论文会直接抄原论文在全量集上的数字。

还有一组比成功率更说明问题的数字：**OSR（Oracle 成功率，即假设停止时机完美时的成功率上限）**。R2R 全量集上，NavGPT 的 OSR 是 42%，MapGPT（GPT-4）把它拉到 57.6%，涨了 15.6 个点；REVERIE 上从 28.3% 拉到 42.6%（GPT-4 版）。OSR 涨得多、SR 涨得少，说明地图主要提升的是"走到目标附近"的能力，而"在正确时机停下"仍然是瓶颈——OSR 和 SR 之间 15~19 个点的 gap，就是停止决策这个子问题吞掉的分数。有意思的是 REVERIE 上 GPT-4 版的 OSR（42.6%）反而高于 GPT-4V 版（36.8%），但 SR 更低（28.4% vs 31.6%）：纯文本版走得更远、探索更多，但靠文字描述判断"到了没"更不可靠；GPT-4V 直接看图，停得更准。这个交叉是"信息损失"理论的一个漂亮佐证。

**SPL 的诚实下滑**：成功率涨了，路径效率（SPL）在 GPT-4 两阶段版上反而掉了。72 场景子集上 DiscussNav SPL 33.3，MapGPT（GPT-4）只有 25.4；全量集上 NavGPT 29，MapGPT（GPT-4）25.8。作者没有藏这个数字，解释是：地图鼓励全局探索，agent 会走更长的路。GPT-4V 版因为没有文字转写的信息损失，探索更精准，SPL 回到 38.1，反超基线。这个 trade-off 是真实的：**全局视野的代价是更长的路径**，在真实机器人上每一步都有能耗成本，这个代价不能只看 SPL，要看实际场景。

## 审稿人会问的六个问题

**1. Prompt 长度随地图增长，扩展性在哪里？** 这是全文最大的未回答问题。Map 部分每探索一个节点就多一行，而且**每一行在之后每一步都会被完整重复输入**。Matterport3D 的房子通常有几十到上百个可走节点，一栋大房子探索下来，Map prompt 轻松超过几千 token。论文没有给出 prompt 长度随步数增长的曲线，没有讨论截断、压缩或分层策略，也没有在超大场景上测试。672 input tokens/步 只是 R2R 上的平均值。真实部署时，这是一个随时间线性膨胀的上下文窗口——方法在 10 步的小房子上漂亮，在 100 步的大楼里会怎样，论文没有数据。

**2. GPT 调用成本和延迟只字未提。** 按论文给的数字算：每步平均 672 输入 + 115 输出 token，一条轨迹走 10 步就是约 6700 输入 / 1150 输出 token。R2R 全量验证集 783 条轨迹，GPT-4V 跑一遍就是约 520 万输入 token——按 2024 年 GPT-4 系列定价，这是一笔论文里没有出现的开支。更重要的是延迟：每步一次 API 调用，串行 10 次，实时导航不可能。这篇论文是能力验证，不是系统方案，审稿人如果问"这能用吗"，作者只能回答"未来模型会更快更便宜"。

**3. 地图本身是"无噪声"的。** 在线地图的边来自仿真器直接给出的"当前可走邻居"——这是**上帝视角的拓扑**，没有感知噪声、没有误检、没有漏检。真实世界里，拓扑边需要从视觉 SLAM 或探索中估计，会错、会漏。论文标题里的 "online" 指的是"边走边建"，不是"从噪声感知里建"。把这套方法搬到连续环境，第一步要回答的就是：当 Map prompt 里出现一条错误的边，GPT 的规划会怎么被带偏？论文没有这个实验。

**4. 回溯在仿真器里是免费的。** 附录实现细节里写得很清楚：GPT 选了一个候选点的编号，系统就把 agent **teleport（瞬移）**到那个 viewpoint。回溯到 Place 1 不需要原路走回去，一步瞬移就到。这让"自适应规划里频繁回溯"这个行为在仿真里零成本。在真实机器人或连续仿真里，回溯意味着把走过的路再走一遍，有时间、有能耗、有风险。SPL 已经部分反映了路径变长，但 teleport 假设让回溯看起来比实际更便宜。

**5. 基线对齐基本做到位，但有一个小问号。** 好的地方：72 场景子集与 NavGPT 完全相同；DiscussNav 被拉到单次预测公平重测；HAMT/DUET 在 REVERIE 500 条子集上重跑而非抄数字。问号在 NavGPT 的表 1 数字（GPT-3.5，16.7%）：NavGPT 原论文的实验设置和这里的是否完全一致，论文没有展开说明。另外所有实验都没有报告随机种子和方差——GPT API 调用本身有随机性，成功率 41.2% vs 37.5% 这种差距在 216 条轨迹上的显著性，读者只能自己估算。

**6. REVERIE 只做了导航，不管 grounding。** REVERIE 任务的完整定义是"导航到目标 + 指认目标物体"，MapGPT 明确说只关注导航子任务、忽略物体 grounding。这意味着表 3 的对比口径是"导航成功率"，和 REVERIE 官方 leaderboard 上的完整任务分数不可比。论文在 4.1 节把这一点写清楚了，算诚实，但读者引用数字时要注意口径。

公平地说，论文也有做得漂亮的地方：坐标地图的**负结果**没有被藏起来，反而成了核心论据；SPL 下滑被正面解释而不是用别的指标掩盖；失败案例放进了附录并归纳了两种典型失败模式。这些都是"我知道我的方法边界在哪里"的信号。

## 把它放回时间线：NavGPT → MapGPT → 之后

2023 年 5 月，NavGPT（Zhou 等）开了"LLM 直接做 VLN agent"的头：三专家、纯文本、局部决策，R2R 零样本 34% 成功率。它证明了 GPT-4 能读懂导航指令、能做单步选择，但也暴露了天花板——没有全局视野。

2023 年 9 月，DiscussNav 试图用"多专家讨论 + 5 次预测融合"把天花板顶高一点，R2R 到 37.5%。这条路线是"堆更多的语言处理"，没有碰表示问题。

2024 年 1 月，MapGPT 换了一条路线：不动专家数量（反而砍到 1 个），改**输入的表示**——给 GPT 一张用句子写的地图。R2R 干到 47.7%（GPT-4V），REVERIE 干到 31.6%，两个数据集同时零样本最优。同一年，同一批作者里的 Bingqian Lin 等人还做了 NavCoT（把推理过程解耦出来学），Gengze Zhou 做了 NavGPT-2（把导航推理能力蒸馏进开源 LVLM）——领域从"prompt GPT-4"转向"让小模型也学会这种推理"。

MapGPT 在这条线上的位置是**表示层的转折点**：它之前，大家默认"历史=摘要文本"；它之后，"地图→语言 prompt"成了一个可复用的设计模式（比如 2024 年 5 月的 MC-GPT 直接把 Memory Map 写进标题）。它的历史意义不在于 47.7% 这个数字——训练过的 ScaleVLN 同年在 R2R 上是 81%，零样本和训练方法之间还隔着巨大的沟——而在于它证明了：**LLM 做空间任务时，瓶颈往往不在推理能力，而在你给它的世界表示是不是它读得懂的形状。**

## 可迁移想法

**想法一：把结构化记忆"翻译"成模型母语，而不是把模型改造成能读结构。** MapGPT 最值钱的一课不是"地图有用"（做导航的人早就知道地图有用，DUET 2022 年就用了），而是"地图要翻译成句子才有用"。坐标是更精确的信息，却让性能下降；句子是更粗糙的信息，却让性能上升。判断信息有没有用的标准，不是信息本身的精度，而是**消费它的模型在预训练里见过多少次这种形式**。这个原则可以搬到任何"LLM + 结构化记忆"的系统：情景记忆、知识图谱、场景图，在喂给 LLM 之前，先问自己——我是该训练模型读图，还是把图翻译成它最熟悉的语言？MapGPT 的消融给出的答案是后者至少值得先试，而且试的成本几乎为零。

**想法二：让模型输出"计划"，而不是输出"远距离决策"。** 表 4 里那个只差一行的对比（"Topological Action" 45.4% vs "Topological Adaptive" 47.7%）讲的是同一件事：当你想让 LLM 利用全局信息时，别让它从几十个候选里**挑一个点**——那是在逼它做精确选择，它的弱项；让它**写一段带多个候选和回溯预案的计划**——那是在用它最强的语言推理。这个"输出形状的选择"独立于导航，任何 LLM 调度器、规划器设计都能用：给模型一个适合它能力形状的输出接口，性能会自己跟上来。

**想法三：负结果是最好的设计论据。** 坐标地图让性能下降，这个实验如果藏起来，论文照样能发表；放出来，它就成了"为什么用句子而不用坐标"的铁证。做研究时，那个"试了但变差了"的实验，别急着删——它往往比成功的实验更能说明你的设计为什么是这个样子。

**想法四：OSR 与 SR 的 gap 是定位瓶颈的廉价工具。** MapGPT 用 Oracle 成功率证明了"走得到、停不准"，把 15 个点的差距精确归因到停止决策。这个方法论是通用的：在任何多阶段 agent 系统里，先测每个子模块在"假设其他模块完美"时的上限，gap 最大的地方就是最值得投入的地方。这比端到端调参高效得多。

**一个值得做的后续问题**：Map prompt 随探索线性膨胀，论文没有给出任何压缩方案。一个自然的想法是**分层遗忘**：把走过很久、且与当前任务无关的分支折叠成一句话摘要（"东翼已探索，无目标"），只保留拓扑骨架和当前 frontier 的完整细节。这和人类画地图的方式一致——你记得"我去过东边那片"，但不记得每间房的门朝哪开。MapGPT 的框架里，这个机制可以直接做成 prompt 层面的改写，不需要动模型。

## 与本课题的关联

本课题的架构是：世界模型引导 + 自适应衰减情景记忆的闭环多规划器自动驾驶 Agent，LLM 调度多个规划器执行开放式自然语言驾驶指令，在 Bench2Drive 闭环基准上验证。MapGPT 与它至少有三处直接咬合。

**咬合点一：情景记忆模块的"外化"形式。** 课题里的情景记忆（episodic memory）需要解决的核心矛盾和 MapGPT 一模一样：记忆在内部是结构化的（哪段经历、在哪、结果如何），但消费它的是 LLM 调度器。MapGPT 的答案是：不要把图结构硬塞给 LLM，而是维护一套**从结构到句子的转写规则**——Trajectory 模板对应"自车走过的路径"，Map Connectivity 模板对应"路网拓扑/车道连接关系"，Supplementary Info 对应"感知到但当前不可达的候选（如被遮挡的路口、远处施工区）"。自动驾驶的 BEV 感知输出天然是结构化的（目标列表、车道线、拓扑），MapGPT 证明了"翻译成句子"这条路在零样本下走得通。更进一步，课题里的"自适应衰减"（时间/重要性加权遗忘）正好回答了 MapGPT 没回答的扩展性问题：Map prompt 线性膨胀怎么办？按衰减权重折叠旧分支，把 MapGPT 的开放问题变成你论文的一个贡献点。

**咬合点二：调度器输出形状的教训——全局规划 vs 局部贪心。** MapGPT 的核心对比是"有地图的多步规划"打败"无地图的单步贪心"，回溯率从 18% 提到 49%。映射到多规划器调度：调度器如果每步只根据当前观测选一个规划器（局部贪心），就会复现 NavGPT 的死胡同困境——比如在无保护左转场景里反复试探、进退失据。MapGPT 的 $P_t$ 机制提示了一种调度器输出形状：**调度器每步输出的不只是一个规划器选择，而是一份多步调度计划**（"先用保守跟车规划器通过路口，若对向车流间隙出现则切换激进左转规划器，否则回退到等待"），并在每步根据世界模型的预测更新这份计划。这正是"自适应路径规划"在驾驶调度问题上的平移。

**咬合点三：世界模型先验与记忆的拼接方式。** MapGPT 的地图是**向后看**的（记录走过的地方），世界模型是**向前看**的（预测未来的状态）。两者拼在一起，就是一张"过去-未来"完整的时空地图：向后看的部分用 MapGPT 的句子转写，向前看的部分把世界模型的 rollout 翻译成"如果执行计划 A，未来 3 秒自车在 X，障碍车在 Y"这样的句子。MapGPT 已经验证了 LLM 能读懂向后看的句子；一个自然的课题内实验是：向前看的预测句子能不能被同一个 LLM 以同样的方式消费？如果能，世界模型和 LLM 调度器之间就不需要复杂的特征对齐，一个 prompt 模板就够了。

还有一个清醒的提醒：MapGPT 的一切都建立在**离散仿真器 + teleport 执行**的理想假设上，地图无噪声、回溯零成本。Bench2Drive 虽然也是仿真，但它是连续控制、有物理、有碰撞代价的。把"地图→句子→规划"这套搬过去时，论文里那六个怀疑点（prompt 膨胀、延迟、地图噪声、回溯成本）会一个个变成真问题——而每一个真问题，都是一节可以写的实验。
